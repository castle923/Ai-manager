# M9 — 통합 작업 기록·설정·성능 차트

기준일: 2026-10-17 · 구현·Windows 실검증·저장소 반영 명시 승인 / 후보 3의 확인한 환경에서 핵심 실제 검증 완료·게시 검토 전

M8의 모델 단위 관리에 이어 수집·준비·실행·비교의 출처를 한곳에서 확인하고, 앱의 실제 설정과 같은 조건의 성능 수치를 이해할 수 있게 한다. 기존 모델 관리·TTS·개인 자료·배포를 보존한다. [M8 이후 로드맵](M8_PLAN.md) · [M9 진행 보고서](M9_REPORT.md)

## 구현 범위와 계약

| 기능 | 이번 계약 | 완료를 위한 확인 |
|---|---|---|
| 통합 작업 기록 | 수집/준비/음성 실행/비교를 원본 종류+ID로 식별. 시각·상태·출처·관련 모델/구성·오류와 원본 상세 연결 | 같은 작업 중복 집계 방지, 필터/정렬/빈 목록/부분 실패·취소·중단·재시작, 원본 기록과 항목 대조 |
| 과거와 현재 구분 | 기록 당시 모델/구성과 현재 registry 세대를 구분. 과거 성공을 현재 구성 PASS로 승격하지 않음 | 보관/복원·메타 편집·자산 변경 후에도 과거 기록은 보존하고 현재 상태와 혼동하지 않음 |
| 설정 | 작업실·DB/모델/출력/runtime 역할과 경로를 가려서 읽기 전용으로 안내. 별도 표시 설정은 기본 화면(모델 관리/작업 기록), 목록 수(10/25/50), 시간(local/UTC), 메모리(MiB/GiB) | 실제 적용값/화면 일치·민감값 비노출·기존 자료 불변. 별도 preferences의 CAS로 충돌을 검출하며 인증·allowlist·원본 settings 편집은 제공하지 않음 |
| 성능 차트 | 모델 로딩·추론·전체 실행 시간과 PyTorch 최대 할당 메모리를 단위별로 표시. 차트와 같은 값의 데이터 표 제공 | 원본 지표/표/막대 길이·레이블 일치, 미수집/0/실패 구분, 키보드·색 외 구분·읽을 수 있는 표 |
| 비교 조건 | 입력 해시·seed·공통 옵션·모델/환경·콜드/웜·캐시·표본 수를 확인. 같은 조건 그룹만 나란히 비교 | 조건 누락/차이 시 비교 제한 또는 차이를 명시. 자동 종합 점수·품질 승자 선정 없음 |

통합 기록은 실제 존재하는 원본 기록을 읽는다. 표시를 채우기 위해 가짜 작업이나 과거 PASS를 새 검증 자료에 섞지 않는다. ID·시각이 누락되거나 원본을 읽지 못하면 미확인/오류로 남기며 임의의 성공·시간·0을 만들지 않는다. 시각 정렬과 표시 시간대, 페이지/범위 제한을 API와 화면에서 일치시킨다. 성능 수집과 목록 렌더 시간은 별개의 지표다.

구현 계약은 `GET /api/history`의 종류+ID 식별, UTC 기준 동률 정렬, snapshot/offset 페이지와 부분 읽기 오류를 포함한다. 차트는 comparison의 두 run을 대상으로 입력·seed·공통 옵션·runtime/code/device/dtype/attention·콜드 조건과 출력 무결성을 확인한다. 비교 대상 모델의 revision/manifest 차이는 의도한 차이로 표시한다. 가로 막대의 직접 값과 동일한 표를 제공하고 미수집은 N/A로 구분한다. 이 계약의 구현·실제 검증 결과는 별도 보고한다.

설정 화면은 파일 정리·임의 DB 교체·자격 증명 공개를 위한 관리 콘솔이 아니다. 실제 개인 경로의 앱 내 확인과 공개 문서의 경로 별칭을 구분하며 토큰·OAuth 비밀 내용은 표시/수집하지 않는다. 기존 inventory와 registry의 복구 범위가 다르다는 설명을 유지한다. 자동 업데이트·기존 home 이사·파일 삭제/업로드를 설정 이름으로 추가하지 않는다.

차트는 과거 실행을 새 측정으로 보이게 하지 않는다. 기록 시각과 조건·출처를 함께 표시하고 PyTorch peak allocated를 전체 VRAM으로 표현하지 않는다. 한 번의 측정은 일반 성능 순위나 발음·자연스러움 품질을 보장하지 않는다. 측정되지 않은 값은 “미수집”이며 비교 가능한 값과 혼합하지 않는다.

## 새 검증과 완료 게이트

1. M9 전용 고유 stage·검증 입력·출처 기록을 만들고 현재 코드·패키지·설치본과 연결한다. 경로는 비공개에 보존한다. 기존 M8 성공을 M9의 새 실행 성공이나 새 UI 통과로 대체하지 않는다.
2. 새 격리 자료로 종류별 타임라인·시각/상태·필터·빈/실패/취소/중단·원본 연결·미수집·비교 조건 차이의 반례를 검증한다. 합성 자료와 실계정/실모델 실행 결과를 구분한다.
3. 새 Windows 설치본에서 기록·설정·차트·표를 실제로 조작하고 원본/API/표/차트를 대조한다. 계획 대표 폭·키보드·포커스·레이블·대비 목표를 점검하며 미확인 범위는 명시한다.
4. 실제 작업을 새로 검증하는 경우 새 입력·run/scan/prep·출력을 사용한다. 과거 기록 조회 기능의 확인은 해당 과거 기록의 재조회이지 새로운 GPU 성공이 아니다. 기존 허용 모델을 사용하는 새 실행의 필요·표본·공통 조건은 구현/검증 담당자와 확정한다.
5. 재시작 후 원본·등록 상태·설정·차트의 일관성과 기존 개인 DB/원본/출력 보존을 확인한다. 새 고정 빌드와 독립 검토를 연결하고 개인정보 검토·공개 파일 목록·원격 고정 커밋 바이트/비변경 보존 대조 후 저장소에 반영한다.

후보 3의 소스·패키지·새 A/B 생성·기록/설정/차트·실제 재생·저장·정상 재시작과 독립 보존 검증을 확인한 Windows 환경에서 완료했다. 이번 변경은 검증된 소스·문서의 저장소 반영 범위다. 실제 Drive 수집·좁은 폭·전면 접근성·장시간 부하 등 미검증 범위는 보고서에 남기며 전체 원구상 완료를 뜻하지 않는다. 새 Release·태그 게시 여부는 소스/문서 반영과 별도 기록한다.

## 승인과 사용자 참여

이번 M9의 필요한 로컬 의존성·구현·수정·검증·비식별 게시에 같은 범위의 반복 승인을 요구하지 않는다. OAuth 로그인·동의와 실제 저장/선택 대화상자에서 필요한 사용자 도움은 사용자 직접행위이며 새 기능 범위 승인과 구분한다. 구현 전에 새 권한이나 자산이 필요한 경우 대상을 조사해 구체적으로 알린다.

작업공간 커스텀은 제외한다. Drive 쓰기·새 모델 계열 실행·원격 GPU·유료 인프라·공개 서비스·전역 브라우저/OS 보안 변경은 이번 범위가 아니다. 관리 에이전트·일정 자동화와 M10 다종 어댑터는 별도 후속 범위다.
