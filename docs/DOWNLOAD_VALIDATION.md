# 다운로드 자동 검증 호출의 시간 제한

이 문서는 M5 다운로드 검증의 호출 구성 수정이다. 앱의 파일 응답이나 Chrome 정책을 수정하지 않는다. 앞선 오프라인 수정 당시에는 실제 다운로드를 중단했다. 이후 사용자는 **보안 설정을 유지하고 원인 로그를 먼저 준비한 지정된 제한 재현**만 명시 승인했다. [최신 한정 승인](APPROVALS.md)을 따르며 전체 재시도 허용으로 해석하지 않는다. 시간 제한 수정은 차단 해제, 브라우저 저장 성공 또는 M5 전체 PASS의 근거가 아니다.

## 확인한 범위

저장소의 scripts, tests, frontend, docs에서 `downloadMedia`·`cua_repl` 하네스를 검색했으나 기존 실행 코드는 없었다. 문제가 있었던 코드는 채팅의 CUA 도구 호출이었다. 따라서 기존 앱 코드를 고쳤다고 표현하지 않는다. 새 오프라인 호출 구성 헬퍼 `scripts/download_validation.mjs`와 모의 테스트를 추가했다.

기존 호출은 `downloadMedia()` 내부 제한을 생략했고, 제공된 API 문서 기본값은 120,000ms였다. 외부 `cua_repl.js` 제한도 생략하여 실제 도구 실행은 약 30초에 시간 초과·세션 초기화됐다. 이 두 시간 제한의 불일치는 확인됐지만 Chrome의 조직 차단 원인으로 단정할 수 없다.

## 수정한 호출 계약

- 바깥 `mcp__cua_repl.js` 인자 `timeout_ms: 150000`.
- 안쪽 `downloadMedia({timeoutMs: 120000})`.
- 내부 제한은 API 문서상 권한 프롬프트 대기 시간을 제외한다. 따라서 외부 150초가 항상 완료를 보장하지 않으며, 외부 timeout도 결과 미확정으로 기록하고 중단한다.
- 안쪽 제한보다 바깥 제한에 최소 30초 여유. A/B는 별개의 도구 호출이며 각각 한 개의 다운로드만 포함한다.
- `buildDownloadRequest({side: 'A'})`는 위 인자가 명시된 도구 요청 데이터를 반환한다. 직접 도구를 실행하지 않는다. 생성된 요청을 `functions.exec` 등 기본 30초 wrapper 안에 다시 넣지 않는다.
- `runSingleAttempt`는 호스트가 명시적으로 제공하는 adapter만 호출한다. 기본값은 차단이다. 앞선 오프라인 검증은 adapter를 연결하거나 실행하지 않았다. 최신 제한 재현은 별도의 승인·진단 계획·비공개 로그 준비 후 지정한 단일 호출에만 적용하며 이 헬퍼가 자동으로 브라우저에 연결되는 것은 아니다.
- 다운로드는 명시 승인된 대상·횟수·진단 계획에 한정하며 승인 값과 차단 상태를 함께 검토한다. 원인이 해결되었다고 미리 가정하지 않는다. 이 문서에서 수행한 시간 제한 수정 검증은 헬퍼·모의 테스트와 인자 수용 확인으로 한정한다. 기존 기록의 읽기 전용 진단·문서·게시 승인 범위와 구분한다.

## 결과 불명과 중단

호스트는 실행 직전에 비공개 영속 ledger에 `in_flight`를 저장해야 한다. `ledger.put`은 저장 완료 후 반환해야 하며, 동일 세션은 한 호스트에서 순차로 처리한다. 브라우저 도구는 자동화를 위해 연결된 CUA API를 사용한다. 이 헬퍼는 별도 다운로드 클라이언트를 구현하지 않는다.

외부 timeout, 세션 초기화, 도구 오류 또는 경로 없는 응답은 결과 미확정이다. 성공·실패를 추정하지 않는다. 해당 세션의 A 재클릭뿐 아니라 B 진행도 중단한다. 영속 기록의 `in_flight`가 남아 있으면 세션을 재개해도 클릭하지 않는다. 원인을 읽기 전용으로 확인하고 사용자에게 보고한다. 세션 ID를 바꾸거나 다른 도구·파일명·경로로 재시도하지 않는다.

도구가 경로를 반환한 경우도 `path_returned_unverified`다. 실제 파일 존재·크기·해시를 별도로 확인하기 전 다운로드 검증 PASS가 아니다. 모의 테스트의 `synthetic.wav`는 실제 파일이나 기존 모델 실행의 증거가 아니다.

## 이번 검증

`node --test tests/download_validation.test.mjs`로 오프라인 모의 adapter만 사용한다. 시간 제한 인자 전달, 한 번에 한 side, 기본 차단 시 호출 0회, timeout 이후 전체 중단, 영속 in-flight 이후 중단, 경로 반환과 무결성 PASS 분리를 확인한다. 네트워크·브라우저 다운로드·GPU 실행은 없다.

`cua_repl.js`에 `timeout_ms: 150000`과 단순 `nodeRepl.write(...)`만 전달하여 인자 수용을 확인했다. 브라우저 동작은 0회다. 150초 동안 실행 가능한지 또는 실제 다운로드가 성공하는지 시험한 것은 아니다.

## 최신 제한 재현의 결과 상태

2026-10-17 사용자의 별도 명시 승인으로 기준 기록·원본 A 파일 해시·읽기 전용 이벤트 커서를 준비한 뒤 원래 A 저장 링크를 한 번 클릭했다. 외부 150,000ms·내부 클릭 120,000ms를 명시했고 약 0.31초에 정상 반환했다. 이 제한 재현은 `downloadMedia` 저장 성공 검증이 아닌 원래 anchor 클릭·후속 기록 관찰이다.

다운로드 시작 이벤트 뒤 canceled·0 bytes가 관찰됐고 새 브라우저 항목도 FILE_BLOCKED 11·state 4·danger 4·0 bytes였다. 대상 파일은 없고 B 클릭·재시도·새 모델 추론·보안/정책/확장/CDP 설정 변경은 모두 0회다. 기존 M5 WAV는 이번 다운로드 재현 원본이며 새 TTS 실행 결과가 아니다.

이번 정상 클릭 반환 뒤에도 차단됐으므로 timeout 계약 개선과 FILE_BLOCKED 해결은 별개다. 독립 읽기 전용 검토도 기존 기록 불변·새 항목 1개·이벤트 연결·대상 파일 부재를 확인했다. Network 이벤트·서버 요청 로그가 없어 GET 서버 도달 여부와 현재 차단의 근본 원인은 미확정이다. 새 진단 로그는 비공개에 보존하고 guid·브라우저 프로필·실제 경로·DB 개인 식별값은 공개하지 않는다.
