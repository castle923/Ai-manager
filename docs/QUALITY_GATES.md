# 제품 품질 게이트

작성일: 2026-10-16 · 상태: 품질 계획.이 문서는 검증 목표이며 UI 구현·준수 인증·성능 측정 완료 보고가 아니다.

전체 기능·작동·대시보드·UI를 가능한 범위에서 높은 완성도로 만든다. 제품 가치와 신뢰성을 우선하며 시각적인 완성도로 미구현 기능이나 검증 실패를 가리지 않는다. [마일스톤](MILESTONES.md)의 기능 기준과 아래 품질 기준을 함께 통과해야 단계 완료로 판정한다.

## 근거와 실제 작동

- 발견·구성·무결성·런타임·실행 상태를 분리하고 각 상태에 확인 시각·출처·버전·미확인 이유를 연결한다.
- 코드·환경·입력·모델·출력 해시와 run_id로 새 실행을 재현할 수 있게 기록한다. 개인 기록은 공개 저장소 밖에 둔다.
- 실계정 연결부터 허용범위 스캔·상세·선택 준비·실행·결과까지 단계별 실제 E2E를 검증한다. API 응답이나 목업만으로 화면 사용 흐름 완료를 대체하지 않는다.
- 오류·권한 취소·토큰 만료·작업 취소·프로세스 중단·앱 재시작을 재현하고 실패가 성공 상태로 표시되지 않는지 확인한다.
- 출처·무결성·환경 확인이 부족하면 차단 이유를 표시한다. 비교는 각각 새 실행을 사용한다.

## 화면·상태·접근성

- 핵심 상태와 다음 행동이 먼저 보이는 정보 위계를 사용한다. 색상·간격·타이포·모서리·상태 표현은 일관된 디자인 토큰으로 관리한다.
- 한국어 글자 크기·행간·줄바꿈·혼합 영문 모델명의 가독성을 확인한다. 긴 이름을 줄일 때 전체 이름에 접근할 방법을 제공한다.
- 로딩·빈 목록·부분 실패·오류·실행 중·취소 중·완료 상태마다 이해 가능한 문구와 가능한 행동을 제공한다. 미수집 값을 0으로 표현하지 않는다.
- 키보드 탐색, 의미 있는 포커스 순서와 표시, 대화상자 포커스 복귀, 입력 라벨·오류 연결, 명도 대비, 색 외의 상태 구분, reduced motion을 접근성 목표로 검증한다. WCAG 준수 인증을 받았다고 주장하지 않는다.
- 데스크톱 폭 1280 / 1440 / 1920과 좁은 폭 768에서 주요 화면을 확인한다. 테이블·상세·오류·실행 화면의 잘림, 가로 스크롤, 버튼 접근성을 기록한다.
- 실제 새 인벤토리의 긴 이름·중복 이름·많은 파일을 검증한다. 대규모 목록은 페이지네이션과 가상화의 필요성·키보드 사용·접근성을 함께 검토한다.

## 성능과 확장

성능 예산은 실제 환경·입력 규모·표본 수·콜드/웜 조건을 기록한 기준 측정 뒤 정한다. UI 반응·스캔·목록 렌더·모델 로딩·추론·메모리를 구분하고 측정 실패는 미수집으로 남긴다. 검증 전 임의 threshold를 달성한 측정치처럼 제시하지 않는다. 개선 후에는 같은 조건에서 새로 측정한다.

모델 유형별 어댑터를 확장할 때 입력 계약·필수 파일·환경·출력 검증·오류·취소를 각각 정의한다. TTS 이후 STT·LLM·이미지·영상은 별도 범위와 검토를 거친다. 이 로드맵은 모든 모델의 범용 실행, 원격 GPU 또는 비용 발생의 자동 승인이 아니다.

## 단계별 판정

| 단계 | 추가 품질 게이트 | 남길 증거 |
|---|---|---|
| M1 | 두 계정 앱 인증·조회·갱신·허용범위 차단, 페이지 끝·부분 실패 | 새 scan_id, 비식별 검증 기록, 인증 실패·갱신 결과 |
| M2 | 실제 목록에서 상태 구분·검색·상세·갱신, 상태별 UI·키보드·대표 폭 | 이번 구현의 화면·사용 흐름·오류 재현 기록; 목업/스모크만으로 통과 불가 |
| M3 | 선택 파일 바이트·해시·환경·디스크·임시 파일 검증 | 실제 파일과 환경 기록, 차단·복구 증거 |
| M4 | 새 WAV 생성·검증·UI 재생, 실행 오류·취소·중단 E2E | 새 run_id와 파일 검증·측정 조건·재생 확인; 스모크만으로 통과 불가 |
| M5 | 각각 새 실행·공통 조건·부분 실패·평가 근거 | comparison_id와 두 run_id, 표본 수·옵션 차이 |
| M6 | 새 환경 시작·인증 복구·DB/작업 재시작·비밀 비노출·전체 UI 회귀 | 대표 E2E와 UI/접근성 목표 점검 결과, 잔여 제한; 목업/스모크만으로 통과 불가 |

단계 보고에는 통과·실패·미확인 항목과 확인 범위를 남긴다. 허용한 미해결 항목이 있으면 영향과 다음 검증 조건을 명시하고 단계 완료 기준에 대한 사용자 검토를 받는다. 이번 M0는 이 품질 계획을 수립한 단계이며 해당 품질 검증을 이미 통과했다는 의미가 아니다.
