# M1 구현·검증 진행 기록

기록일: 2026-10-16 · 판정: **M1 두 계정 인증·갱신·수집 성공 / 승인된 M1 범위 완료**

## 승인과 범위

두 계정 연결, 지정 allowlist의 읽기 전용 모델 목록, 필수 앱 설정, 새 로컬 구현·검증·저장소 반영이 승인됐다. 작업공간 커스텀은 사용자 정정에 따라 제외했다. 모델 다운로드·추론·M2 이후 기능의 완료를 이 보고서에서 주장하지 않는다. [승인 기록](APPROVALS.md)

## 구현과 증거 상태

M1 로컬 구현과 자동·독립 합성 검증 후 사용자가 두 계정의 브라우저 로그인·동의를 완료했다. 이번 실제 검증에서 새 앱은 계정 A/B의 `drive.readonly` scope와 Drive 계정 일치를 확인하고 DPAPI 저장·강제 토큰 갱신·지정 allowlist의 재귀 수집을 각각 성공했다. 초기 A 로그인 시간 초과는 이전 시도 기록이며 현재 인증 실패 상태가 아니다. 독립 데이터·보안·실제 목록 화면 검토가 통과해 승인된 M1 범위를 완료로 판정했다.

| 확인 항목 | 현재 상태 |
|---|---|
| 구현 파일·사용 방법·의존성 버전 | 신규 Python 3.10.11 환경, requests 2.32.5 및 5개 런타임 의존성 lock; README 명령 작성, `pip check` 통과 보고 |
| 로컬 테스트·실패 반례·수정 검증 | 최신 코드에서 unittest 21개·`pip check`·브라우저 JavaScript의 `node --check` 통과 보고; 독립 기본 브라우저 검토 통과 |
| 계정 A/B 앱 로그인·동의·실제 scope | 두 계정 사용자 로그인·동의 완료; 실제 tokeninfo scope·Drive identity·DPAPI 저장 확인 |
| 계정별 Drive 조회·토큰 갱신 | 두 계정 각각 강제 갱신 성공; 새 수집 COMPLETE·오류 0건 |
| allowlist·페이지 끝·부분 실패·인증 취소/만료 | 실제 지정 4개 루트 수집 완료; 실패·범위 차단·취소/만료 반례는 합성 검증 통과. 실제 계정 권한 취소/만료는 재현하지 않음 |
| GitHub 반영·고정 커밋 내용 대조 | 변경은 저장소 커밋 이력으로 추적; 게시 결과의 고정 커밋 검증은 작업 완료 보고에서 제공 |

독립 검토자는 Windows DPAPI와 합성 OAuth loopback, Host/Origin/CSRF 방어와 페이지네이션 등을 검사했다고 보고했다. 이는 가짜 입력 기반 로컬 검증이며 Google 실계정 로그인·Drive E2E를 대신하지 않는다. 검토에서 발견한 두 P2 항목은 저장된 인증정보를 연결 성공처럼 보이게 하던 표시를 `credential_saved`로 구분하고, 인증정보 임시 파일을 고유하게 생성하며 계정별 프로세스 간 잠금을 적용하는 방식으로 수정됐다. 독립 검토자는 미해결 BLOCK이 없다고 보고했다. 추가 설정 테스트·소규모 UI 수정 후 21개 테스트가 통과했다.

독립 기본 브라우저 검토에서는 실제 로컬 화면의 계정 A/B 로그인 필요·대기·스캔 없음 표시와 이전/다음 비활성화, 한국어 배치를 확인했다. 별도 신규 합성 51개 파일에서는 50개/1개 페이지·카운터·이전/다음 동작과 HTML 모양 파일명이 텍스트로 표시되어 이미지 요소가 생성되지 않는 점을 검증했다. Google 계정 조작은 없었으며 M2 전체 UI/접근성 검증을 대체하지 않는다.

현재 로컬 화면은 계정 연결·갱신·허용 범위 스캔·수집 목록 50개 단위 페이지 조회를 위한 M1 화면이다. 실제 목록은 새 수집 결과를 읽는다. 앞선 빈 목록·로그인 필요 화면의 검증은 연결 전 상태의 검증이며 현재 두 계정 인증과 실제 수집 완료 상태를 대체하지 않는다. M2 대시보드 완료를 의미하지 않는다.

## 이번 실제 수집 집계

실행 ID: `m1-live-verification-354048da65f14a8e93f32df2866df84b`. 공개 scan 별칭은 `A_SCAN_CURRENT`와 `B_SCAN_CURRENT`다. 실제 scan ID·시각·입력 출처 해시·현재 코드 8개와 lock 해시는 비공개 실행 증거에 기록했다. 공개 집계는 실행 담당 에이전트가 이번 새 실행에서 보고한 값이며 독립 검토자가 비공개 실행 증거와 로컬 DB·현재 설정·집계를 대조해 일치를 확인했다. 실제 파일명·계정 주소·Drive ID·폴더 이름·경로는 공개하지 않는다.

| 항목 | 계정 A | 계정 B |
|---|---:|---:|
| 지정 루트 수 | 3 | 1 |
| 최종 상태 | COMPLETE | COMPLETE |
| 파일 관찰 수 | 436 | 113 |
| 폴더 관찰 수 | 101 | 14 |
| 조회 페이지 수 | 101 | 14 |
| 제외 항목 수(폴더 포함) | 301 | 34 |
| 오류 수 | 0 | 0 |
| 가중치 후보 | 225 | 67 |
| 모델 구성요소 후보 | 158 | 36 |
| 배포 문서 후보 | 53 | 10 |
| 수집 소요 시간(이번 1회) | 43.55초 | 10.02초 |

합계 **549개는 계정별 파일 관찰 수**다. 계정 간 중복 제거를 하지 않았고 파일 종류는 후보 분류이므로 549개 모델 보유 또는 실행 가능 모델 수로 해석하지 않는다. COMPLETE는 지정 allowlist의 페이지 처리를 완료했다는 뜻이며 두 Drive 전체 목록의 완전성 증명이 아니다. 소요 시간은 이번 실행의 관찰값이며 보편적 성능 수치가 아니다.

독립 검토자는 같은 앱을 재시작한 실제 목록 화면에서 두 계정의 인증정보 저장과 루트 수 3/1, 수집 기록 2건·오류 없음, A의 436개/101폴더/301제외 및 B의 113개/14폴더/34제외 집계를 확인했다. 각 계정의 첫 50개 목록과 `1–50/436`, `1–50/113` 페이지 표시, 이전 비활성화·다음 활성화를 확인했다. 검토 과정에서 새 인증이나 재수집은 실행하지 않았고 개인 파일명·토큰·식별자는 공개하지 않았다. 데이터·보안·실제 목록 UI 검토를 통과해 **현재 승인된 네 루트의 M1 범위를 완료(PASS)**로 판정한다. 실패·취소·만료 반례는 합성 검증 범위이며 실제 성공 검증과 구분한다.

Drive 메타데이터의 체크섬 제공 수는 A의 MD5/SHA1/SHA256 각각 436개, B의 MD5 113개·SHA1/SHA256 각각 58개였다. 모델 파일 내용을 다운로드하거나 실제 바이트 해시와 비교하지 않았으므로 무결성 검증 완료가 아니다. 이번 검증에서 모델 내용 다운로드나 Drive 쓰기는 수행하지 않았다.

개인 설정·DB·인증정보는 저장소 밖 `<private_app_home>`에 기록한다. 해당 디렉터리는 현재 Windows 사용자와 SYSTEM 권한으로 제한하고 토큰은 DPAPI로 암호화한다. 실행 환경은 `<repo>/.venv`, 이번에 지정한 allowlist와 Desktop client JSON은 저장소 밖 원본을 사용했다. 계정·파일 ID·실제 경로·로그 원문은 공개하지 않는다.

## 출처와 한계

동일 프로젝트의 승인된 계획과 이번에 새로 작성한 코드·테스트를 사용한다. 공개 문서에는 계정 주소·실제 경로·Drive ID·자격 증명을 넣지 않는다. OAuth 파일 정적 검사와 Codex의 M0 조회 성공은 새 앱의 실계정 인증·목록 수집 성공 증거를 대체하지 않는다. 실제 입력·출력·의존 경로 확인이 끝나기 전 재사용 없음 검증 완료를 단정하지 않는다.

담당 구현 에이전트는 `.venv/Scripts/python.exe -m unittest discover -s tests -v`의 21개 테스트, `pip check`, UI JavaScript의 `node --check` 통과를 보고했다. 이번 실제 인증·수집에서는 코드를 변경하지 않았으며 해당 합성 검증과 실계정 결과의 확인 범위를 구분한다. 실제 모델 다운로드·바이트 무결성·추론·M2 UI 품질은 검증하지 않았다. GitHub 고정 커밋 검증은 게시 후 작업 완료 보고에 제공한다.
