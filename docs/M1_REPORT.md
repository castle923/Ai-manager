# M1 구현·검증 진행 기록

기록일: 2026-10-16 · 판정: **M1 구현·합성 검증 확인 / 실계정 사용자 참여 대기(전체 PASS 아님)**

## 승인과 범위

두 계정 연결, 지정 allowlist의 읽기 전용 모델 목록, 필수 앱 설정, 새 로컬 구현·검증·저장소 반영이 승인됐다. 작업공간 커스텀은 사용자 정정에 따라 제외했다. 모델 다운로드·추론·M2 이후 기능의 완료를 이 보고서에서 주장하지 않는다. [승인 기록](APPROVALS.md)

## 구현과 증거 상태

M1 로컬 구현과 자동·독립 합성 검증은 완료됐다. `src/ai_manager`에 CLI·설정·OAuth·Windows DPAPI·loopback 서버·Drive 읽기·SQLite 인벤토리 코드, `pyproject.toml`, `requirements.lock`과 새 인증/인벤토리 테스트를 작성했다. 실제 계정 A 로그인 시도는 시간 초과로 종료됐고 B는 아직 연결하지 않았다. 새 앱의 실계정 인증·Drive 수집·갱신은 남아 있어 M1 전체 PASS를 선언하지 않는다.

| 확인 항목 | 현재 상태 |
|---|---|
| 구현 파일·사용 방법·의존성 버전 | 신규 Python 3.10.11 환경, requests 2.32.5 및 5개 런타임 의존성 lock; README 명령 작성, `pip check` 통과 보고 |
| 로컬 테스트·실패 반례·수정 검증 | 최신 코드에서 unittest 21개·`pip check`·브라우저 JavaScript의 `node --check` 통과 보고; 독립 기본 브라우저 검토 통과 |
| 계정 A/B 앱 로그인·동의·실제 scope | A는 `authentication_timeout`으로 종료되어 인증정보 미저장, B 미시작; 새 사용자 로그인 참여 필요 |
| 계정별 Drive 조회·토큰 갱신 | 미검증 |
| allowlist 차단·페이지 끝·부분 실패·인증 취소/만료 | 합성 입력으로 자동·독립 검증 통과; 실제 Google 계정과 Drive에서의 검증은 미수행 |
| GitHub 반영·고정 커밋 내용 대조 | 변경은 저장소 커밋 이력으로 추적; 게시 결과의 고정 커밋 검증은 작업 완료 보고에서 제공 |

독립 검토자는 Windows DPAPI와 합성 OAuth loopback, Host/Origin/CSRF 방어와 페이지네이션 등을 검사했다고 보고했다. 이는 가짜 입력 기반 로컬 검증이며 Google 실계정 로그인·Drive E2E를 대신하지 않는다. 검토에서 발견한 두 P2 항목은 저장된 인증정보를 연결 성공처럼 보이게 하던 표시를 `credential_saved`로 구분하고, 인증정보 임시 파일을 고유하게 생성하며 계정별 프로세스 간 잠금을 적용하는 방식으로 수정됐다. 독립 검토자는 미해결 BLOCK이 없다고 보고했다. 추가 설정 테스트·소규모 UI 수정 후 21개 테스트가 통과했다.

독립 기본 브라우저 검토에서는 실제 로컬 화면의 계정 A/B 로그인 필요·대기·스캔 없음 표시와 이전/다음 비활성화, 한국어 배치를 확인했다. 별도 신규 합성 51개 파일에서는 50개/1개 페이지·카운터·이전/다음 동작과 HTML 모양 파일명이 텍스트로 표시되어 이미지 요소가 생성되지 않는 점을 검증했다. Google 계정 조작은 없었으며 M2 전체 UI/접근성 검증을 대체하지 않는다.

현재 로컬 화면은 계정 연결·갱신·허용 범위 스캔·수집 목록 50개 단위 페이지 조회를 위한 M1 화면이다. 실제 목록은 새 스캔 결과를 읽으며 목업 데이터로 실계정 성공을 표시하지 않는다. 실제 연결 시도 종료 후 계정 A/B의 저장된 인증정보는 없고 스캔 목록은 비어 있다. M2 대시보드나 작업공간 커스텀 구현 완료를 의미하지 않는다.

개인 설정·DB·인증정보는 저장소 밖 `<private_app_home>`에 기록한다. 해당 디렉터리는 현재 Windows 사용자와 SYSTEM 권한으로 제한하고 토큰은 DPAPI로 암호화한다. 실행 환경은 `<repo>/.venv`, 이번에 지정한 allowlist와 Desktop client JSON은 저장소 밖 원본을 사용했다. 계정·파일 ID·실제 경로·로그 원문은 공개하지 않는다.

## 출처와 한계

동일 프로젝트의 승인된 계획과 이번에 새로 작성한 코드·테스트를 사용한다. 공개 문서에는 계정 주소·실제 경로·Drive ID·자격 증명을 넣지 않는다. OAuth 파일 정적 검사와 Codex의 M0 조회 성공은 새 앱의 실계정 인증·목록 수집 성공 증거를 대체하지 않는다. 실제 입력·출력·의존 경로 확인이 끝나기 전 재사용 없음 검증 완료를 단정하지 않는다.

담당 구현 에이전트는 `.venv/Scripts/python.exe -m unittest discover -s tests -v`의 21개 테스트, `pip check`, UI JavaScript의 `node --check` 통과를 보고했다. 이 결과의 범위는 새 로컬 코드·합성 테스트 입력·현재 Windows 환경이다. 실계정 scan_id는 아직 없고, 실제 모델 다운로드·바이트 무결성·추론·M2 UI 품질은 검증하지 않았다. GitHub 고정 커밋 검증은 게시 후 작업 완료 보고에 제공한다.
