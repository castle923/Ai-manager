# Ai Manager 0.18.0 · 작업실의 대표와 참고 후보

## 무엇이 없었고 무엇을 연결했는가

이전 화면의 Drive 목록 수집과 모델 관리는 서로 다른 단계였다. 작업실의 실행 선택은 명시된 지원 프로필로 등록한 모델만 읽었고, 연결된 Drive 메타데이터 후보를 작업실에 표시하는 기능과 유형별 사용자 대표 설정은 구현돼 있지 않았다. 따라서 수집 목록은 있어도 등록 모델이 0개이면 실행 선택은 비어 있었다. 이것을 RAM 부족 때문에 목록에서 사라진 것으로 해석하면 안 된다.

이제 음성 합성·음성 인식·텍스트 생성·이미지 생성·영상 점 추적 작업실에서 다음 세 층을 함께 확인한다. 작업실 전체 화면에서는 작업 유형을 바꾸어 다섯 유형의 대표와 후보를 볼 수 있다. 실제 실행 선택과 서버의 파일·환경·자원 검사는 유지한다.

| 표시 | 뜻 | 실행과의 관계 |
| --- | --- | --- |
| 기준 모델 · 참고용 · 보유 미확인 | 앱에 묶인 고정 지원 프로필의 기준 | 성능 1위·현재 소유·실행 성공 판정 아님 |
| 연결된 Drive 후보 · 참고용 | 현재 허용 범위와 최근 수집에서 관찰한 이름·구성 단서 | 등록·실제 모델 식별·가중치 검증 아님 |
| 등록한 관리 모델 | 사용자가 저장한 모델 설명·위치·명시된 프로필 | 준비·무결성·현재 실행 검사가 별도로 필요 |

프로필을 지정하지 않은 관리 모델의 사용자 용도와 실제 지원 작업은 다르다. 미지정 모델을 자동으로 TTS로 분류하지 않는다. 이름이 비슷하거나 목적 단서만 있는 후보는 지원 프로필이 확인된 모델로 승격하지 않는다. 이미지 분산 가중치처럼 안전하게 묶지 못한 경우도 그대로 미확인으로 남긴다.

## 사용자 대표와 참고 미리보기

참고 목록에서 모델을 고르고 **선택한 모델을 대표로 표시**하면 그 유형의 표시용 선택만 별도 작업실 설정 파일에 저장한다. 모델 DB·인증 설정·실행 기본 모델은 바꾸지 않는다. 아직 선택하지 않았다면 기준 프로필을 참고용으로 보여 준다. 이 선택은 다운로드·모델 등록·실행 승인이 아니다.

대표에는 작업 종류, 출처 종류, 원본 관찰·등록 revision과 fingerprint, 기준 manifest와 정책 버전을 연결한다. 재수집·보관·등록 수정·기준 변경으로 근거가 달라지면 이전 대표를 만료로 표시하고 직접 다시 선택하도록 한다. 다른 후보를 조용히 대신 선택하지 않는다. 현재 자원 여유량처럼 자주 바뀌는 관측은 대표의 식별 근거와 별도로 관리한다. 저장은 협력하는 앱 사이의 revision 잠금과 교체 직전 원본 파일의 존재·identity·바이트 대조로 외부 변경을 탐지한다. 외부 프로그램과 완전한 파일시스템 CAS를 보장한다고 주장하지 않는다. 저장 응답은 저장 직전 확인한 근거와 명시적 저장 완료 상태를 사용하며, 저장 뒤 별도 자원·DB 조회 실패를 저장 실패로 바꾸지 않는다.

**작동 방식과 근거 보기**는 참고용 정보 카드다. 선택 유형의 입력 → 처리 → 예상 출력 종류를 설명하고, 실제 관찰 근거와 부족한 확인을 보여 준다. 실제 모델이 생성한 음성·텍스트·이미지·영상은 아니다. 참고 응답은 `mode=reference`, `execution_allowed=false`, `sampled_generation=false`다. 이전 출력물을 새 결과로 가져오지 않는다.

후보의 **등록 화면 열기**는 기존 명시적 모델 등록 폼에 원본 참조를 전달한다. 이 버튼만으로 저장하지 않는다. 등록 뒤에도 전체 필수 파일·SHA-256·별도 환경·현재 자원·실제 실행 확인은 각각 다른 단계다. 지원 범위는 기존 다섯 작업 종류·여섯 프로필이며, 범용 새 모델 실행기나 영상 생성 기능을 추가하지 않았다.

## 참고용인 이유와 로컬 사양

화면은 저장된 환경 준비 기록과 현재 RAM·작업실 드라이브의 여유 공간 관측을 분리한다. 자원 값은 관측 시각과 bytes 원본에 기반하며 화면에서는 GiB로 변환한다. GPU 메모리를 신뢰할 수 있게 관측하지 못하면 **미측정**으로 표시한다. 미측정은 부족 판정이 아니다. 저장 공간은 작업실이 실제 위치한 드라이브의 값이다.

정량 비교는 기존 프로필에 명시된 규약 최소값이 있을 때만 한다. 현재 이미지 프로필의 RAM·GPU·디스크 최소값을 다른 유형에 일반화하지 않는다. 관측 최소값을 만족해도 실행 가능이나 품질을 보장하지 않으며, 실행 직전의 기존 preflight가 최종 확인한다. 등록 없음·프로필 미지원·가중치 미확인·환경 미준비·자원 부족·자원 미측정은 서로 다른 이유다. 관측 파일이 0 bytes인 경우도 용량 미확인과 구분한다.

## Claude API 추천 검토

Claude는 이름과 공식 설명을 토대로 **목적 관련성 분류·검토 우선순위·근거 설명**을 보조하는 후보로 검토했다. 공식 문서의 Haiku 5.5와 API ID `claude-haiku-5-5` 존재를 확인했지만 사용자 계정 접근과 실제 API는 검증하지 않았다. 이번 제품에는 provider 호출·키 조회·외부 데이터 전송·과금을 구현하거나 실행하지 않았다. [공식 모델 개요](https://platform.claude.com/docs/en/models/haiku-5-5/overview)

LLM 응답은 모델 identity·고정 adapter·실행 권한·품질 우열을 확정할 수 없다. 현재 로컬 규칙과 원본 사실 검증이 기준이다. 추후 도입한다면 전송할 필드의 미리보기, 최소 정보 선택, 예산 상한, 사용자 승인, 응답 schema와 근거 ID의 로컬 검증이 먼저 필요하다. Structured JSON과 native citations를 동시에 쓰는 조합의 제약 때문에 근거 ID를 명시한 schema와 앱의 원본 대조를 검토한다. 이는 이번 구현 완료 기능이 아니다. [구조화 출력](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [인용](https://platform.claude.com/docs/en/build-with-claude/citations)

## 검증 상태

새 합성 작업실에서 대표 선택·revision 충돌·만료·원본 범위·0 bytes와 미확인 값·미지정 프로필 분류·읽기 전용 조회·Host/CSRF/admission 경계를 검증했다. 참고 조회는 기존 DB·설정 바이트를 바꾸거나 실제 가중치를 해시·로딩하지 않는다. 화면의 참고용 선택이 기존 실행 모델 선택에 들어가지 않는지도 검사한다.

개발 중 새 반례 18개와 TypeScript/Vite, 합성 UI의 대표 저장·해제·재수집 만료·후보 등록 폼 연결·다섯 유형·작업실 접기 입력 보존·1266/768px 표본을 확인했다. 최종 동결 소스의 전체 회귀는 456개 중 449개 통과·7개 명시적 건너뜀·오류 0개로 끝났다. 새 패키지와 실제 native 관측은 아직 수행하지 않았다. 기존 테스트·스크린샷·모델 출력은 이번 실행의 성공 근거로 대체하지 않는다.

실제 개인 작업실은 같은 `--home`를 계속 사용한다. 개발·반례 검증은 별도 합성 작업실이며 기존 인증·DB를 복사하거나 수정하지 않았다. 이번 단계에서 새 OAuth·Drive 수집·모델 다운로드·추론·원격 GPU·Drive 쓰기는 실행하지 않았다.
