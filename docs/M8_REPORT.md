# M8 모델 등록·통합 상태 진행 보고서

기준일: 2026-10-17 · desktop-0.8-3 확인 환경의 M8 핵심 구현·실검증 완료 / 소스·문서 반영 범위·0.8.0 Release 미게시

사용자가 원구상 화면의 남은 범위를 재정리하고 모델 단위 등록 관리·통합 상태부터 구현·실검증·저장소 반영할 것을 승인했다. [M8 계획과 완료 게이트](M8_PLAN.md)를 따른다. 기존 TTS·독립 앱의 완료 이력은 보존하며 전체 원구상 완료로 확대하지 않는다.

M8 전용 새 검증 경로·새 설치·새 home을 사용했고 이전 토큰·인벤토리·출력을 복사하지 않았다. 기존 release·모델·인증·개인 DB·출력은 보존하고 이전 WAV·테스트 성공을 M8 새 성공으로 사용하지 않는다. 개인 계정·실제 경로·Drive ID·입력 원문·자격 증명·원시 로그는 공개하지 않는다.

최종 후보 3 ZIP은 58,432,393 bytes·SHA-256 `632e7b88c379cb3cf8231c5883f428f3daf7498d8d6ca6b5123bcb9b53328016`, EXE SHA-256은 `c0ace6cc179e7f912b8d72ab052555f401a27f26b053153388e174c913bffc3b`, manifest SHA-256은 `652ad004309f9766004d1ef5c099bfd36da23c4ff5981a0955caa3faeecc40cd`다. 번들 M8_INSTALL은 SHA-256 `a59992529414c052fd324d59b4be048d34b3b5535354d5c9c32c349c8c71fdf5`로 동결했다.

앞선 후보 1은 fresh home의 없는 후보 참조 오류를 정상 JSON으로 처리하지 못해 보존하고 최종 검증 대상에서 제외했다. 후보 2는 실제 TTS·저장 성공 뒤 설명 편집 반례가 추가로 발견돼 최종 대상에서 제외하고 보존했다. 현재 검증 대상은 두 수리를 반영한 후보 3이다. 잠긴 inventory DB 조회는 독립 합성 관측에서 약 21.484초 후 정리된 HTTP 400 JSON을 반환하고 서버가 유지됐다. 이 잠금 지연은 남은 제한이며 즉시 응답·모든 DB 장애 복구를 보장하지 않는다. 기존 inventory backup/restore가 별도 registry까지 복원하지 않는 경계도 유지한다.

지원하는 고정 TTS adapter와 로컬 보관 폴더를 명시한 등록은 고정 manifest의 파일만 전량 크기·SHA-256으로 확인한다. 빈 폴더나 Drive 관찰만으로 구성 확인을 통과시키지 않으며 원본·실제 준비 자산의 일치를 실행 직전에 다시 확인한다. 등록·명시 변경·실행 직전의 강한 내용 검증과, 자동 조회 때의 기록/파일 stat 및 작은 코드·WAV 해시 확인은 다르다. 검증 완료는 최근 확인 시각·현재 구성·확인한 환경에 연결된 근거이며 화면 갱신마다 모델 전체를 해시하거나 파일 변경을 항상 즉시 발견한다는 보장은 아니다.

## 최종 후보 3의 새 실제 실행 근거

새 런타임은 후보 3 설치본의 동봉 Python 기반 별도 환경이다. 지정 0.6B 원본 13개·준비본 13개·등록 attestation·고정 manifest의 전체 크기/해시가 일치했다. 실제 설치 코드 12개·현재 repo·새 runtime lock과 registry UUID·현재 generation·fingerprint·manifest binding을 새 run 상태/provenance에 연결해 독립 확인했다. 후보 2 WAV를 읽거나 새 성공 근거로 대체하지 않았다.

새 한국어 입력은 29자이며 SHA-256은 `4c5e425590f6ce6063e36f05110c3a6842439283b5795828ce52916774ec4526`다. 모델 로딩 3.016초·추론 24.593초·전체 42.032초·PyTorch peak allocated 2,361,982,976 bytes를 관찰했다. 이 값은 전체 VRAM이나 반복 측정에 의한 일반 성능 판정이 아니다.

새 WAV는 303,404 bytes·151,680 frames·6.32초·PCM16 mono 24 kHz·EOS true·clipped samples 0이며 SHA-256은 `6e78f7f1da01c2acb9ed9223bf503fb668a11eefcc2f054726aaa84aadf03854`다. 앱에서 끝까지 재생하고 native 저장본과 형식·바이트·해시 일치 및 별도 파일 ID·서로 다른 파일임을 독립 확인했다. 이는 0.6B 새 입력 1회의 모델 연결 검증이며 청취 품질·1.7B 새 M8 실행·모든 환경의 보장은 아니다.

## 알려진 제한과 남은 게이트

- 후보 2의 지원 모델 설명 편집 BLOCK은 브라우저 Number로 전달된 나노초 수정 시각의 정밀도 손실이 원인이었다. 후보 3은 서버 보유 참조를 identity 토큰과 CAS로 유지하도록 수정했다. Node JSON 왕복·경계 회귀, 실제 지원 모델 설명 편집·참조 유지, 새 성공 후 설명 편집의 검증 유지와 재시작 상태/파일 보존을 확인했다.
- 이번 새 home에서 fresh OAuth와 실제 Drive 후보를 통한 등록 E2E는 수행하지 않았다. 해당 경계의 합성/API 검증과 로컬 지정 원본을 사용한 실제 등록·실행을 구분한다.
- 실제 창 약 1266px에서 확인했다. 좁은 폭·전체 계획 폭·전면 접근성은 아직 확인하지 않았다.
- 후보 2의 metadata 키까지 일치하던 검색은 후보 3에서 값만 검색하도록 수정하고 회귀를 통과했다. 실제 태그 값 검색·1개 결과·상태 필터도 확인했다. 모든 검색 조건의 완전성을 주장하지 않는다.
- 앞서 기록한 DB 잠금 지연·별도 registry 백업 미제공·화면 갱신의 stat 확인 한계를 유지한다.

후보 3의 확인한 Windows·로컬 지정 0.6B 자산·등록/편집/보관·상태 집계·새 실행/재생/저장·정상 재시작 범위에서 M8 핵심 흐름을 검증했다. 새 run·저장본은 독립 검토를 통과했고 재시작의 API/파일 대조와 native 화면 재표시도 확인했다. 이는 앞서 명시한 Drive 실제 경로·좁은 폭 등의 미검증을 포함한 전면 PASS가 아니다. 후보 2 결과는 해당 이력으로 보존하고 최종 증거를 대신하지 않는다. 공개 반영은 명시한 23개 파일로 제한하고 원문 바이트/해시·비변경 파일 보존을 대조한다. 이 변경은 소스·문서 반영이며 로컬 검증 ZIP의 공개 Release 게시를 뜻하지 않는다. M9 통합 기록/설정/차트와 M10 다종 어댑터는 미완료 후속 계획이다. 0.8.0 공개 Release는 게시하지 않았으며 기존 공개 배포는 보존한다.
