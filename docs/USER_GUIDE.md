# Ai-manager 사용 가이드

기준일: 2026-10-17 · Windows 독립 앱 기준

Ai-manager는 **두 Google Drive 계정의 모델을 찾아보고, 지원하는 한국어 음성 모델을 내 PC에서 실행하는 개인용 작업실**입니다. 모델 목록을 확인하는 기능과 실제 음성을 만드는 기능을 한 앱에서 사용합니다.

## 할 수 있는 일

| 하고 싶은 일 | 앱에서 하는 일 |
|---|---|
| 가진 모델 찾기 | 계정 A/B의 허용 폴더를 읽어 목록을 수집하고 이름·용도·계열·파일 형식 등으로 검색/필터링 |
| 모델 정보 확인 | 상세 화면에서 파일 구성·크기·출처·확인 수준 확인 |
| 음성 모델 준비 | 지정 Qwen3-TTS 0.6B/1.7B CustomVoice의 필요한 파일을 준비하고 크기·해시 검사 |
| 한국어 음성 만들기 | 새 문장을 입력하고 선택 모델로 WAV 생성·재생·저장 |
| 두 모델 비교 | 같은 새 문장과 공통 조건으로 순차 실행하고 A/B 음성·시간·메모리 비교 |
| 기록 확인 | 실행 상태·결과·오류를 조회하고 진행 중 작업 취소 |

목록에 모델이 보인다고 실행 가능한 것은 아닙니다. 현재 음성 실행은 위 두 지정 모델을 지원하며, 모든 AI 모델을 자동 실행하거나 이미지·영상·대화형 AI를 만드는 범용 도구는 아닙니다. Drive의 허용 범위를 읽고 로컬에서 실행하며 Drive 파일을 삭제·이동·자동 업로드하지 않습니다.

## 어떤 버전을 실행하나요?

**M8/0.8.0 모델 관리 화면은 로컬 후보 3의 확인한 환경에서 핵심 흐름을 검증했습니다.** 아래 공개 0.7.0·로컬 0.7.1 흐름과 구분합니다. 새 **모델 관리**의 등록·편집·보관·세 KPI와 모델별 새 실행 안내는 [0.8.0 후보 안내 초안](M8_INSTALL.md)에 준비했으며, 공개 0.7.0 배포에 이미 포함됐다는 뜻은 아닙니다. [M8 진행 상태](M8_REPORT.md)

M8에서 후보 파일 관찰이나 빈 폴더 등록은 실행 준비 완료가 아닙니다. 지원 TTS 구성과 실제 원본 폴더를 연결해 파일 크기·해시를 확인하고 실행 직전 현재 준비 자산과 다시 대조하도록 구현했습니다. 자동 상태 갱신이 매번 모델 전체를 다시 읽는 것은 아니며 확인 시각·구성·환경 범위를 함께 봐야 합니다. 후보 3의 실제 편집·보관/해제·새 실행·재생/저장과 성공 후 편집 유지·정상 재시작을 확인했습니다. 실제 Drive 후보 등록·좁은 폭은 이번 검증에 포함하지 않았습니다.

| 버전 | 현재 위치와 차이 |
|---|---|
| **공개 v0.7.0** | [공개 다운로드](https://github.com/castle923/Ai-manager/releases/download/v0.7.0/AiManager-0.7.0-windows.zip). Python을 포함한 독립 앱. 당시 0.6B 실제 사용 흐름을 검증한 배포본 |
| **로컬 M8 0.8.0 후보** | 모델 단위 등록·편집·보관·상태 KPI와 등록 구성의 새 실행을 추가. 후보 3의 확인한 환경에서 핵심 실제 흐름·편집 유지·재시작을 검증. 실제 Drive/좁은 폭 등 제한이 있으며 공개 Release 없음 |
| **로컬 검증 0.7.1 후보** | 지정 PC에서 두 모델의 새 A/B·재생·저장을 검증한 수정본. 모델 원본 폴더의 직접 경로 입력·선택 경로/실패 크기 표시를 추가. 공개 Release는 아직 없음 |

공개 ZIP을 받으면 0.7.0입니다. 0.7.1 전용 버튼이 없더라도 설치 오류로 판단하지 마세요. 로컬 수정본을 처음 사용할 때도 해당 설치 폴더의 `AiManager.exe`에서 시작할 수 있지만, 별도로 지정해 둔 작업실을 이어 쓰는 경우에는 아래 재실행 주의사항을 따릅니다. 다른 버전의 실행 파일이나 `_internal` 폴더를 섞지 않습니다. 검증 범위는 [v0.7.0 보고서](M7_REPORT.md)와 [0.7.1 새 A/B 보고서](M7_AB_REPORT.md)를 구분해 확인할 수 있습니다.

## 처음 실행하기

1. **ZIP 전체를 새 폴더에 압축 해제합니다.** ZIP 안에서 바로 실행하거나 `AiManager.exe`만 꺼내지 마세요. `_internal` 등 모든 동봉 파일이 필요합니다.
2. **`AiManager.exe`를 실행합니다.** 별도 Python 설치나 명령어 입력은 필요하지 않습니다. 화면은 독립 창으로 열립니다.
3. 필요하면 첫 화면의 **사용자 폴더에 설치**를 선택합니다. 새 버전 폴더를 만들어 복사하며 이미 있는 대상은 덮어쓰지 않습니다. 설치 완료 안내가 나오면 현재 창을 닫고 새 설치 폴더의 `AiManager.exe`를 실행합니다. 압축 해제한 위치에서 사용할 수도 있습니다.

이 앱은 시스템의 **Microsoft Edge WebView2 Runtime**을 사용합니다. 없거나 창을 열 수 없다는 안내가 나오면 설치 상태와 앱 파일을 확인하세요. 앱이 WebView2를 자동 전역 설치하지는 않습니다. 보안 경고나 명시적인 차단이 나오면 출처·배포 해시를 확인하고 중단하세요. 보안 설정을 끄거나 경고를 우회해서 실행하지 않습니다.

처음에는 인터넷과 충분한 저장 공간이 필요합니다. Python 기반은 동봉되지만 Torch 등 추론 의존성은 앱에서 별도로 내려받으며 수 GB의 공간을 사용합니다. 모델 가중치와 아래 개인 설정 파일은 ZIP에 들어 있지 않습니다.

## 처음 한 번: 계정과 모델 준비

### 1. 지정 설정 파일 선택

처음 화면에서 다음 두 JSON 원본을 선택합니다.

- **OAuth client 선택**: 이 앱이 Google 로그인에 사용할 클라이언트 설정 파일
- **허용 목록 선택**: 어느 계정의 어느 Drive 폴더를 읽을지 정한 파일

화면의 전체 경로 입력과 **경로 적용**을 사용할 수도 있습니다. 둘 다 선택한 뒤 **새 작업실 시작**을 누릅니다. 파일이 없다면 이번 프로젝트에 지정된 설정 원본을 먼저 준비해야 합니다. 내용·토큰·개인 경로를 공개 게시물에 붙여 넣지 마세요.

### 2. 두 계정 로그인과 목록 수집

**계정 및 수집**에서 A/B 각각 **Google 로그인**을 누릅니다. 별도로 열린 시스템 브라우저에서 사용자가 직접 로그인·동의합니다. OAuth 때문에 브라우저가 열리는 것은 정상이며 앱 본체는 독립 창입니다.

로그인 후 **인증 갱신 확인**, **새로 수집**으로 현재 연결과 허용 폴더 목록을 확인합니다. 계정 두 개를 각각 진행하세요. “인증정보 저장됨”만으로 현재 로그인 성공을 보장하지는 않습니다. 수집 완료는 허용 범위의 목록을 읽었다는 뜻이며 모델 파일 다운로드·실행 성공과 다릅니다.

### 3. 추론 환경 준비

**앱 추론 환경**의 **추론 환경 준비**를 누르고 준비 상태를 기다립니다. 처음에는 다운로드·설치 시간이 걸리며 환경에 따라 달라집니다. 완료 후 **모델 준비**의 **환경 점검** 또는 **환경 다시 점검**으로 의존성과 장치를 확인합니다. 환경 점검 통과도 아직 음성을 생성했다는 뜻은 아닙니다.

같은 설치 위치와 구성이면 정상 재실행 시 기존 환경을 사용합니다. 앱의 동봉 Python 폴더를 따로 이동하거나 삭제하지 마세요. 다른 설치 위치·구성은 새 환경 준비가 필요할 수 있습니다.

### 4. 사용할 모델 파일 준비

**0.6B 폴더 선택** 또는 **1.7B 폴더 선택**에서 해당 모델의 가중치·config·tokenizer가 들어 있는 **폴더**를 고릅니다. 파일 하나를 고르는 단계가 아닙니다. 지정 파일을 별도 준비 위치로 복사하고 크기·해시를 확인하며 원본은 보존합니다. 앱의 **모델 준비** 화면에는 허용 Drive 출처의 준비 기능도 있습니다.

0.7.1 후보에서는 **직접 경로로 준비할 모델**을 고르고 **지정 모델 원본 폴더 전체 절대경로**를 입력한 뒤 **이 경로로 모델 준비**를 누를 수 있습니다. **선택 모델·선택 원본 폴더**가 의도한 대상인지 확인하세요. 이 입력 방식은 공개 0.7.0에는 없습니다.

**모델 파일 준비·무결성 확인 완료**를 확인한 뒤 실행합니다. 1.7B는 0.6B보다 더 큰 모델이므로 준비 공간과 실행 시간이 더 필요할 수 있습니다.

## 한국어 음성 하나 만들기

1. **음성 작업실**에서 준비된 모델을 선택합니다.
2. 읽게 할 새 한국어 문장을 입력하고 **새 음성 생성**을 누릅니다.
3. 대기·생성 중·완료 상태를 확인합니다. 완료 전 다른 요청을 여러 번 누르지 마세요.
4. 성공한 결과의 재생 버튼으로 듣고 **WAV 저장**을 누릅니다.

실행이 대기열에 들어가면 앞선 작업이 끝난 뒤 실행됩니다. 실패·취소된 실행은 성공한 음성으로 표시하지 않습니다. 다른 모델이나 입력으로 다시 생성하면 별도 실행 기록이 생깁니다.

## 같은 문장으로 A/B 비교하기

두 모델이 모두 준비됐으면 **새 A/B 비교**에서 새 문장을 입력하고 **두 모델 새 비교 시작**을 누릅니다. 앱은 같은 입력·seed·공통 조건으로 A 다음 B를 순차 실행합니다. 두 모델을 동시에 GPU에 올리는 방식이 아닙니다.

완료 후 각각 재생하고 **A WAV 저장**, **B WAV 저장**으로 따로 저장합니다. 한쪽만 성공하면 부분 결과로 표시하며 실패한 쪽의 음성을 만들었다고 표시하지 않습니다. 시간·메모리 숫자는 해당 실행 조건의 측정값입니다. 숫자만으로 발음·자연스러움의 우열을 보장하지 않으며 평가는 사용자가 직접 듣고 판단합니다.

## 저장 창에서 폴더와 파일 이름 구분하기

Windows 저장 창의 **상단 주소/폴더 영역은 저장할 위치**, **하단 파일 이름 칸은 새 WAV 이름**입니다. 먼저 실제 저장 폴더를 확인하고 하단에 새 이름(예: `내음성.wav`)을 입력해 **저장**합니다. 파일 이름을 주소/폴더 영역에 입력해 같은 이름의 폴더를 만들지 않도록 확인하세요.

**취소**하면 저장하지 않습니다. 기존 파일에는 덮어쓰지 않으므로 새 이름을 선택하세요. 저장 후 앱의 저장 결과와 실제 폴더의 파일을 확인합니다. 예상 위치에 보이지 않으면 바로 반복 저장하기보다 저장 창에서 선택했던 실제 폴더부터 확인하세요. 앱 내부 결과 원본과 사용자가 별도로 저장한 WAV는 구분됩니다.

## 다음에 다시 사용할 때

일반적인 첫 설정 이후에는 같은 설치 폴더의 `AiManager.exe`를 실행해 같은 기본 작업실을 사용합니다. 이미 설정된 같은 작업실에서는 매번 JSON 선택·로그인·환경 설치를 반복할 필요가 없습니다. 연결 오류가 있으면 **인증 갱신 확인**으로 상태를 확인하고 필요한 계정만 다시 로그인합니다. 모델 원본을 바꿨다면 새 준비·검증이 필요합니다.

**별도 작업실 경로를 지정해 실행했다면 같은 실행 옵션을 유지해야 합니다.** 이번 로컬 0.7.1 검증은 별도 작업실을 지정한 환경이므로 실행 파일만 더블클릭하면 검증 때의 인증·모델 준비를 자동으로 이어 쓰지 않습니다. 기본 작업실의 처음 설정 화면이 열렸다고 기존 데이터가 삭제된 것은 아닙니다. 이 경우 제공받은 해당 작업실의 실행 방법을 사용하고 개인 폴더를 복사·이동·삭제하지 마세요.

실행 기록에서 성공·실패·취소 상태와 결과를 확인할 수 있습니다. 진행 중 작업은 화면의 취소 기능을 사용합니다. 앱 창을 닫으면 소유 작업자의 종료 절차를 수행합니다. 재시작은 이전 기록을 다시 읽는 것이며 중단된 음성 생성을 자동으로 이어서 성공시키는 기능은 아닙니다. 설정·모델·기록 폴더를 지우거나 옮겨 오류를 해결하지 마세요.

## 막혔을 때 확인할 것

| 상황 | 먼저 확인할 것 |
|---|---|
| 실행 후 창이 늦게 뜸 | 잠시 기다리고 중복 실행하지 않기. 시작 지연 사례가 있으나 원인은 미확정이며 모든 실행이 같은 시간에 열리는 것은 아님 |
| 로그인 필요·갱신 실패 | 해당 A/B 계정의 로그인·동의와 현재 연결 상태 확인 |
| 환경 준비 실패 | 인터넷·여유 공간·앱 파일 무결성 확인 후 표시된 재준비 기능 사용 |
