## 1. 목표

사용자가 “내가 가진 모델이 무엇인지, 어떤 용도인지, 실행 준비가 되었는지, 새로 실행하면 결과가 어떤지”를 한 화면에서 파악한다.

초기 배포 형태는 **개인 PC에서 실행하고 로컬 브라우저로 접속하는 앱**으로 제안한다. 모델은 Drive에서 직접 실행하지 않고 승인된 파일을 로컬 저장소에 준비한 뒤 실행한다. 원격 서버·공개 웹 배포는 후속 범위다.

## 2. 첫 버전의 범위

### 포함

- 계정 A/B별 연결 상태와 허용한 모델 폴더 선택.
- 수동 새로고침, 스캔 진행·오류·부분 완료 표시.
- 모델 용도·계열·파일 형식·용량·저장 위치 검색.
- 모델 상세의 필수 구성요소, 누락 이유, 근거와 최근 확인 시각.
- 선택한 파일의 다운로드 전 용량 확인, 임시 파일과 검증된 파일 분리.
- 음성 합성 모델 하나의 실제 실행과 WAV 재생·저장.
- 같은 작업 유형의 모델 2종을 동일한 새 입력으로 순차 비교.
- 이 프로젝트에서 생성한 실행 기록의 조회와 오류 진단.

### 후속 단계

- STT, 이미지 생성, LLM, 영상 점 추적용 개별 실행 어댑터.
- 원격 GPU 워커, 다중 사용자, 일정 기반 실행.
- 모델별 라이선스·버전 변경 알림과 고급 평가.

### 초기 제외

- 모든 모델 파일을 범용 실행 버튼 하나로 실행하는 기능.
- Drive 파일의 삭제·이동·자동 업로드.
- 전체 모델의 자동 다운로드·자동 모델 코드 실행.
- 서로 다른 작업의 속도를 한 점수로 순위화.
- 과거 프로젝트 데이터·기존 시안 이미지·측정 결과의 가져오기.
- 유료 인프라 생성과 공개 서비스 운영.

## 3. 화면 구성

| 화면 | 주요 내용 | 사용자 행동 |
|---|---|---|
| 개요 | 최근 스캔 시각·계정 연결·발견 모델·상태별 집계 | 부족한 항목으로 이동 |
| 모델 목록 | 이름·용도·계열·저장 위치·파일 규모·확인 수준 | 검색·필터·상세 열기 |
| 모델 상세 | 파일 구성·필수 의존성·출처·누락 이유·런타임 지원 | 검증·준비 요청 |
| 실행 작업실 | 입력·파라미터·환경·예상 필요 자원·진행·취소 | 새 실행·결과 재생 |
| 비교 | 같은 입력의 A/B 출력과 실제 측정 조건 | 비교 세션 생성·평가 |
| 실행 기록 | run_id·상태·시각·오류·현재 환경과의 차이 | 과거 실행임을 인지하고 조회 |
| 연결·설정 | 계정 A/B·허용 폴더·로컬 위치·보관 정책 | 범위 설정·연결 해제 |

미수집 수치는 0으로 꾸미지 않고 “미확인”으로 표시한다. 예시 데이터 모드는 실제 데이터 모드와 분리하고 화면에 고정 표시한다. 미실행 모델에는 성공 배지를 붙이지 않는다.

## 4. 기술 구성 제안

M0에서 공식 패키지 요구사항과 PC 환경을 조사했고 M3에서 별도 Windows 환경·고정 의존성·실제 import/CUDA 연산·선택 자산의 바이트 해시를 검증했다. [M3 결과와 한계](M3_REPORT.md)를 따른다. Windows의 실제 모델 로딩·한국어 생성·WAV·재생은 M4에서 검증했다. 청취·내용 정확도와 비교 품질은 미검증이다. [M4 보고서](M4_REPORT.md)를 따른다.

- 화면: React + TypeScript 기반의 새 UI.
- API·작업 조정: Python 기반 로컬 API.
- 데이터: 초기 개인용 SQLite, 스키마 버전과 마이그레이션 기록.
- 실행: 모델 유형별 어댑터와 별도 작업 프로세스. GPU 작업은 기본 1개씩.
- 저장: 모델 자산 캐시와 실행 결과 디렉터리 분리.
- 연결: 두 계정을 분리한 읽기 전용 Drive 인증.
- 환경: 앱 환경과 추론 환경을 분리하고 패키지 버전을 고정.

현재 Codex의 Google Drive 연결은 조사 도구다. 제작 앱의 OAuth 클라이언트, 범위, 토큰 저장·갱신 방식은 별도 설계·검증한다. 개인 토큰을 소스에 넣지 않는다.

## 5. 초기 실행 모델

첫 실행 모델은 **Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice**로 선정했다. M0 당시 공식 revision의 13개 파일 경로·크기를 대조했고, 이후 M3에서 새 Drive 다운로드 13개 전량의 실제 SHA-256과 별도 환경을 검증했다. M4 모델 로딩·출력의 최종 실제 검증 상태는 [M4 보고서](M4_REPORT.md)에 별도로 기록한다. 첫 검증은 새 한국어 문장, Korean, Sohee, batch 1로 진행하고 instruct는 제외한다. 텍스트 입력과 WAV 출력으로 완료 여부를 검증한다. [세부 근거](M0_REPORT.md)

M5에서 명시 승인된 두 번째 모델은 `Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice`다. 공식 revision은 `0c0e3051f131929182e2c023b9537f8b1c68adfe`이다. 지정 Drive 가중치를 사용하고 필수 speech tokenizer config만 같은 revision의 공식 파일로 보완한다. Drive 원본은 보존하며 모델 준비·실행 성공은 각각 새로 검증한다. 두 모델을 GPU에 동시에 적재하지 않고 순차 실행한다. 메모리·의존성 조건을 충족하지 못하면 실행 완료를 주장하지 않고, 더 작은 승인 모델 또는 환경 조정안을 검토한다. 원격 GPU를 자동 생성하지 않는다.

## 6. 성공 기준

- 사용자가 두 계정의 지정 폴더에서 모델을 찾아 현재 확인 수준을 이해한다.
- 누락된 구성요소가 있는 모델은 이유가 표시되며 실행을 차단한다.
- 첫 모델의 새 출력 파일을 실제 생성하고 UI에서 재생한다.
- 비교 화면의 모든 수치는 새 실행 ID와 조건에 연결된다.
- 취소·오류·재시작이 성공 상태로 둔갑하지 않는다.
- 이전 산출물 재사용 및 개인 데이터의 공개 저장소 유출이 없다.

## 7. 운영 원칙

단계별 범위 승인 → 구현 → 독립 검토 → 완료 보고 → 다음 단계 범위 승인으로 진행한다. M0와 M1의 두 계정 연결·읽기 전용 목록 구현·검증·게시, M2 실제 목록의 검색·필터·모델 상세 대시보드 UI, M3 첫 모델 읽기 전용 다운로드·바이트 검증·별도 환경 준비·공개 의존성 설치·구현·검증·게시가 승인됐다. M1 완료 근거는 [M1 보고서](M1_REPORT.md), 이후 승인 범위는 [승인 기록](APPROVALS.md)에 기록한다. 모든 실무는 서브에이전트가 수행하며 이후 생성 서브에이전트는 GPT-6.1 sol / medium을 사용한다. M4 첫 모델의 한국어 TTS·WAV·UI·오류·취소 구현·검증·게시도 명시 승인됐다. M5 두 모델의 동일한 새 한국어 입력 A/B 비교 구현·실제 검증·문서·게시도 명시 승인됐다. 같은 M1·M2·M3·M4·M5 범위의 의존성 설치·테스트·수정·GitHub 반영에 재승인을 요구하지 않는다. 앱 OAuth와 설치·추론 불확실성을 해소한 뒤 작업량을 산정한다.

## 8. 완성도 우선 원칙

전체 기능·작동·대시보드·UI를 가능한 범위에서 높은 완성도로 만든다. 제품 가치와 신뢰성을 우선하며 예쁜 UI로 미구현 상태를 감추지 않는다. 상태의 근거·무결성·재현성, 실계정 E2E, 한국어 가독성·디자인 일관성·접근성·반응형 검증을 [품질 게이트](QUALITY_GATES.md)로 관리한다. M2/M4/M6는 목업 또는 단순 스모크 성공만으로 완료하지 않는다. 이 원칙은 단계별 품질 계획이다. M2 조회 UI와 M3 첫 모델 준비는 명시 승인됐다. M4 첫 모델의 한국어 TTS·WAV·UI·오류·취소는 별도로 명시 승인됐다. M5 같은 계열 두 모델의 새 A/B 비교는 명시 승인됐으며 핵심 실행·재생·부분 취소 검증을 마쳤다. 정상 지원 Edge A/B 저장 무결성까지 확인해 원계획의 승인 기능을 검증했다. Chrome 차단 원인·별도 시도 종결은 알려진 미확정 제한이며 선택 품질 평가·M6와 구분한다. [M5 보고서](M5_REPORT.md)의 이번 증거로 완료를 판정하며 M6 원계획 개인용 로컬 출시는 명시 승인됐으며 [M6 보고서](M6_REPORT.md)의 새 증거로 완료를 판정한다. 승인에 없는 확대는 별도다.

모델 유형별 어댑터를 확장하되 각 유형의 입력·출력·실패·검증 기준을 별도로 마련한다. TTS 뒤 STT·LLM·이미지·영상 유형의 범위는 단계별로 승인한다. 범용 실행 또는 원격 비용 발생을 자동 승인하지 않는다.

원계획의 개인 PC 로컬 출시가 2026-10-17 명시 승인됐다. 최신 배포 패키지·신규 환경 설치/시작·인증/DB/작업 복구·Edge 대표 실제 흐름·전체 UI 회귀를 새 M6 실행으로 검증했으며 확인 범위·제한은 M6 보고서를 따른다. M5 결과를 현재 PASS 근거로 대체하지 않는다. 프로그램 형태 배포는 실행 패키지와 UI host를 구분해 검토하며 새 네이티브 UI 전체 재구현을 자동 승인하지 않는다. [승인 범위](APPROVALS.md) · [M6 진행 보고서](M6_REPORT.md)

## M7 최신 승인과 실행 기준

후속 0.7.1 후보에서는 사용자 명시 요청에 따라 새 1.7B 준비와 동일 새 한국어 입력의 두 모델 실행·앱 재생·native 저장본 무결성을 검증했다. 앞선 준비 실패의 원인은 미확정으로 보존하고 경로·파일 크기 관측과 정상 제품 경로 입력을 보완했다. 소스/문서 반영과 공개 배포를 구분하며 v0.7.0 Release·태그·ZIP은 유지한다. [새 A/B 결과와 범위](M7_AB_REPORT.md)

2026-10-17 별도 Python 설치 없이 실행하는 Windows 독립 앱의 구현·새 설치·사용자 인증·실제 TTS·native 파일 저장·비식별 게시가 명시 승인됐다. v0.7.0은 앱 Python과 추론 Python을 포함하고 독립 WebView2 창을 제공한다. WebView2 시스템 전제는 별도로 안내하며 전역 설치·보안 설정을 자동 변경하지 않는다. M6 개인 자료와 출시를 보존하고 M7 고유 home/runtime/output의 새 증거로 완료를 판정한다. desktop4 새 GUI 설치·독립 창·A/B 사용자 인증/갱신·새 수집·런타임 설치·0.6B 파일 준비를 확인했다. desktop5에서 계약·동시 종료 수정 테스트와 새 GUI 설치/전량 해시·새 런타임 ready를 확인했으며 실제 CUDA·새 0.6B TTS·native 저장·취소·실행 중 종료를 확인했다. 정상 종료/재시작의 상태·해시 보존도 확인했다. 재시작 후 독립 창 재생·두 계정 실제 갱신까지 확인해 필수 실제 흐름을 검증했다. 정상 [v0.7.0 Release](https://github.com/castle923/Ai-manager/releases/tag/v0.7.0)와 첨부 ZIP 크기/digest 및 소스 태그 대상 `066e62d286cb50fee1755bd0146c3ddbd3188526`을 확인해 승인 범위 출시를 완료했다. 후속 main 변경은 문서 보완이며 태그를 이동하지 않는다. 1.7B 새 M7 추론은 미검증이다. M6 결과로 M7 PASS를 대체하지 않는다. [M7 계획](M7_PLAN.md) · [M7 진행 보고서](M7_REPORT.md)
