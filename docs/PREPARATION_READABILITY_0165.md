# 모델 준비 화면 가독성 · Windows 0.16.5

상태: 소스·합성 미리보기·새 portable 패키지 무결성 검증 완료, 확인한 네이티브 화면의 가독성 검증 완료. 새 GitHub Release나 태그를 뜻하지 않는다.

## 변경

앱 추론 환경과 모델 파일 준비를 각각 흰 카드로 나누고 단계·제목·상태·주요 버튼의 위계를 구분했다. 본문은 진한 중립색, 입력과 선택은 44px 높이를 사용한다. 첫 환경 준비에 인터넷과 수 GB 공간이 필요하다는 안내는 항상 보인다. Python 포함 설명, runtime ID, 복사·해시 관련 기술 설명은 기본 접힌 `자세히 보기`에서 확인한다.

진행 상태, 오류, 원본 폴더, 선택 모델과 preflight 파일 정보는 접지 않는다. 기존 선택자·핸들러·busy/disabled 조건·취소·경로 trim 검사와 native 경로 전달은 유지한다. 화면 개선은 모델 파일 준비나 추론을 수행한 결과가 아니다.

## 이번 검증

- TypeScript/Vite 빌드와 기존 desktop·package integrity·local mode·native guard·view contract 관련 40개 회귀 테스트가 통과했다. 첫 테스트 명령은 PYTHONPATH 미지정으로 import 오류였으며, src 경로를 지정한 최종 실행 40개 통과와 구분한다.
- 실제 컴포넌트와 CSS에 브라우저 메모리의 합성 bridge만 연결한 비공개 미리보기를 사용했다. 실제 backend·인증·파일 접근·모델 실행·다운로드는 연결하지 않았다. 미리보기 HTML과 fixture는 저장소와 패키지에 포함하지 않는다.
- 1266px 컴포넌트 미리보기에서 기본·진행·실패·접근 거부 상태별 표본을, 768px에서는 기본 상태 표본을 확인했다. 768px 표본의 문서 가로 넘침은 없고 입력·선택 높이는 44px였다. 이 폭은 실제 네이티브 앱 shell 폭 검증과 다르다.
- 기본 닫힌 두 details, 상시 보이는 상태·오류·preflight, 취소와 직접 경로 준비의 합성 메서드/모델 ID/경로 전달을 확인했다. 비반환 setup 12개와 기능 JSX 속성 19개의 AST 비교가 동일했다. 이는 실제 native 폴더 선택과 모델 준비 실행 성공 증거가 아니다.

실제 모델 파일 준비·취소, 추론·다운로드·OAuth, 스크린리더·모든 폭과 상태는 검증하지 않았다. 기존 인증·자료·모델 원본을 변경하지 않는다. 기존 로컬 모드 및 보안 경계는 [0.16.4 문서](TYPOGRAPHY_LOCAL_0164.md)를 따른다.

## 새 패키지의 근거와 범위

제품 소스 커밋은 `8c6c6266f43576869bd290c9bb58510e68c28dc4`다. 패키지는 이 커밋의 78개 source 파일과 결합하며 후속 문서 커밋과 구분한다. 8,314개 manifest 파일과 ZIP 전량 SHA, ZIP CRC·중복·위험 경로 및 소스 바이트 대조가 통과했다. 실행 파일의 전체 무창 자체 검사도 0.16.5 / 해당 소스로 verified를 반환했다. 독립 검토자가 별도로 대조했다. 선택한 텍스트의 알려진 개인 경로·계정·토큰 패턴은 발견하지 않았으며 모든 바이너리의 비밀 부재를 보장하는 검사는 아니다. 라이선스와 고정 공개 CPython 배포 출처를 동봉한다.

이번은 새 portable 빌드 검증이다. installer 핵심은 바꾸지 않았고 0.16.5 새 설치를 반복 실행하지 않았다. 프로그램 파일의 출력 위치와 모델 준비 사본의 작업실 위치는 다르며 기존 자료의 이동·정리·자동 캐시 변경은 수행하지 않는다.

## 실제 네이티브 관찰

사용자가 새 0.16.5 portable EXE를 새 로컬 작업실로 직접 열었다. 정상 시작 화면에서 Drive 없이 로컬 작업실 시작을 선택한 뒤 1266×893 창의 새 준비 영역을 관찰했다. 두 상세 설명이 기본 접힘이고 환경 ID가 기본 숨김인 점, 환경 상세를 펼쳤을 때 ID와 기술 안내가 나타나고 다시 접히는 점, 모델 상세의 복사·해시 안내 펼침을 확인했다. 제목·상태·주/보조 버튼·입력/선택과 빈 경로 준비 버튼의 비활성 표시가 보이는 표본에서 읽혔으며 겹침·잘림은 발견하지 않았다. 검증 뒤 상세는 다시 접었다.

초기 로컬 작업실 전환의 라이브러리 요청에서 `Failed to fetch`가 관측됐다. 지원되는 다시 불러오기 한 번 뒤 배너가 사라졌고 후속 접근성 상태에도 오류 문구가 없었다. 원인은 미확정이며 초기 전환 전체를 PASS로 보지 않는다. 준비 영역의 가독성 관찰과 이 요청 오류를 구분한다. 모델·환경 준비, 폴더 선택 대화상자 실행, 다운로드·추론·OAuth를 클릭하지 않았고 실제 네이티브 좁은 창·zoom·재시작은 검증하지 않았다.
