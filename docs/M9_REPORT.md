## 소스 단계의 중간 검증

10월 17일 전체 자동 테스트 198개(기존 184개와 M9 신규 14개)가 30.765초에 통과했다. 별도 독립 검토는 동결 소스 18파일 일치와 신규 14개 테스트의 통과(2.897초), 원본 이동 URL 7개 경계 및 큰 보기 설정 revision의 정밀도 수리를 확인했다. TypeScript/Vite 빌드도 통과했다. 이 결과는 소스·합성 반례 단계이며 실제 Windows 독립 창·설치본·새 GPU 실행의 성공으로 대신하지 않는다.

초기 빌드는 상위 출력 디렉터리 부재로 기능 소스 산출 전 중단됐다. 새 상위 디렉터리를 준비해 같은 동결 소스로 빌드를 완료했으며 기능 소스 변경은 없다. 구현 담당 및 독립 패키지 검사는 payload 4,290파일·소스 30파일·ZIP 4,291항목과 동결 안내 바이트의 일치를 확인했다. ZIP은 58,463,775 bytes, SHA-256 `4ef883b17bb458d35852913a3e22d0f3ee32d81eff62fe12d4c205cc0c03980c`다.

앞선 GUI 진입에서는 설치 프로그램 실행 뒤 사용자의 중단으로 멈췄으며 설치 버튼·새 작업실 설정·런타임·모델·GPU 검증은 수행하지 않았다. 10월 18일 사용자가 실제 설치·설정·새 A/B·기록/차트·재생/저장·재시작 검증의 재개를 명시했다. 당시 재개 지점에는 실제 사용 검증 결과가 없었으며 이후 후보 1의 차단과 후보 2의 수리는 아래에 구분한다. 이전 중단을 제품 실패나 새 성공으로 해석하지 않는다.

## 후보 2 — native 연결 수리와 검증 범위

재개 후 후보 1은 실제 설치와 초기 빈 기록 화면까지 확인했으나, 화면 상태를 URL query에 넣으면서 native bridge의 query 금지 정책에 걸렸다. 설정 저장·런타임 준비·새 GPU 실행 전에 중단했으며 해당 기능의 성공 근거는 없다.

후보 2는 화면 상태를 fragment로 옮기고 native 거부 상태를 명시하며 관련 동작을 비활성화했다. native bridge의 신뢰 검증과 query 금지 정책은 완화하지 않았고 setup의 URL 계약도 유지했다. 소스 20파일 동결 후 전체 201개 테스트가 28.530초에 통과했고 프런트엔드 빌드는 5.88초에 통과했다. 신규 native 계약 3개 테스트는 구현 담당 0.376초·독립 0.404초에 통과했으며 화면 fragment 경로 7개와 거부 경계 6개를 확인했다. 이는 소스·계약 검사이며 실제 native 사용 성공과 구분한다.

구현 담당과 독립 패키지 검사는 후보 2의 payload 4,290파일·소스 30파일·ZIP 4,291항목 및 안내 바이트 일치를 확인했다. ZIP은 58,463,937 bytes, SHA-256 `d9fdf31dd7ee8ff04e0d1efd88babcce4689492fc21eb3652676eb06c0905167`다. EXE SHA-256은 `c4d668919418d3301c716b919637fd6dc383fe24d6da36a499cd4d72a944e483`, manifest SHA-256은 `d898df00672444e13a9b13c567009d8b04922cd3ac2af3e4fe6099cf256e4cb2`다. 후보 1의 검사·화면 관측을 후보 2의 실제 성공으로 대신하지 않는다. 실계정 수집 경로의 이번 E2E도 미검증이다.

개인 계정·실제 경로·Drive ID·자격 증명·원시 로그·입력/출력은 공개하지 않는다. 기존 registry/inventory·모델·인증·WAV와 출시 기록을 보존하고 과거 측정·PASS를 새 M9 성공으로 대신하지 않는다. 작업공간 커스텀·Drive 쓰기·새 모델 계열·원격 GPU·전역 보안 변경은 이번 범위에 없다.

## 10월 18일 실제 설치·런타임 준비 후 재개

후보 2의 실제 새 설치본은 전체 4,291파일 해시를 대조했다. 새 추론 환경은 준비 완료 상태이며 동봉 Python 3.10.22 기반·실제 로드 DLL·고정 의존성 97개 정합을 확인했다. 이는 아직 CUDA 동작이나 모델 로딩·음성 생성 성공의 증명이 아니다.

이후 사용자의 명시적 중단으로 설정 저장 전 멈췄다. 중단 시 보기 설정은 revision 0이며 저장 0회, 모델 준비·CUDA·새 A/B·WAV 저장·재시작 검증은 모두 0회다. 새 설치·런타임과 기존 자료를 보존했다. 사용자가 같은 설치·런타임에서 설정 저장부터의 재개를 명시했으며 당시 보고 시점에는 후속 실제 결과가 없었다. 이후 후보 2의 결과와 후보 3의 수리는 아래에 구분한다. 중단 자체를 제품 실패로 판정하지 않으며 이미 완료한 설치·런타임을 새로 수행한 것으로 중복 기록하지 않는다.

## 후보 3 — 비교 기록 상태 파생 수리

후보 2의 새 A/B는 양쪽 음성 생성·성능 API·WAV 검증에 성공했지만 통합 기록이 비교 원본을 읽기 실패로 오판했다. 비교 원본 serializer는 status를 직접 저장하지 않고 하위 실행에서 상태를 파생하는데, 통합 기록이 status 필드를 필수로 요구한 것이 원인이다. 이로 인해 전체 실제 gate는 통과하지 못했으며 후보 2의 재생·native 저장은 0회다. 이 생성 결과를 후보 3의 새 성공으로 재사용하지 않는다.

후보 3은 history.py와 unit/HTTP 테스트의 3파일만 수정했다. 추론 코드 12파일·UI·native 신뢰 검증·동결 설치 안내는 바꾸지 않았다. 전체 205개 테스트가 29.004초에 통과했고 독립 회귀 18개도 통과했다. 실제 serializer의 status 없는 기록을 사용해 정상 8종·오류 7개·UTC offset과 원본 bytes 보존을 확인했다. 실제 후보 2 기록 8행의 수정 후 재조회도 정상이며 이는 기록 투영 수리 검증이지 새로운 모델 실행 성공이 아니다.

후보 3의 구현 담당 및 독립 패키지 검사는 payload 4,290파일·소스 30파일·ZIP 4,291항목 정합을 확인했다. ZIP은 58,466,209 bytes, SHA-256 `596538cb502e7e63de44c522f1ee470a833cbf12fd8c45dae93964a40e46e200`다. EXE SHA-256은 `a0f2d4bb6816900fb70b5291fd3a3e4b8338e74e4f60e12891ccb34f0bf2581b`, manifest SHA-256은 `0b8bbc5a2ab1e47af7ad169c6df5c11b298f1f84b49fcdb1bd8a8015a69ca3f9`다. 이 단계에서는 후보 3의 새 실제 검증을 대기로 두었으며 이후 결과는 아래에 별도로 기록한다. 과거 후보의 성공으로 이 gate를 대체하지 않는다.

## 후보 3의 새 실제 A/B·기록·성능 검증 — 2026-10-18

새 설치본의 별도 런타임은 동봉 Python 3.10.22 기반과 실제 로드 DLL이 일치했다. System32만의 PATH·Python 환경변수 제거·격리 실행에서 고정 의존성 97개와 설치 97개의 정합을 확인했다. 환경 검사는 모델 import 없는 검사이며 아래 GPU 실행과 구분한다.

이번에 새로 만든 30자 한국어 입력·동일 seed 1312644436·동일 공통 생성 조건으로 A(0.6B)→B(1.7B)를 콜드 순차 실행했다. 모델별 n=1, 캐시 재사용은 없다. 지정 원본·새 준비본·고정 manifest의 25파일 전체 SHA/크기/구성 집합과 추론 코드 12파일·런타임 lock·현재 소스/설치 소스 30파일을 연결해 독립 검증했다. 두 실행 모두 succeeded·오류 없음·EOS 도달이며 이전 후보 출력으로 대신하지 않았다.

| 지표 | A — 0.6B | B — 1.7B |
|---|---:|---:|
| 모델 로딩 (초) | 2.531 | 3.563 |
| 음성 생성 (초) | 20.110 | 17.375 |
| 총 처리 (초) | 32.656 | 32.750 |
| PyTorch 최대 할당 (bytes) | 2,361,982,976 | 4,342,098,944 |
| 화면 표시 (MiB, 소수 3자리) | 2,252.563 | 4,140.948 |
| WAV 길이 (초) | 6.32 | 4.96 |
| WAV 크기 (bytes) | 303,404 | 238,124 |

둘 다 PCM16·mono·24 kHz이며 clipping 0이다. A WAV SHA-256은 `21ac9de2a6edd29087ec02f01754853c9377db9e4d951dfb9d98a515e64babb0`, B는 `9652468cb188b9890cf6f655d3b4d9e8f9aa436b6eb20089275a688941eda9e3`다. 총 처리는 무결성 검사·로딩·프로세스 부가 시간을 포함하며 큐 대기와 구분한다. 메모리는 PyTorch 최대 할당량으로 전체 VRAM이 아니다. 서로 다른 출력 길이의 단회 측정으로 속도·음질 우열을 일반화하거나 자동 승자를 정하지 않는다.

새 비교의 통합 기록은 completed/read_error=false이며 하위 실행 2개와 연결됐다. 원본 12행을 10+2 고정 페이지로 대조해 중복·누락·읽기 오류 0을 확인했다. 공통 조건 API와 원천 표의 수치가 일치했다. 보기 설정은 revision 1의 기본 화면 통합 기록·10개·UTC·MiB이며 알려진 원본 JSON·두 DB·설정의 읽기 전후 해시 보존을 확인했다. 실제 독립 창에서도 전체 시간·로딩·생성·메모리 수치와 막대·원천 표, 메모리 단위 전환과 공통 조건 펼침을 확인했다. 종류/상태 필터·빈 결과·원본 ID 이동·F5 재조회와 고정 10+2 페이지도 확인했다.

## 실제 재생·저장·정상 재시작

후보 3의 새 A/B를 각각 6.32초·4.96초 끝까지 재생했고 정상 Windows 저장 대화상자로 각 1회 저장했다. 독립 검사에서 두 저장본은 각 새 원본과 SHA-256·크기·PCM 형식이 일치하고 파일 ID는 서로 달랐다. 실제 개인 경로는 공개하지 않는다. 재생 완료는 발음·자연스러움의 주관적 품질 판정이 아니다.

정상 종료 뒤 기존 앱과 자손 7개 및 이전 수신 포트가 사라졌다. 같은 설치·작업실을 새 프로세스와 포트로 다시 열어 기본 화면 통합 기록, 설정 revision 1의 10개·UTC·MiB, 기록 12행과 새 비교 completed·하위 실행 2개, 동일 런타임 재사용·재설치 0회를 확인했다. 실제 재시작 화면에서 차트와 표도 유지됐다. 재생·저장은 재시작 전에 각 1회 했으며 재시작 뒤 반복하지 않았다.

종료 전후 60개 지정 파일(두 DB·연결/보기 설정·런타임 기록·준비 자산·새 입력/출처·원본/저장 WAV와 관련 기록)의 누락·변경은 0개였다. 설치 파일 4,290개도 전량 해시가 유지됐다. 승인된 사용자별 로컬 바로가기 1개만 추가됐으며 대상 실행 파일·명시한 작업실·작업 디렉터리를 읽어 확인했다. 이 바로가기가 공개 ZIP에 자동 제공된다는 뜻은 아니다. 기존 M8과 이전 작업실·배포물도 보존했다.

## 현재 제한과 남은 확인
