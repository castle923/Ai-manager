# 승인 범위와 사용자 직접행위

기록일: 2026-10-16 · M1 명시 승인 후 진행 중

## 이미 승인된 M1 범위

사용자는 두 계정 연결, 지정 허용 범위의 읽기 전용 모델 목록, 해당 구현·검증과 저장소 반영을 승인했다. 이 범위에 필요한 신규 로컬 앱 구현, 공개 의존성 설치, 테스트, 발견한 오류 수정, 문서 갱신과 GitHub 게시에 같은 승인을 반복해서 요구하지 않는다. 계정별 allowlist와 비공개 저장 위치 등 필수 앱 설정을 포함한다.

작업공간 커스텀은 사용자 정정에 따라 이 프로젝트 요구에서 제외한다. 작업공간 이름·여러 루트·위젯 배치·테마 커스텀을 M1 요구 또는 후속 제품 약속으로 취급하지 않는다. 기존 자료 보존과 실행별 출력 경로 분리 규칙은 유지한다.

## 승인이 아닌 사용자 직접행위

Google 계정 로그인과 OAuth 동의는 사용자가 브라우저에서 직접 수행해야 한다. 이는 승인된 M1 인증 검증에 필요한 참여이며 새 범위 승인 요청이 아니다. 비밀번호·인증 코드·토큰을 채팅에 요구하지 않는다. 두 계정 각각의 동의, 실제 scope, 새 앱 조회·갱신 결과를 확인해야 실계정 E2E 완료로 판정한다.

## 이후 범위 승인

현재 단계 규칙상 M2 조회 대시보드, M3 모델 다운로드·환경 준비, M4 추론, M5 새 비교, M6 개인용 출시는 해당 범위 승인 후 진행한다. 사용자는 명시적으로 후속 단계를 묶어 승인할 수 있으며 그 경우 승인된 범위 안에서 반복 확인하지 않는다. 단계 승인이 있어도 완료 판정은 새 구현과 실행 증거에 따른다.

아래 행위가 실제 다음 작업에 필요하고 기존 승인에 포함되지 않은 경우에는 대상·목적·영향을 구체화한 뒤 승인을 받는다. 발생 가능성만으로 미리 포괄 승인을 요구하지 않는다.

| 변경 | 확인할 범위 |
|---|---|
| 기존 자료 삭제·이동·덮어쓰기 | 실제 대상과 보존·복구 방법 |
| Drive 쓰기 | 실제 변경 파일·행위·권한 확대 |
| 공개 배포 또는 비용 발생 원격 GPU | 공개 범위·서비스·비용·종료 조건 |
| 새 계정·데이터 루트 접근 또는 외부 전송 | 실제 접근/전송 대상·목적·범위 |
| 실질적인 기능·데이터·실행 범위 확대 | 현재 승인과 달라지는 부분 |

허용된 공개 라이브러리 다운로드, 승인된 두 계정의 읽기 전용 API 호출, 비식별 코드·문서의 승인된 GitHub 반영을 새 외부 전송 승인 요청으로 중복 취급하지 않는다. 이전 산출물 재사용 예외는 특정 결과물과 사용 목적에 대한 별도 명시 허용이 필요하며 일반적인 진행 지시나 단계 승인은 금지 해제가 아니다.

## 현재 상태

M0 조사·설계·OAuth 파일 준비는 완료됐고 M1 구현·검증은 진행 중이다. 실계정 검증과 단계 완료 판정은 [M1 보고서](M1_REPORT.md)에 기록한다. M2 이후는 아직 승인되지 않았다.
