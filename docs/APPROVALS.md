# 승인 범위와 사용자 직접행위

기록일: 2026-10-16 · M1~M4 승인 범위 완료 / M5 승인 기능 검증 완료(확인한 로컬·Edge 범위)·Chrome 알려진 제한 / M6 이후 미승인

## 이미 승인된 M1 범위

사용자는 두 계정 연결, 지정 허용 범위의 읽기 전용 모델 목록, 해당 구현·검증과 저장소 반영을 승인했다. 이 범위에 필요한 신규 로컬 앱 구현, 공개 의존성 설치, 테스트, 발견한 오류 수정, 문서 갱신과 GitHub 게시에 같은 승인을 반복해서 요구하지 않는다. 계정별 allowlist와 비공개 저장 위치 등 필수 앱 설정을 포함한다.

작업공간 커스텀은 사용자 정정에 따라 이 프로젝트 요구에서 제외한다. 작업공간 이름·여러 루트·위젯 배치·테마 커스텀을 M1 요구 또는 후속 제품 약속으로 취급하지 않는다. 기존 자료 보존과 실행별 출력 경로 분리 규칙은 유지한다.

## 이미 승인된 M2 범위

사용자는 실제 수집된 인벤토리를 사용하는 검색·필터·모델 상세 대시보드 UI, 가능한 범위에서 높은 완성도의 기능·작동·UI, 검증과 저장소 반영을 명시 승인했다. 같은 범위의 의존성 설치·로컬 테스트·오류 수정·문서 갱신·비식별 GitHub 반영은 반복 승인이 필요하지 않다.

현재 Ai-manager 프로젝트의 수집 목록을 조회 입력으로 사용하고 코드·문서를 갱신한다. 이는 사용자가 지정한 같은 프로젝트의 후속 작업이며 다른 프로젝트 결과물이나 기존 앱·배포·생성 캐시 연결을 허용하지 않는다. M1의 549개 파일 관찰과 과거 테스트 결과는 역사 기록이다. M2 검증에서는 이번 코드와 새로운 실행 증거를 별도로 남긴다. 작업공간 커스텀은 계속 제외한다.

## 이미 승인된 M3 범위

사용자는 첫 모델의 읽기 전용 다운로드, 실제 파일 바이트·해시 검증, 별도 환경 준비와 공개 의존성 설치, 해당 기능·UI 구현·테스트·문서·저장소 반영을 명시 승인했다. 같은 범위에서 필요한 설치·수정·새 검증·비식별 GitHub 반영은 반복 승인이 필요하지 않다. 대상은 공식 고정 revision을 기록한 첫 모델이며 전체 인벤토리 일괄 다운로드나 임의 모델 실행으로 확대하지 않는다.

동일 프로젝트의 지정된 수집 메타데이터와 허용된 모델 자산을 사용한다. 실행마다 새 자산 출력·출처 기록을 만들고 기존 결과·중단 실행·다른 프로젝트 파일을 성공 입력으로 섞지 않는다. 공개 라이브러리·공식 모델 정보는 출처와 버전을 기록한다. 다운로드·해시 일치·의존성 import·CUDA 가용성은 모델 로딩·추론 성공과 구분한다. M3 승인 자체는 모델 추론을 포함하지 않는다. M4의 별도 명시 승인은 아래에 기록한다. 작업공간 커스텀은 계속 제외한다.

## 이미 승인된 M4 범위

사용자는 선정된 첫 모델의 실제 로딩·한국어 TTS 추론·새 WAV 생성, 실행 UI·오류·취소 처리, 구현·검증·문서와 비식별 저장소 반영을 명시 승인했다. 같은 범위의 의존성 설치·수정·로컬 실행·검증·게시에는 반복 승인을 요구하지 않는다. M3에서 준비한 동일 프로젝트의 선정 모델과 환경을 사용하며 실행마다 모델 바이트 해시를 다시 확인한다.

대상은 고정 revision의 Qwen3-TTS 0.6B CustomVoice이며 Korean / Sohee / batch 1, instruct 제외 조건이다. 실행별 고유 디렉터리에 새 입력·출력·출처를 기록하고 다른 프로젝트 산출물이나 이전 WAV·생성 캐시를 연결하지 않는다. 이 승인은 M5 두 모델 비교, 다른 모델 계열, 원격 GPU·외부 전송·공개 서비스 운영을 포함하지 않는다. 구현 승인과 완료 판정은 별개이며 최종 소스의 실제 WAV·UI 재생·취소·오류 검증을 보고한다.

## 이미 승인된 M5 범위

사용자는 같은 계열 두 TTS 모델을 동일한 새 한국어 입력으로 A/B 비교하는 구현·실제 검증·문서·비식별 저장소 반영을 명시 승인했다. 대상은 `Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice`와 `Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice`다. 같은 범위의 의존성 설치·읽기 전용 모델 다운로드·구성 보완·수정·로컬 실행·검증·게시에는 재승인을 요구하지 않는다. 현재 승인과 완료 판정은 별개이며 M5 완료는 이번 최종 구현의 두 모델 새 실행 및 UI·오류·취소 검증에 따른다.

첫 모델의 지정 자산을 사용할 수 있으나 M4 WAV·로그·측정값은 새 비교의 입력이나 성공 근거로 사용하지 않는다. 두 번째 모델은 지정 Drive 모델 가중치를 읽기 전용으로 다운로드하고 실제 바이트 해시를 확인한다. Drive 원본의 필수 `speech_tokenizer/config.json`이 비어 있는 경우 고정 공식 revision의 해당 구성요소만 별도로 보완하며 Drive 원본은 보존한다. 출처·해시·용도는 자산 manifest와 비공개 실행 기록에 구분한다.

비교마다 새 comparison_id와 두 run_id를 생성하고 동일 입력·seed·공통 생성 조건을 기록한다. Korean / Sohee / batch 1, instruct 제외, 최대 300자·600초·1,024개 신규 토큰, GPU 1개 작업씩 콜드 순차 실행을 적용한다. 한쪽 실패는 부분 완료이며 자동 승자를 정하지 않는다. 사용자 평가는 두 실행 모두 성공한 경우에만 저장한다. 작업공간 커스텀, M6 출시, 다른 모델 계열, 원격 GPU·외부 개인 자료 전송·Drive 쓰기는 이 승인에 포함하지 않는다.

## 2026-10-17 M5 후속 진단·자동검증 수정 승인

사용자는 같은 M5의 기존 다운로드 파일·브라우저 기록 읽기 전용 진단, 자동검증 timeout 수정·검증, 새 발견의 문서·비식별 저장소 반영을 승인했다. 최초 A 완료와 후속 A/B 차단을 별개로 기록하며 새 다운로드 E2E 성공으로 대체하지 않는다. 추가 다운로드, 보안 설정 변경, 파일명·다른 도구를 통한 저장 우회는 하지 않는다. 같은 범위의 수정·검증·게시에는 재승인을 요구하지 않는다.

## 2026-10-17 원인 로그 준비 후 제한 다운로드 재현 승인

사용자는 보안 설정을 유지한 상태로 원인 로그를 먼저 준비한 뒤 이번 진단에 한정해 제한된 다운로드 재현과 결과·해결 여부의 문서·저장소 반영을 명시 승인했다. 기존 추가 다운로드 금지는 이 지정 재현 범위에서만 대체하며 전체 해제나 자동 반복 재시도를 뜻하지 않는다. 실제 재현 전에는 성공·해결로 기록하지 않는다.

같은 M5의 기존 정상 비교 WAV는 이번 다운로드 재현의 지정 원본으로만 허용한다. 과거 WAV를 새 TTS 실행·새 품질 측정·새 GPU 성공 근거로 사용하지 않는다. 새 고유 진단 ID·원인 로그·출처 기록은 비공개에 보존하고 공개 문서에는 개인 계정·파일 경로·브라우저 프로필·DB 개인 식별값을 넣지 않는다.

정책·보안·확장·CDP 설정을 변경하지 않고 다른 저장 방식·파일명·도구를 통한 우회를 하지 않는다. 로그 준비와 승인된 단일 재현 계획을 먼저 확인하며 실패·차단·timeout·불명 결과는 그대로 기록하고 자동 재클릭이나 다른 side 진행으로 확대하지 않는다. 이번 승인은 원인 진단이며 M5 전체 PASS·M6 진행 승인이 아니다.

## 2026-10-17 진단 로그 보강과 별도 1회 재현 승인

앞선 단일 재현은 이미 완료했고 FILE_BLOCKED로 종료했다. 사용자는 이번에 서버의 명시적 opt-in 개인정보 최소화 진단 로그 구현·검증·필요한 로컬 재시작, 지원되는 브라우저 관찰 기능의 로그 준비, 준비 완료 뒤 보안 설정을 유지한 별도 다운로드 1회 재현, 결과·원인 해결 가능성의 문서·비식별 저장소 반영을 새로 승인했다. 앞선 1회 승인과 이번 1회를 섞거나 자동 반복 허용으로 해석하지 않는다.

대상은 같은 M5의 기존 정상 비교 A WAV이며 다운로드 진단 원본으로만 사용한다. 새 모델 추론·새 GPU 성공·새 품질 비교의 근거로 재사용하지 않는다. 새 고유 진단 ID·출처·로그는 비공개에 보존한다. 서버·네트워크 관찰 로그에는 쿠키·인증 토큰·비밀값을 수집하지 않으며 공개 저장소에 개인 로그·원시 브라우저 정보·경로를 게시하지 않는다.

브라우저 보안·정책·확장·CDP download behavior 설정을 변경하지 않는다. 관찰용 지원 기능만 사용하고 다른 저장 방식·파일명·도구를 통한 우회를 하지 않는다. 준비 후 지정한 단일 재현만 수행하며 실패·차단·timeout·불명 결과 후 자동 재시도하지 않는다. 실제 재현 전에는 성공·원인 해결을 기록하지 않는다. 진단 서버 코드가 바뀌므로 기존 GPU 검증·wheel 해시를 현재 진단 구현 전체의 검증으로 대체하지 않는다. M5 전체 PASS·M6 진행 승인이 아니다.

## 2026-10-17 명시적 Edge 전환의 한정 승인

사용자는 Edge로 전환해 진행할 것을 명시 승인했다. 정상 지원되는 Edge 연결로 같은 M5 기존 A WAV 원본의 정상 다운로드를 1회 진단하는 범위다. 이전 Chrome 관측과 분리하고 새 진단 ID·출처·로그를 비공개에 기록한다. 앞선 다른 브라우저/도구 저장 중단 규칙을 이 명시적인 Edge 1회 범위에서만 대체하며 일반적인 저장 우회·반복 허용이 아니다.

Chrome·Edge의 보안·정책·확장·CDP download behavior 설정을 변경하거나 우회하지 않는다. Edge의 관리 정책이나 위험 분류 상태를 확인 전에 없다고 단정하지 않으며 명시적인 deny·위험 경고가 나오면 중단한다. 앱 접근·health·관찰 로그 준비 후 지정한 정상 다운로드 1회만 수행하고 재클릭·다른 side·다른 저장 방식으로 확대하지 않는다. 기존 M5 A WAV는 다운로드 진단 원본일 뿐 새 TTS 실행 성공 근거가 아니다. 실제 실행 전에는 다운로드 성공·해결을 기록하지 않으며 실행 후에도 확인된 경로와 범위만 판정한다.

## 2026-10-17 Edge B 단일 다운로드와 M5 잔여 검증 정리 승인

사용자는 정상 지원 Edge 경로로 같은 M5 정상 비교 B WAV를 한 번 다운로드하고 무결성을 확인하며, 결과와 M5 잔여 검증 항목을 문서·저장소에 반영할 것을 명시 승인했다. 대상 B 원본은 157,484 bytes·SHA-256 `443376fc599adb0de1aed293ba8c764166fb517b62df91e62ab6b0b0ee3d4aa2`다. 기존 M5 출력은 이번 다운로드 진단 원본으로만 사용하고 새 TTS 추론·품질 측정으로 사용하지 않는다.

이번 범위는 B 1회이며 A 추가 다운로드·자동 재시도·다른 방식 저장·보안/정책/확장/CDP download behavior 변경을 하지 않는다. 명시적인 deny가 나오면 중단한다. 새 로그·실제 경로·브라우저 식별값은 비공개에 보존한다. B 결과 전 성공을 기록하지 않으며 Chrome 원인 해결이나 모든 환경 PASS를 이 승인에 포함하지 않는다. M6의 신규 환경 출시·복구 검증은 별도 범위다.

## 2026-10-17 M6 개인용 로컬 출시 승인

사용자는 원계획 M6 범위의 최신 배포 패키지·신규 환경 설치·인증 및 작업/DB 복구 검증·Edge 실제 사용 흐름·문서·비식별 저장소 반영을 명시 승인했다. 같은 범위의 로컬 의존성 설치·구현·수정·검증·게시에는 반복 승인을 요구하지 않는다. M6는 현재 시작 단계이며 새 실행·검증 증거 전 완료로 판정하지 않는다.

같은 Ai-manager 코드와 지정된 모델 자산을 사용할 수 있으나 M5 WAV·로그·테스트 결과·스크린샷·배포물을 이번 성공 근거로 대체하지 않는다. M6 고유 실행·검증 디렉터리와 새 출처 기록을 만들고 현재 코드·패키지·의존성·사용 모델 해시를 연결한다. 기존 자료·인증·개인 DB는 보존하고 복구 실험은 격리된 검증 자료 또는 보존한 동일 프로젝트 데이터의 명시 범위에서 수행한다. 공개 저장소에는 개인 계정·Drive ID·실제 경로·자격 증명·개인 로그를 올리지 않는다.

프로그램 형태의 배포 가능성 검토도 승인됐다. 이는 실행 패키지·launcher·desktop host 대안과 검증 범위의 검토이며 별도 네이티브 UI 전체 재구현을 자동 승인하지 않는다. 화면이 브라우저 기반인지 독립 창인지와 실행 파일/설치 패키지 형식을 구분해 설명한다. Edge를 선호하고 Chrome 원인 조사를 확대하지 않는다.

Google 로그인·OAuth 동의는 사용자 직접행위다. 필요한 실제 사용자 참여와 새로운 범위 승인을 구분한다. 작업공간 커스텀·Drive 쓰기·공개 서비스 배포·서명 구매·새 모델·원격 GPU·OS 전역 보안/브라우저 설정 변경은 포함하지 않는다. 필요한 새 범위가 실제로 생기면 대상·영향·보존 방법을 구체화해 알린다.

## 승인이 아닌 사용자 직접행위

Google 계정 로그인과 OAuth 동의는 사용자가 브라우저에서 직접 수행해야 한다. 이는 승인된 M1 인증 검증에 필요한 참여이며 새 범위 승인 요청이 아니다. 비밀번호·인증 코드·토큰을 채팅에 요구하지 않는다. 두 계정 각각의 동의, 실제 scope, 새 앱 조회·갱신 결과를 확인해야 실계정 E2E 완료로 판정한다.

## 이후 범위 승인

M5 새 비교는 아래 범위로 명시 승인됐다. M6 개인용 로컬 출시는 위 범위로 명시 승인됐다. 그 이후와 승인에 없는 확대는 해당 범위 승인 후 진행한다. 사용자는 명시적으로 후속 단계를 묶어 승인할 수 있으며 그 경우 승인된 범위 안에서 반복 확인하지 않는다. 단계 승인이 있어도 완료 판정은 새 구현과 실행 증거에 따른다.

아래 행위가 실제 다음 작업에 필요하고 기존 승인에 포함되지 않은 경우에는 대상·목적·영향을 구체화한 뒤 승인을 받는다. 발생 가능성만으로 미리 포괄 승인을 요구하지 않는다.

| 변경 | 확인할 범위 |
|---|---|
| 기존 자료 삭제·이동·덮어쓰기 | 실제 대상과 보존·복구 방법 |
| Drive 쓰기 | 실제 변경 파일·행위·권한 확대 |
| 공개 배포 또는 비용 발생 원격 GPU | 공개 범위·서비스·비용·종료 조건 |
| 새 계정·데이터 루트 접근 또는 외부 전송 | 실제 접근/전송 대상·목적·범위 |
| 실질적인 기능·데이터·실행 범위 확대 | 현재 승인과 달라지는 부분 |

허용된 공개 라이브러리 다운로드, 승인된 두 계정의 읽기 전용 API 호출, 비식별 코드·문서의 승인된 GitHub 반영을 새 외부 전송 승인 요청으로 중복 취급하지 않는다. 이전 산출물 재사용 예외는 특정 결과물과 사용 목적에 대한 별도 명시 허용이 필요하며 일반적인 진행 지시나 단계 승인은 금지 해제가 아니다.

## 현재 상태

M0 조사·설계·OAuth 파일 준비 후 M1에서 두 계정 실인증·강제 갱신·지정 범위 수집을 성공했다. 단계 완료 근거와 확인 한계는 [M1 보고서](M1_REPORT.md)에 기록한다. M2는 승인 범위의 구현·실제 목록·독립 검증을 완료했으며 결과는 [M2 보고서](M2_REPORT.md)에 기록한다. M3는 승인 범위의 구현·13개 실자산·환경·독립 검증을 완료했으며 [M3 보고서](M3_REPORT.md)에 이번 증거를 기록한다. M4는 승인 범위의 구현·실제 새 WAV·재생·저장·취소·독립 검증을 완료했다. [M4 보고서](M4_REPORT.md)에 이번 증거를 기록한다. M5는 원계획의 승인된 새 A/B 비교 기능과 정상 지원 Edge A/B 저장 무결성까지 확인한 로컬 환경 범위에서 검증 완료했다. Chrome 차단 원인·별도 시도 종결은 알려진 미확정 제한이며 선택 평가·M6와 구분한다. 모든 브라우저·입력·환경의 성공으로 확대하지 않는다. [M5 보고서](M5_REPORT.md)에 현재 증거와 미완료 항목을 구분한다. M6 개인용 로컬 출시는 명시 승인 범위의 확인한 Windows/Edge 출시 준비 gate를 검증했으며 공개 반영·태그/Release 식별이 최종 단계다. [M6 보고서](M6_REPORT.md)는 이번 새 증거와 미완료 gate를 기록한다. M6 이후 확대는 승인되지 않았다.

이번 Ai-manager 프로젝트의 이후 브라우저 작업은 사용자 요청에 따라 Edge를 선호한다. 이는 프로젝트 작업 선호이며 OS·브라우저 전역 기본 설정 변경이 아니다.

M6 fresh home에는 사용자가 이번 프로젝트에 지정한 OAuth client JSON·동일 allowlist 원본을 설정 입력으로 적용할 수 있다. 토큰·state·output·inventory를 기존 home에서 복사하지 않는다. 두 계정 fresh OAuth 로그인·동의는 사용자 직접행위다. 이번 구현 방향은 기존 Python이 필요한 user-scope 설치 스크립트·launcher와 v0.6.0 wheel이며 standalone exe·native host가 이미 구현됐다고 주장하지 않는다. 최종 gate 검증 전 v0.6.0 태그를 만들지 않는다.
