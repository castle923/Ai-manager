# 파일 후보의 작업별 검토 추천 계약

0.16.0 로컬 수정 후보다. 추천은 현재 작업실에 이미 수집된 Drive 파일 메타데이터의 검토 순서이며, 실측 성능·품질·실행 가능성 순위가 아니다. 새 수집, 파일 다운로드, 모델 실행, 등록 또는 승인을 일으키지 않는다.

## 목적과 순서

- 음성 생성, 음성 인식·전사, 이미지 생성(편집 미확인), 텍스트 대화, 영상의 지정 지점 추적 중 목적을 고른다. 미선택 전체 목록에는 임의 추천번호를 붙이지 않는다.
- 계정·검색·계열·수집 상태 등 현재 필터를 먼저 적용하고 전체 결과에서 안정 정렬·그룹 검토번호를 계산한 뒤 페이지를 나눈다. 동일 조건은 이름·계정 별칭·식별자 순이며 크기·파일 개수·파라미터 수는 품질 가산점이 아니다.
- 모델 그룹에서만 추천번호를 표시한다. 전체 파일 모드는 각 파일의 관련 근거를 표시하며 shard·config·README를 별개의 추천 모델로 승격하지 않는다. 사용자가 선택한 이름·크기·수정일 정렬도 유지한다.

## 번호의 의미와 보류

고정 프로필의 명확한 이름 후보 하나와 목적이 맞고, 해당 그룹에서 기대하는 최상위 주요 가중치 및 필요한 config의 이름·크기를 관찰했으며, 수집이 complete이고 관찰한 shard 누락·중복 이름이 없을 때 메타데이터 검토번호를 부여한다. 이 조건은 실제 모델 식별, revision, 전체 가중치·바이트 SHA, runtime·자원 준비 또는 추론 성공을 증명하지 않는다. 각 행과 상세에 근거와 미확인 한계를 함께 표시한다.

모호한 다중 프로필 이름, 미지원·판단 불가·목적 불일치, 부분 수집, 구성 파일만 있는 그룹은 번호를 부여하지 않는다. TAPIR의 공식 단일 checkpoint 형태에는 임의의 config 조건을 추가하지 않는다. 이미지의 분산 component는 표시 경로만으로 서로 다른 폴더를 합치지 않는다. 현재 inventory만으로 root 전체 가중치를 확인할 수 없는 이미지 관련 후보는 존재를 표시하되 순위 보류 사유를 명시한다. config 존재만으로 모델 식별을 확정하지 않는다.

## 화면·읽기 경계

목적을 바꾸면 이전 목적의 행·순위를 새 목적처럼 보여주지 않는다. 늦은 응답과 상세 응답은 요청 목적·세대가 맞을 때만 반영한다. 요청 실패 중에도 목적 선택지는 유지한다. 상세에 목록 필터 문맥의 번호가 없으면 조건 충족과 번호 미제공을 보류와 구별한다.

추천 GET은 기존 SQLite를 mode=ro와 query_only로 읽는다. 없는 DB 조회는 빈 결과이며 폴더·DB를 만들지 않는다. 명시한 미존재 scan은 별도 오류다. 기존 준비·등록·승인 동작은 유지한다. TTS 두 모델 준비 화면의 계정/프로필 제한은 범용 파일 후보 탐색과 구별한다. 로컬·외장하드의 자동 검수 원본 지정 경로는 별도 기능이며 이번 화면이 디스크를 자동 탐색한 것은 아니다.
