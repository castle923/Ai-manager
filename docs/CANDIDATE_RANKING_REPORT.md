# 파일 후보 추천 0.16.0 검증 보고서

현재 상태: 새 Windows 패키지·격리 설치·실제 독립 창에서 검증한 로컬 수정본. 기존 사용 앱·인증을 교체하거나 새 GitHub Release를 게시한 것은 아니다. 공개 v0.15.0 Release에는 이번 추천 기능이 포함되지 않는다.

## 변경과 원인 구분

파일 후보 탐색에 작업 목적 5종, 추천 우선 정렬, 그룹 검토번호, 선택 이유·기준·미확인 사항을 추가했다. 추천은 현재 작업실의 수집된 Drive 메타데이터를 읽는 검토 순서다. 실측 성능 수치나 모델 크기에 따른 품질 우열을 만들지 않는다. 필터 후 전역 정렬·번호 계산과 페이지 분할을 적용하고, 전체 조회 조건의 세대가 바뀌면 이전 행·순위·상세를 지운다. 늦은 응답이나 실패가 새 조건의 결과를 덮지 못하게 한다. 조회 실패·조회 중·실제 빈 결과를 구분하며 오류를 미수집으로 표시하거나 새 수집을 권유하지 않는다.

기존 dashboard API에 TTS만 수집·조회하는 필터는 없었다. TTS 두 모델 준비 화면의 제한과 범용 후보 탐색·등록 목록은 서로 다른 범위다. 계정·검색·계열 필터와 home별 수집/등록 상태도 표시 범위에 영향을 준다. 후보 파일 수는 모델 수가 아니며 이름·경로의 계열 추정은 확정 식별이 아니다. 상위 경로의 일반 TTS 단서가 더 가까운 Whisper 등의 구체적 단서를 덮는 분류를 수리했다. 개인 인벤토리 내용·수치·계정·식별자·실경로는 게시하지 않는다.

## 고정 패키지와 설치

- 빌드 source: `15c8e92aa3f2a7a99d64b52164538f02289fcda3`. 코드·정적 자산 SHA-256: `15979a3235289c068b0760c5e45a7cec01c5d3f7fdb3548db4ceae400bc26bfa`. 후속 보고서 commit은 제품 source와 다르다.
- 최종 ZIP: `AiManager-0.16.0-windows.zip`, **113,178,021 bytes**, SHA-256 `de0a83d2595b75cb7034d4e9e442b8ddbcc8b5ab8e6830cbd05f0e8e442bc044`.
- EXE SHA-256: `6098f3140800d28d8e665394d92ff036de593476d3031a32d1cc063555246c92`. 서명되지 않은 EXE다. Windows WebView2 Runtime은 별도 전제다.
- 8,311개 payload와 manifest의 ZIP CRC·전체 파일 SHA, 77개 동봉 source/static/lock의 고정 commit 원문, SOURCE-PROVENANCE와 실제 frozen 자체 검사를 대조했다. 독립 검토도 일치했다. 공개 라이선스 파일 28개와 두 CPython runtime의 LICENSE를 확인했다.
- 새 대상에 설치 엔진을 호출한 뒤 설치본 8,311개 전량 SHA·추가/누락 0과 설치 EXE 자체 검사를 확인했다. 설치 후 UI 검사 뒤에도 동일했다. 설치 엔진 호출은 격리 공개 Python을 사용했으며 설치 폴더 선택 GUI 완료로 주장하지 않는다. 설치 EXE 앱 호스트는 frozen이며 자식 실행 환경에서 PYTHONHOME/PYTHONPATH와 사용자 Python PATH를 제외하고 독립 창을 실행했다. 모델 runtime 준비 요건과 앱 호스트 Python 독립성은 별개다.

## 이번 검증과 수정 단계

1. 새 합성 메타데이터 직접/API 테스트 18개로 목적 5종, 전체·파일 모드의 번호 없음, 동점·전역 페이지·필터, 모호·미지원·부분 후보, TAPIR 단일 파일, 이미지 분산 구조 보류와 읽기 전용 DB 경계를 확인했다. 최종 문구·조회 세대 수리 뒤에도 owner 및 독립 실행에서 18개가 통과했다. TypeScript 검사와 Vite 빌드도 통과했다.
2. 초기 전체 회귀에서 빈 home의 읽기 전용 DB 미존재 처리 오류를 수리했다. 최종 동결 전체 회귀는 **400개: 393 PASS / 7 SKIP / 오류 0, 55.458초**다. SKIP은 tracking CPU 의존성 4개·decode 의존성 2개와 Windows 비특권 symlink 1개다. 별도의 PYTHONPATH 미설정 하네스 실패는 제품 실패와 구분해 보존했다. 이후 CSS·문구·조회 표시 상태만 바꾼 단계는 영향 범위 검증을 수행했으며 전체 400개를 다시 수행했다고 주장하지 않는다.
3. 첫 패키지의 합성 OAuth fixture 형식 오류와 후보표의 한글 한 글자 줄바꿈을 발견했다. 전자는 가짜 설정 입력만 수리했고, 후자는 후보표 전용 열 폭·가로 스크롤·번호 줄바꿈 금지로 수리했다. 실패 후보와 증거는 보존했다.
4. 두 번째 격리 설치본에서 5개 목적, 번호 없는 관련/보류 후보, 계정·검색 필터, 상세, 전체 파일 모드, 수동 정렬, 두 페이지와 오류 회복을 실제 창으로 확인했다. 정상 폭과 최소 폭 설정에서 정상 문장 줄바꿈·표 내부 좌우 스크롤·오른쪽 상세 접근을 확인했다. 최소 창 캡처는 767×872 pixels였다. 이 단계에서 수동 정렬과 충돌하는 파일 안내, TAPIR에 불필요한 구성 관찰을 암시하는 문구, 조회 오류를 미수집으로 보이게 하는 표시를 발견했다.
5. 최종 세 번째 설치본에서 해당 수리를 새로 검증했다. 정상 그룹 추천·이유/기준, 이름순 파일 목록의 정렬 중립 안내, TAPIR의 프로필별 필요한 파일 이름·크기 관찰 설명이 일치했다. 같은 음성 목적을 유지한 선택 수집 기록·검색 오류에서 이전 순위/행이 사라지고 통계·빈 화면은 조회 실패/현재 수집 상태 확인 불가로 표시됐다. 목적·계열 선택은 유지됐다. 합성 fixture 오류를 유지한 채 ‘목록 다시 조회’를 직접 한 번 클릭해 중립 실패가 유지됨을 확인했고, fixture 복원 뒤 정상 상태 polling으로 현재 추천이 회복됐다. 복원 직후 polling이 먼저 회복해 버튼이 사라진 최초 클릭 시도는 실행되지 않았다. **직접 재조회 클릭이 성공 회복을 유발했다는 인과는 미실증**이며 자동 회복과 구분한다. 오류는 실제 `400 invalid_request`였고 404로 기록하지 않는다.
6. 최종 화면은 이번 새 합성 검증 데이터다. 실제 사용자 모델 목록이나 추론 성공 화면이 아니다. 별도로 허용된 현재 수집 목록은 `mode=ro`·`query_only`로 목적별 집계만 읽어 DB SHA·파일 identity·행 수와 sidecar 부재가 전후 같음을 확인했다. 모델 파일·토큰·Drive를 새로 읽거나 기존 앱을 새 버전으로 실행하지 않았다.

## 보존과 전달 범위

선정한 기존 설정·DB·인증 파일 16개의 전후 파일 identity/크기/시각과 설정·DB SHA가 같았다. 인증 파일 내용은 읽지 않았다. 이는 선정 파일 범위의 대조이며 기존 home 전체 불변을 주장하지 않는다. 새 앱은 정상 닫기로 종료했고 해당 PID 부재를 확인했다. 모델 다운로드·복사·추론, Drive 새 수집/쓰기, 기존 home 이관과 기존 앱 교체는 수행하지 않았다.

새 작업 디렉터리·합성 입력·실행 로그·화면을 사용했다. 승인된 같은 프로젝트 코드·문서와 공개 고정 의존성만 사용했고 과거 생성 출력·성공 로그·스크린샷을 이번 성공으로 대체하지 않았다. 공식 PyPI에서 고정 host wheel 12개 **5,712,418 bytes**를 새로 수신해 SHA를 검증했다. 공개 wheel/npm 캐시와 고정 공식 CPython archive 두 개도 사용했다. 모든 네트워크 수신이 0이었다고 주장하지 않는다. 모델 runtime이나 전역 환경에는 설치하지 않았다.

0.16.0은 기본 home 이름을 기존 `desktop-0.15.0`으로 유지한다. 다른 home의 인증을 자동 복구·이관하는 기능은 아니다. 기존 작업실을 계속 쓰는 명령은 [설치·사용 안내](CANDIDATE_RANKING_INSTALL.md)에 있으며 정적 호환만 확인했다. 기존 작업실에 새 앱을 실제 실행해 쓰는 검증은 하지 않았다. 이전 자동 검수 계획은 변경된 코드 SHA 때문에 새 계획을 요구할 수 있다.

이미지의 분산 root 전체 가중치, 정확한 모델 identity/revision/전체 SHA, runtime·자원 충족, 실행 성공·품질은 추천 메타데이터만으로 확인되지 않는다. 관련 후보가 있어도 관찰이 부족하면 번호를 보류한다. 이번 변경은 로컬/외장하드 통합 탐색이나 지원 어댑터 확대가 아니다. 별도 PC·실계정 새 OAuth·모델 추론·전면 접근성 검증은 포함하지 않는다. 공개 Release와 기존 자료를 보존했고 새 0.16.0 Release/tag는 생성하지 않았다.
