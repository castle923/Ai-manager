# 모델 원본 무결성 확인과 제한 복구 계획

상태: 공개 검토용 초안. 원본 파일 및 원격 저장소의 변경은 실행하지 않았다.

## 이전 진단 해석 정정

전체 인벤토리에서 관측한 0바이트 항목의 합계와 특정 모델의 복구 대상 분모는 서로 다르다. 전체 합계를 한 모델의 손상 파일 수로 읽으면 안 된다. 복구 대상은 파일 이름만으로 결정하지 않고 계층상의 모델 소속, 부모 폴더, 원격 파일 식별자와 정확한 상대경로를 확인하여 정해야 한다. 다른 모델에 속하는 구성 파일은 동일한 이름이어도 서로 대체할 수 없으며 별도 원본이 확인될 때까지 보류한다.

## 확인된 원본 무결성 범위

로컬 모델 자산의 가중치와 필수 구성 파일을 이번 실행에서 직접 읽어 크기와 전체 바이트 해시를 계산했다. 공식 `hexgrad/Kokoro-82M`의 고정 revision `f3ff3571791e39611d31c381e3a41a3af07b4987` 메타데이터와 대조했다. LFS 파일은 포인터의 Git 해시와 내용 해시를 구분하여 내용 SHA256으로 검증했고, 일반 구성 파일은 공식 Git blob 해시와 대조했다. 새 SHA256과 읽기 전후 파일 상태도 기록했다. 구성 JSON은 대소문자를 보존하고 중복 동일 키를 거부하는 파서로 확인했다.

이 결과는 지정 모델 자산의 정적 무결성 확인이다. 전체 런타임 의존성, 모델 로딩, 추론, 음성 품질 또는 현재 앱의 실행 지원을 검증한 결과가 아니다. 과거 실행 성공, 생성 음성, 이전 테스트 로그로 이번 결과를 대체하지 않았다.

## 복구 대상과 실행 제한

현재 원격 메타데이터와 부모 폴더 목록을 다시 읽어 복구 후보를 로컬 공식 일치 원본과 상대경로별로 연결했다. 동일 이름·식별자·부모·중복 여부를 확인하고, 이미 양수인 주변 파일과 다른 모델의 구성 파일은 교체 대상에서 제외했다. 상세 매핑과 개인 경로는 비공개 기록에 보존한다.

현재 단계는 읽기 전용 조사와 계획 수립이다. 정상 연결 도구가 요청한 원격 checksum, content version 및 쓰기 가능 여부를 응답에 제공하지 않는 경우 해당 값은 미확인으로 남긴다. 크기가 양수이거나 로컬 크기와 같다는 이유만으로 원격 무결성 일치를 선언하지 않는다.

도구 문서에 동일 식별자의 raw bytes 교체 기능이 있더라도 실제 전송 경로의 지원성, 조건부 쓰기, revision 보존 및 복원 가능성이 확보됐다는 뜻은 아니다. 실행 직전의 재조회만으로 검사와 쓰기 사이의 동시 변경을 완전히 막을 수 없다. 필요한 충돌 방지와 보존·복원 경로가 확인되기 전에는 교체를 실행하지 않는다.

## 추가 승인이 필요한 범위

실제 복구 승인은 비공개 매핑에 고정된 해당 모델의 0바이트 가중치 항목에 한정하여 받아야 한다. 정상 원본의 외부 전송, 동일 원격 식별자의 내용 교체, 실행 직전 재검증, 파일별 결과 및 원격 무결성 확인 방법을 구체적으로 제시한다. 이름·폴더·공유상태 변경, 기존 파일 삭제나 이동, 다른 모델 복구, OAuth 권한 확대는 이 계획에 포함하지 않는다.

승인 후에도 원본 또는 대상의 식별자·이름·부모·크기·수정 시각 변화, 권한 거부, 충돌 또는 결과 불명이 발생하면 중단한다. 자동 반복이나 다른 저장 방식으로 확대하지 않는다. 파일별 진행 기록을 남기고 이미 확인된 항목을 무조건 다시 업로드하지 않는다. 원격 checksum이 제공되지 않아 정상 재다운로드가 필요하면 그 전송과 저장 범위를 별도로 명확히 해야 한다.

복구 후 인벤토리 재수집과 앱 DB 반영 여부도 승인 범위에 명시해야 한다. 원격 바이트 복구가 완료되더라도 해당 모델의 앱 실행 지원 추가나 실제 추론 성공으로 확대하지 않는다.

원본 모델 파일, 원격 파일, 인증과 보안 설정은 보존했다. 복사·다운로드·업로드·교체·삭제·이동·모델 실행은 이 조사에서 수행하지 않았다.

## 저장 공간을 줄이는 후속 설계 제안

추천 목록의 후보 3~5개와 실제 내려받아 보관하는 모델 수를 분리하는 방안을 검토한다. 후보 비교는 메타데이터만으로 제공하고, 필요한 시점에 1~2개 모델을 E 드라이브의 관리 저장소에서 준비하는 형태다. 실제 파일 크기, 실행 시 필요한 추가 공간과 여유 공간을 측정한 뒤 저장량 상한을 정해야 한다.

앱 버전별로 모델을 중복 복사하지 않는 관리 저장소와 무결성 확인, 사용 중인 모델을 보존하는 정책을 설계할 수 있다. 이는 이번 가독성 수정에 구현한 기능이 아니다. 자동 캐시 정리나 기존 모델 삭제·이동은 수행하지 않았으며 별도 사용자 승인과 보존 계획이 필요하다.

이번 E 드라이브 분리는 새 프로그램 빌드와 설치 검증 출력의 위치다. 기존 C 드라이브 작업실을 그대로 선택하면 현재 코드의 모델 준비 사본은 그 작업실 아래에 생성된다. E에 실행 파일을 두었다고 모델 캐시까지 E로 전환되는 것은 아니다. 모델 저장 위치의 독립 설정, 공용 자산 저장소, 중복 제거와 자동 퇴출 정책은 미구현이며, 이번 작업에서 기존 C 자료를 이동하거나 정리하지 않았다.
