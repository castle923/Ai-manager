# Windows 0.16.0 로컬 수정 후보 사용법

작업별 파일 후보 검토 추천을 추가한 로컬 후보다. GitHub Release 게시를 뜻하지 않는다. 실제 패키지·설치 검증 상태는 저장소의 [이번 보고서](CANDIDATE_RANKING_REPORT.md)를 확인한다.

1. 새 패키지를 새 폴더에 풀고 AiManager.exe를 실행한다. 앱 호스트 Python은 동봉하며 Windows WebView2 Runtime은 별도 전제다. 모델 runtime과 모델 자산을 포함하지 않는다.
2. 검증·새 작업실은 `AiManager.exe --home "새 작업실의 전체 경로"`처럼 home을 명시한다. 기존 설치 폴더를 덮어쓰지 않는다. 앱 내 설치는 새 AiManager-0.16.0 폴더를 만들며 기존 대상이면 거부한다.
3. 일반 실행의 기본 작업실은 이전 버전과 같은 `desktop-0.15.0`을 유지한다. 프로그램 버전이 바뀌었다는 이유만으로 새 기본 작업실을 만들지 않는다. 다른 home의 로그인·설정·수집 목록을 자동 이관하거나 최초 인증을 복원하는 기능은 아니다. 별도 home을 실행하면 별도 설정·인증 상태가 보일 수 있다. token·DB·output을 임의 복사하지 않는다.
4. 파일 후보 탐색에서 작업 목적을 고르고 추천 우선 정렬을 확인한다. 현재 home에 이미 수집된 파일 후보만 대상으로 하며 후보 파일 수는 모델 수가 아니다. 그룹의 검토번호와 이유·기준·미확인을 함께 읽는다. 전체 파일 모드에는 모델 추천번호를 붙이지 않는다.
5. 추천번호가 없으면 해당 행의 사유를 확인한다. 이미지 관련 후보가 있어도 root 전체 가중치 관찰이 부족하면 순위를 보류한다. 추천은 품질·성능·실행 성공 보장이 아니다. 계정·검색·계열 필터가 목적과 충돌해 빈 결과면 필터를 해제해 다시 확인한다.

TTS 두 모델 준비 화면은 범용 후보 탐색과 범위가 다르다. 현재 준비 가능한 지정 TTS/계정 제한을 표시하며 다른 작업의 관련 후보를 발견했다고 준비·실행 지원이 추가되는 것은 아니다. 로컬·외장하드 모델은 기존 자동 검수의 명시 원본 지정 경로를 사용한다. 이번 추천 화면에 로컬 디스크 통합 탐색을 추가하지 않았다.

Google 로그인·동의는 사용자 직접행위다. 기존 home을 바꾸거나 인증을 새로 요구하는 절차를 이번 검증에 포함하지 않는다. EXE 서명·별도 PC·모든 접근성·모델 추론 품질 검증은 이 로컬 UI 수정 후보의 보장 범위가 아니다.
