# Windows 0.16.1 로컬 수정 후보 사용법

고정 프로필의 게시자/모델 이름 형식과 모델별 보류 이유를 수정한 로컬 후보이며 새 GitHub Release 게시를 뜻하지 않는다. [이번 검증 상태](CANDIDATE_NAME_FIX.md)를 확인한다. 이 안내가 패키지에 포함된 시점과 후속 검증 완료 시점은 다를 수 있다.

1. 새 패키지를 새 폴더에 풀고 AiManager.exe를 실행한다. 앱 호스트 Python은 동봉하며 Windows WebView2 Runtime은 별도 전제다. 모델 runtime과 모델 자산은 포함하지 않는다.
2. 격리 검증은 `AiManager.exe --home "새 작업실의 전체 경로"`처럼 home을 명시한다. 기존 설치 폴더는 덮어쓰지 않는다. 앱 내 설치는 새 AiManager-0.16.1 폴더를 만들며 기존 대상이면 거부한다.
3. 기본 작업실 이름은 기존 `desktop-0.15.0`을 유지한다. 다른 home의 토큰·설정·인벤토리를 복구하거나 자동 이관하지 않는다. 현재 인증 상태를 보존하려면 사용하는 home을 먼저 확인한다. 임의로 토큰·DB·output을 복사하지 않는다.
4. 파일 후보 탐색에서 하고 싶은 작업을 선택하고 후보 그룹의 검토 추천·근거를 확인한다. 전체 파일 보기에는 모델 추천번호를 붙이지 않는다.
5. 상세에는 관찰 이름, 작업 관련 경로 이름 단서, 대응 이름 프로필/형식, 필수 파일별 관찰 부족과 미확인 경계를 표시한다. 미지 게시자나 임의 suffix를 제거해 추천하지 않는다. 관련 후보가 있다는 것은 실행 지원·정확 모델 식별 확인이 아니다.
6. 이미지 분산 가중치나 관찰 shard 누락 등은 이름이 인식돼도 별도로 보류한다. 새 모델 실행 또는 다운로드가 이름 인식 수리의 전제는 아니다.

기존 작업실을 명시해 실행할 때는 `AiManager.exe --home "현재 사용하는 작업실의 전체 경로"`를 사용한다. 이 문서에 실제 개인 경로는 포함하지 않는다. 현재 실행 중 앱을 교체하거나 종료하는 행위는 별도 사용자 흐름이며 이번 격리 검증의 성공으로 대체하지 않는다.

최종 ZIP의 정확한 이름·크기·SHA와 새 설치본 검증 결과는 패키지 게이트 완료 후 [이번 보고서](CANDIDATE_NAME_FIX.md)에 기록한다. 별도 PC, 새 OAuth, 모델 추론, 전체 접근성·모든 화면 폭 검증을 포함한다고 주장하지 않는다.
