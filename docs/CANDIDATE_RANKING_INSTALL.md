# Windows 0.16.4 로컬 후보 사용법

이 패키지는 글꼴 가독성 개선과 Drive 미연결 로컬 작업실 시작 경로를 포함하는 로컬 후보이며 새 GitHub Release 게시를 뜻하지 않는다. [구현과 검증 경계](TYPOGRAPHY_LOCAL_0164.md)를 확인한다.

1. 패키지를 새 폴더에 풀고 AiManager.exe를 실행한다. 앱 호스트 Python은 동봉하며 Windows WebView2 Runtime은 별도 전제다. 추론용 공개 의존성과 모델 자산은 별도 준비 대상이다.
2. 새 로컬 작업실은 `AiManager.exe --home "새 작업실의 전체 절대경로"`로 시작하고 처음 시작 화면에서 **Drive 없이 로컬 작업실 시작**을 선택한다. Google 로그인·OAuth client·가짜 계정이 필요하지 않다. 기존 settings가 있는 작업실을 덮어쓰거나 자동 전환하지 않는다.
3. Drive 연결 작업실은 처음 시작 화면의 지정 OAuth client·허용 목록 원본 경로를 사용한다. Google 로그인과 동의는 사용자가 직접 한다. 로컬 모드에서 기존 자격 증명 저장소를 확인하거나 원격 Drive 작업을 수행하지 않는다.
4. 로컬 모드에서 나중에 Drive를 쓰려면 별도 새 Drive 작업실을 설정한다. 로컬 등록 DB의 자동 이관과 로컬→Drive 설정 전환은 미구현이다. 토큰·DB·인벤토리·output을 임의로 복사하지 않는다.
5. 앱 내 설치는 선택한 상위 폴더 안의 새 AiManager-0.16.4 폴더에만 진행하며 기존 대상이면 거부한다. 기본 작업실 이름은 호환성을 위해 기존 `desktop-0.15.0`을 유지한다. 프로그램 폴더와 작업실의 위치는 다르다.
6. E 드라이브에서 EXE를 실행해도 기존 C 작업실의 모델 준비 사본이 자동으로 E로 옮겨지지 않는다. 저장 위치 이관·중복 제거·자동 캐시 정리는 이번 기능이 아니다.

파일 후보 추천은 이름·관찰 메타데이터에 근거한 검토 순서이며 실제 모델 식별·가중치 무결성·실행 지원 확인을 뜻하지 않는다. 로컬 등록과 새 모델 추론의 완료도 구분한다. 실제 계정·모델 추론·별도 PC·모든 폭과 접근성 검증을 수행했다고 주장하지 않는다.
