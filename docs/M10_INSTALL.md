# M10 Windows 후보 설치·사용 안내

> C6 후속 결과: 동일 새 조건의 TTS A/B 양쪽 생성·재생과 새 8개 기록의 정상 재시작 후 유지까지 확인했다. 상세 선택은 재선택 검증이며 자동 복원 판정이 아니다. 기존 22개 이력 전체 UI ID·모든 필터 검증은 하지 않았다. 최종 전체 완료나 이미지 로컬 성공으로 확대하지 않는다.

> 현재 candidate6 실제 사용 갱신: 이번 새 TTS 생성·running 취소·소유 자식 정리, 사용자 수동 native 저장/취소와 저장본 SHA 일치, 새 Whisper 전사 및 16프레임 합성 TAPIR 추적을 확인했다. Whisper는 원문 차이가 있어 정확도 PASS가 아니며, TAPIR는 실물 영상 검증이 아니다. LLM은 RAM/GPU/disk 공통 자원 gate에서 실패해 출력이 없었다. 새 TTS A/B 양쪽 cold 생성·native 재생 완료와 정상 종료·재시작 후 새 8개 기록 유지까지 확인했다. 기존 DB 행 fingerprint·환경 보존과 대표 STT JSON의 사용자 수동 native 저장·해시 일치도 확인했다. 추가 TAPIR PNG·A/B 저장 변형은 미검증으로 남긴다. 아래 남은 검증/초기 상태와 최신 항목별 결과를 [M10 보고서](M10_REPORT.md)에서 구분한다.


### candidate4·5의 시작 실패와 candidate6 수정

candidate4는 새 대상 설치 8,291개 파일 무결성을 통과했으나 앱 창 시작에 실패했다. 진단만 보강한 candidate5에서도 시작 실패를 보존했다. candidate5의 opt-in trace는 `home → SettingsStore → protect_directory → icacls`의 30초 timeout 호출 위치를 확인했다. WebView 초기화 전 단계이며, 채워진 디렉터리에 상속 ACL을 다시 적용하면서 자식으로 전파된 것이 정확한 지연 원인인지는 별도로 측정하지 않았으므로 가설로 남긴다.

candidate6은 Win32 API로 기존 root 디렉터리의 실제 owner·protected DACL·현재 사용자/SYSTEM의 정확한 두 full-control 규칙을 검사하고 일치할 때 재적용을 생략한다. 불명확한 ACL의 populated 디렉터리는 변경하지 않고 실패하며, 새 empty 디렉터리에만 기존 보호 절차를 적용하고 다시 검증한다. root의 계약 확인은 모든 자식 ACL을 전수 인증하는 것이 아니다. 전역 보안 설정을 변경하거나 보호 검사를 끄지 않는다.

명시적 opt-in 시작 진단은 단계·제한된 예외 종류·허용 module/line만 기록한다. 예외 원문·locals·실제 경로·계정·비밀값은 수집하지 않으며 16KiB·32 events로 제한한다. 진단 쓰기 실패가 원래 오류를 바꾸거나 시작 흐름을 가로막지 않도록 한다. 시작 진단과 worker의 별도 이미지 진단을 구분한다.

candidate6 소스 동결·native build·바이트 정합은 확인했고 전체 자동 회귀 280개 중 274개 통과·6개 skip, 관련 독립 CPU 13개 통과를 확인했다. candidate6는 새 설치본 8,292개 파일 검증과 실행 파일 SHA 일치, 같은 작업 영역의 실제 앱 창 진입을 확인했다. 현재 후보의 명시한 새 TTS·Whisper·합성 TAPIR 실행, TTS 취소·저장, 새 A/B·재생, 기록·정상 재시작 및 보존 검증을 확인했다. LLM은 자원 gate 실패·이미지 로컬은 미준비 상태이며 전체 모델 PASS는 아니다. 기존 22개 기록 조회는 보존된 과거 이력이며 새 실행 성공으로 계산하지 않는다. candidate4 설치 성공이나 이전 버전 모델 출력을 candidate6 실제 실행 성공으로 사용하지 않는다.


## 0.10.0 candidate6 통합 수정과 소스 재현

2026-10-18 현재 공개 Release는 **v0.7.0**이며 아래 내용은 **로컬 0.10.0 candidate6**의 소스·검증 후보에 관한 안내다. 새 Release·태그·설치 자산 공개를 뜻하지 않는다. candidate6의 native payload 8,292개 파일과 source 61개는 manifest에 정합하고 새 설치본 실제 앱 창 진입을 확인했다. 이번 문서에 명시한 실행·취소·저장·기록·재시작 표본을 확인했으며 LLM 자원 gate·이미지 로컬 미준비와 미검증 저장 변형을 남긴다. 설치 성공을 앱 실행 성공으로 확대하지 않는다.

이번 수정은 이미지 런타임의 실제 패키지 검사와 앱 검사 사이에서 빠져 있던 `torchvision` 계약을 맞춘다. TTS·STT·TAPIR·Llama의 기존 라이브러리 환경을 새로 설치하지 않고, 정확한 lock·환경 소유 기록·기반 Python/라이브러리 해시·격리 metadata probe가 일치할 때만 원래 위치를 참조한다. 이전 ready 표시만으로 통과시키지 않는다. 불일치하면 새 역할별 미준비 환경으로 남긴다.

기존 환경을 참조하는 경우 **원래 candidate3 Python 기반과 기존 환경 폴더를 삭제·이동·이름 변경하지 않는다.** 기존 base를 지우면 해당 venv가 동작하지 않을 수 있다. venv의 `pyvenv.cfg`를 수정하거나 라이브러리·인증·DB·출력을 새 환경에 복사하지 않는다. 새 작업은 현재 candidate6 worker와 출처 해시를 사용한다. TTS 의존성 lock·버전을 변경하거나 기존 네 런타임을 재설치하는 작업이 아니다.

등록 모델의 자원 안내는 실행 가능성에 관한 참고 정보이며, 실제 구성·격리 환경·worker의 자원 검사는 계속 실행을 막는 조건이다. 이미지 로컬 환경은 준비 미완료이고 현재 Windows PC에서 이미지 로딩·생성 성공을 검증하지 않았다. 별도의 [RunPod 기록](M10_RUNPOD_REPORT.md)은 Linux 원격 GPU의 실행 기록이며 이 Windows 앱의 원격 연동이나 로컬 8GB 성공을 뜻하지 않는다.

### 소스에서 새 UI·wheel·native 후보 만들기

공개 소스에는 모델·라이브러리 환경·인증·DB·출력과 생성 static을 포함하지 않는다. Node.js 및 Python 빌드 도구를 사용하는 개발 재현과, 만들어진 독립 앱을 사용하는 경우를 구분한다. 공통 순서는 다음과 같다.

1. 저장소 소스를 새 전용 폴더에 준비하고 고정 lock과 필수 소스가 모두 있는지 확인한다. `frontend/package-lock.json`으로 npm 의존성을 고정한다.
2. `frontend`에서 `npm.cmd ci --ignore-scripts`, 이어 `npm.cmd run build`를 실행한다. TypeScript 검사와 Vite가 `src/ai_manager/static`을 새로 생성한다. 이전 설치본의 static을 가져오지 않는다.
3. 새 빌드 환경에서 `requirements.lock`과 `requirements-desktop.lock`의 도구를 준비한다. UI 빌드 뒤에 Python wheel을 만들며 `pyproject.toml`이 static·model/adapter manifest·어댑터 lock·TAPIR license/provenance를 package-data로 포함한다. 예: `python -m pip wheel --no-deps --wheel-dir <새 wheel 출력 폴더> .`.
4. native 후보는 같은 소스에서 `python scripts/build_desktop_bundle.py --output <존재하지 않는 새 절대 출력 폴더>`로 만든다. 빌더는 고정 공식 CPython 3.10과 이미지 전용 3.11 archive를 내려받아 크기·SHA를 확인한다. 명시한 허용 공개 archive cache를 사용할 때도 같은 해시를 재검사한다. 사용자 전역 Python·보안 설정을 변경하지 않는다.
5. 빌더가 복사하는 `docs/M10_INSTALL.md`도 필수 소스다. 빌드 결과의 `DESKTOP-MANIFEST.json`·소스 해시·패키지 해시와 새 설치본을 연결해 검증한다. 최종 앱 실제 사용 gate를 별도로 통과해야 한다.

candidate6 동결 snapshot에서 TypeScript/Vite와 native build는 통과했다. native manifest의 소스 61개가 snapshot 해시와 모두 일치한다. 이 **native 소스 61개**와 Git 변경 목록의 **게시 delta 62개**는 서로 다른 집합이다. 전자는 native에 들어간 기존·신규 source/static의 집합이고, 후자는 기존 공개 main에 대해 바뀌거나 새로 추가되는 제품·테스트 파일의 집합이다. 공개 소스만 받은 깨끗한 별도 환경의 전체 재빌드는 아직 검증하지 않았다.

내부 `image_hq_worker.py`는 동일 후보 소스 재현을 위해 포함하는 별도 실험 worker이며 앱 어댑터에 연결되지 않는다. 작업실 UI에서 2K 고품질 실행을 지원한다고 해석하지 않는다. 앱의 이미지 계약은 계속 512×512·4 steps의 제한 실험이다.

아래 초기 개발 환경·자원 수치는 각 시점의 역사 기록이다. candidate6 설치본의 현재 자원이나 실제 실행 결과로 대신 사용하지 않는다.


## 초기 작성 시점의 계획·상태 기록

기준일: 2026-10-18 · 후보 0.10.0 · **최종 Windows 설치·전체 실제 사용 검증 진행 중**

이 문서는 M10 현재 소스의 설치·사용 계약을 설명한다. 과거 버전의 설치 성공이나 초기 개발 환경 실행을 현재 후보의 검증으로 대체하지 않는다. 최신 확인 범위와 미완료 항목은 [M10 진행 보고서](M10_REPORT.md), 최종 완료 기준은 [M10 계획](M10_PLAN.md)을 따른다.

**공개 다운로드는 v0.7.0이며 0.10.0 Release는 아직 게시하지 않았다.** [기존 v0.7.0 Release](https://github.com/castle923/Ai-manager/releases/tag/v0.7.0)는 M10 다종 실행을 포함한 배포물이 아니다. 이 안내에 적힌 후보 기능과 공개 ZIP의 기능을 구분한다. 후보 ZIP의 최종 크기·SHA-256·소스 커밋·검증 설치본은 패키지 동결 후 확정하며 임의의 과거 수치를 기입하지 않는다.

## 시작 전 준비

- Windows 독립 앱은 어댑터별 Python 기반을 동봉한다. TTS·Whisper·TAPIR·Llama에는 CPython 3.10.22를 유지하고, 고정 이미지 의존성의 Python 3.11 이상 요구에 맞춰 이미지 전용 Astral CPython 3.11.17+20261009 기반을 별도로 격리한다. 앱 UI는 독립 창에서 열리며 사용자 전역 Python을 별도 설치하는 방식이 아니다. 최종 후보에서 두 기반의 분리 실행을 실제로 검증하는 절차는 아직 진행 중이다.
- Microsoft Edge WebView2 Runtime이 시스템에 필요하다. 없거나 초기화에 실패하면 안내된 원인을 확인하고 정상 지원 설치 경로를 사용한다. 브라우저·보안·정책·확장 설정을 변경하거나 다른 렌더러로 우회하지 않는다.
- 첫 추론 환경 준비에는 인터넷·디스크 공간과 공식 공개 런타임 의존성 다운로드가 필요하다. 모델별 격리 환경을 번들 Python 기반으로 따로 준비하며 기존 TTS 환경을 보존한다. 다운로드나 import 점검 성공은 모델 실행 성공과 다르다.
- 모델 가중치·개인 인증·인벤토리·출력은 앱 패키지에 포함하지 않는다. 사용자 지정 모델과 고정 공식 manifest에 맞는 필수 config/tokenizer/가중치를 별도로 준비해야 한다. 네 모델 전체를 임의로 자동 수집하는 설치 프로그램이 아니다.
- 모델마다 라이선스와 메모리 조건이 다르다. 특히 Qwen Image 2.1은 연구용 라이선스의 연구·평가·개인 실험 범위이며, 현재 확인 환경에서는 메모리 gate가 막혀 실제 생성을 검증하지 못했다. 일반 offload 기능이 있다는 이유로 실행 가능하다고 가정하지 않는다.

## 후보 패키지 열기

1. 이번 검증에 제공된 `AiManager-0.10.0-windows.zip`의 버전·크기·SHA-256을 확정된 비식별 패키지 기록과 대조한다. 기록이 아직 확정되지 않았다면 최종 배포 검증 완료로 취급하지 않는다.
2. 기존 설치·개인 DB·인증·모델·출력을 덮어쓰지 않는 새 폴더에 ZIP 전체를 푼다. 실행 파일만 따로 옮기지 않는다. 경로 길이 오류가 생기면 새 짧은 전용 경로를 사용하며 실패한 기존 환경을 삭제하지 않는다.
3. 압축을 푼 `AiManager` 폴더의 `AiManager.exe`를 실행한다. 선택 설치를 사용할 경우 새 대상 폴더는 `AiManager-0.10.0`으로 구분한다. 앱 창과 준비 상태·오류를 확인한다. 시스템 Python으로 개발 소스를 실행한 결과는 이 설치본의 성공 근거가 아니다.
4. 이번 실행용 전용 작업 영역을 사용하고 기존 실행의 토큰·state·인벤토리·출력을 자동 복사하지 않는다. Google Drive 기능을 연결할 때는 이번 프로젝트의 지정 OAuth client·allowlist만 사용하며 Google 로그인·OAuth 동의는 사용자가 직접 수행한다. 시스템 브라우저의 인증 화면과 앱의 독립 UI 창은 서로 다른 역할이다.

## 모델 등록과 별도 환경 준비

**모델 관리**에서 지원 모델을 등록하고 해당 고정 어댑터와 모델의 로컬 보관 위치를 지정한다. 임의 폴더나 Drive 목록의 이름만으로 실행할 수 있는 것은 아니다. [M10 보고서의 공식 모델·revision 표](M10_REPORT.md)에 맞는 구성 파일과 내용 해시를 확인해야 한다. 등록 시와 실행 직전에 구성·무결성을 검사하며 누락·변경·손상된 자산은 실행을 막는다. 개인 경로는 로컬 설정에만 기록하고 공개 이슈·문서에 붙이지 않는다.

**격리 실행 환경**에서 Whisper·BootsTAPIR v2·Llama·Qwen Image 중 준비할 유형을 선택하고 **선택한 격리 환경 준비**를 누른다. 설치 중에는 완료를 기다리고 실패하면 비공개 진단과 화면의 사유를 확인한다. 설치·CUDA 점검 완료 표시도 실제 출력 생성이나 현재 모델 구성 충족을 의미하지 않는다. 모델 다운로드·해시 확인·환경 준비·실행 결과를 각각 확인한다.

이미지 전용 공식 고정 의존성은 Python 3.10 기반에서 요구 버전 불일치로 정상 거절된 기록을 보존한다. 이를 보안 설정 변경으로 우회하지 않고 별도 Python 기반을 준비했다. 이미지 Python 공개 archive는 48,233,938 bytes·SHA-256 `4d307648d2fe5f8d927e10380cc33eb7afd8a34a7efe0ed786b5860b5f2d3408` 전량 검증을 마쳤다. 초기 별도 환경에서 Python 3.11.17·Torch 2.9.1+cu128·Transformers 5.17.0의 고정 의존성 설치·pip check와 `QwenImage21Pipeline` import-only 점검을 완료했다. PATH를 Windows System32만으로 제한한 import, pipeline 소스 SHA-256·실제 호출 signature·전이 패키지 버전 기록도 확인했다. 이는 최종 앱 설치본의 준비 완료나 모델 로딩 성공을 뜻하지 않는다.

실제 모델 가중치 33,131,601,593 bytes의 다운로드와 이미지 생성은 아직 0이다. 이번 점검 시 RAM 여유 12,148,547,584 bytes(약 12.15 GB)는 요구 18 GiB(19,327,352,832 bytes)보다 작았고 GPU 여유 7,459,569,664 bytes도 요구 7 GiB(7,516,192,768 bytes)보다 작아 두 자원 gate를 충족하지 못했다. GB와 GiB를 같은 단위로 취급하거나 환경 import 성공을 모델 실행 성공으로 해석하지 않는다.

**유형별 작업실** 탭의 **모델 작업 실행**에서 등록 모델을 선택한다. 유형별 지원 상태·모델 구성·별도 추론 환경을 먼저 확인한다. 현재 구현 계약은 다음과 같으며 최종 후보의 모든 경로가 검증 완료됐다는 뜻은 아니다.

| 유형 | 이번 실행 입력 | 현재 제한과 출력 |
|---|---|---|
| Whisper STT | 이번에 지정한 원본 또는 새로 만든 WAV | 16 kHz·mono·PCM 16-bit, 30초 이하·960,128 bytes 이하. 앱이 파일을 자동 변환하지 않는다. 결과는 전사 JSON/TXT |
| Llama 3.1 8B Instruct | 새 텍스트 | UI 최대 2,000자, 서버 UTF-8 최대 8 KB·템플릿 포함 최대 256 token, greedy 신규 최대 64 token. 결과는 응답 JSON/TXT |
| BootsTAPIR v2 | 이번 새 MP4와 첫 프레임의 추적점 JSON | 최대 5 MB·32프레임·20초, 정규화 x/y 0–1의 점 1–8개. 추적 입력은 256×256으로 변환. 결과는 tracks JSON·표시 PNG |
| Qwen Image 2.1 | 새 이미지 프롬프트 | 제한 실험 512×512·4 steps·seed 0·CFG 4, 결과 PNG·메타데이터 JSON. 현재 메모리 gate 미충족으로 실제 생성 미검증 |

과거 WAV·텍스트 응답·이미지·영상·로그를 새 실행의 입력이나 성공 근거로 자동 가져오지 않는다. 이번에 새로 만든 중간 결과는 같은 실행의 출처·해시 기록을 연결한 경우에만 다음 단계로 전달한다. Llama 구성 보완 인증·부분 다운로드는 아직 모델 준비나 새 응답 생성 성공과 다르다.

## 결과 확인·취소·저장

작업을 시작하면 새 실행 ID와 상태를 확인한다. 같은 작업 영역의 TTS와 다종 worker는 공용 실행 슬롯을 사용하므로 대기 상태가 생길 수 있다. 다른 작업 영역 전체를 통제하는 전역 GPU 잠금은 아니다. 실패·timeout·취소·자원 부족을 완료로 해석하지 않는다. 대기 또는 실행 중 취소를 요청하고 종료 상태를 확인한다. 취소 동작과 worker 정리는 최종 설치본의 실제 검증 항목으로 남아 있다.

완료된 실행의 전사·응답·이미지·추적 결과를 해당 유형의 결과 화면에서 확인한다. 저장은 독립 앱의 정상 native 저장 대화상자를 사용한다. 허용된 파일 형식과 새 대상 경로를 선택하며 기존 파일을 덮어쓰지 않는다. 대화상자를 취소한 경우 저장 완료가 아니다. 정상 저장 뒤 원본과 저장본의 크기·SHA-256을 대조하는 것이 무결성 검증이며, 결과 표시만으로 저장 성공을 판정하지 않는다.

다른 이름·도구·저장 방식으로 차단을 우회하지 않는다. 원본 결과·개인 로그·입력 본문·계정 주소·Drive ID·토큰을 공개 저장소에 올리지 않는다. 공개 문제 보고에는 비식별 오류 코드와 재현 조건만 사용한다.

## 현재 검증 범위와 보존

현재 초기 개발 소스에서 새 Whisper 전사와 단순 합성 영상의 TAPIR GPU 추적, 짧은 Llama 응답 생성을 확인했으며, 이는 동결한 0.10.0 설치본의 독립 창·정상 저장·오류/취소·재시작 완료를 뜻하지 않는다. Llama 모델 자산의 전체 통합 검증은 완료했지만 실제 응답 확인은 짧은 초기 표본이며, 선행 자원 감시 실패의 원인은 아직 미확정이다. 이미지는 초기 별도 환경의 의존성/import 점검을 마쳤지만 자원 gate·모델 다운로드·실제 생성이 남아 있다. 설치·runtime 준비·네 유형 E2E·새 TTS A/B 회귀·재시작·저장 검증과 독립 검토가 끝나기 전 M10 전체 PASS를 선언하지 않는다.

후보 설치·진단은 기존 설치본·home·모델 원본·인증·DB·출력·실패 환경을 보존하며 진행한다. 이 안내는 기존 자료 삭제·이동·정리 권한이 아니다. 새 모델·원격 GPU·Drive 쓰기·공개 서비스·보안 설정 변경으로 범위를 자동 확대하지 않는다.
