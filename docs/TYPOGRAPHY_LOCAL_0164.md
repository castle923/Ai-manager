# Drive 미연결 로컬 작업실과 글꼴 개선 (0.16.4)

상태: 로컬 구현·전체 회귀·새 portable 패키지 무결성·frozen 자체 검사와 사용자가 직접 연 새 로컬 창의 1266px 표본 확인 완료. 좁은 창·확대·재시작·0.16.4 새 설치 실행과 공개 배포는 미검증이다.

## 정상 로컬 시작 경로

새 작업실의 처음 시작 화면에서 **Drive 없이 로컬 작업실 시작**을 선택할 수 있다. Google OAuth 원본·가짜 계정·허용 폴더를 만들지 않고 version 2의 명시적 로컬 설정을 새로 저장한다. CLI는 `ai-manager --home <새 절대경로> init-local`을 지원하며 명시 home이 필요하다. 기존 settings가 있으면 덮어쓰지 않는다.

로컬 모드에서는 OAuth client를 읽거나 자격 증명 저장소를 생성·조회하지 않는다. 계정 정보는 빈 목록이고 Drive 상태는 `not_configured`다. 이를 자격 증명이 없다고 검사한 결과로 표시하지 않는다. 로컬 모델 등록·검증과 저장된 이력·보기 설정을 사용할 수 있다. 로컬 폴더 모델 준비에도 OAuth 생성자 의존성을 제거했으며 기존 경로·해시·무결성 검증은 유지한다.

Drive 로그인·갱신·수집·연결 해제·원격 모델 준비는 HTTP와 CLI에서 작업·이력 시작 전에 거부한다. Drive 검수 provider와 예전 Drive 계획의 승인·시작·복구·재개도 거부하며 원격 토큰 revoke나 삭제를 하지 않는다. Host/Origin/CSRF, 기존 Drive A/B·허용 폴더·OAuth endpoint 검증을 완화하지 않았다. 손상된 기존 Drive 설정을 자동으로 로컬 설정으로 전환하지 않는다.

로컬 모드는 Google Drive를 연결하지 않는 모드다. 네트워크 전체를 차단하는 기능은 아니며 공개 런타임 의존성 설치는 별도 명시적 온라인 작업이다. 나중에 Drive를 연결하려면 지정 OAuth 원본과 허용 폴더를 선택한 별도 새 작업실을 만들어야 한다. 로컬 등록 DB를 새 Drive 작업실로 자동 이관하거나 기존 로컬 설정을 Drive 설정으로 전환하는 기능은 이번에 구현하지 않았다.

## 글꼴 체계

본문 기본 크기 15px·줄 높이 1.65, 페이지 제목 30px(좁은 화면 28px)·700, 구역 제목 20px·700, 하위 제목 기본 16px·700으로 정리했다. 기존 8~11px 보조 문구를 최소 12px로 조정하고 조작 요소와 표의 크기·명도를 보강했다. 본문은 400을 유지한다. 작은 화면의 아이콘 전용 탐색 규칙은 보존했다.

외부 폰트와 CDN은 추가하지 않았다. 설치된 Segoe UI와 Malgun Gothic을 우선 사용하고 실제 설치 폰트의 Regular 400·Bold 700 face를 확인했다. 기존 750에서 700으로 명시한 제목이 실제로 더 두꺼워졌다고 주장하지 않는다. 실제 glyph fallback·두께 체감·잘림·겹침은 네이티브 화면에서 별도로 확인해야 한다.

지정 보조 색 #52627a의 계산 대비는 흰색에서 6.20:1, 화면 배경에서 5.83:1다. 안내·사이드바·기본 placeholder의 지정 조합은 각각 5.82:1·8.36:1·4.70:1이다. 모든 기존 상태와 색 조합의 접근성 인증은 아니다.

## 앞선 실행과 실행 정책 거절의 구분

미공개 중간 0.16.3 source preview는 runtime resources가 준비되지 않아 시작하지 못했다. 이후 새 frozen 패키지는 runtime 구성을 통과했지만 초기 합성 client의 형식이 유효하지 않아 앱 시작을 거부했다. 두 결과는 이번 새 입력과 실행에 한정한다.

그 뒤 합성 client 보완과 GUI 재시작을 포함한 실행 도구 요청이 `blocked by policy`로 거부됐다. 구체적인 내부 계층과 사유는 제공되지 않아 미확인이다. 이를 특정 자동 검토 설정의 결과로 단정하지 않는다. 해당 요청은 실행되지 않았고 같은 효과를 내는 다른 도구·파일·실제 자격 증명 원본으로 대체하지 않았다.

0.16.4의 명시적 로컬 모드는 Google 설정이 없는 사용자에게 정상 로컬 관리 경로를 제공하는 제품 개선이다. 실행 정책 거절을 해제하거나 회피하는 기능이 아니다. 수정 후 자동 GUI 재실행을 하지 않았다. 이후 사용자가 정상 시작을 직접 수행한 창을 지원 UI 도구로 관찰했으며 아래 실제 확인 범위를 따른다.

## 검증과 보존 경계

기존 0.16.3은 TypeScript/Vite 및 39개 회귀 테스트, 새 패키지와 8,311개 파일 설치·frozen 자체 검사를 확인했다. 이것을 후속 0.16.4 전체의 성공 근거로 대체하지 않는다. 0.16.4의 새 빌드·전체 회귀·패키지·설치 결과는 이번 실행 증거로 따로 기록한다.

이번 1266×893 창에서 제목·KPI·구역 제목의 위계와 본문·검색·버튼을 관찰했다. 보이는 표본 영역의 겹침·잘림은 발견하지 못했다. 한글 glyph의 실제 선택 측정, 이전 버전 대비 두께 우열, 데이터가 채워진 표, 좁은 창과 확대 시각 검증은 미완료다. 네이티브 창의 지원 최소 너비는 768px이며 390px 휴대폰 화면을 검증한 결과는 아니다. 실제 계정 로그인·새 모델 다운로드·실제 모델 추론을 수행한 검증도 아니다.

기존 사용자 home·토큰·모델·DB·생성 결과를 새 작업실로 복사하지 않고 보존한다. 프로그램 빌드·설치 출력의 E 드라이브 분리는 기존 C 작업실의 모델 캐시 위치를 변경하지 않는다. 새 릴리스·태그·기존 설치 덮어쓰기·자료 정리는 별도 결과로 구분한다.

0.16.4의 TypeScript/Vite 빌드는 통과했고 전체 회귀는 415개 중 408 PASS·7 SKIP로 종료했다. 이후 원래 줄바꿈 형식을 보존하고 native setup guard의 새 headless 반례를 추가한 뒤 관련 17개 테스트도 통과했다. 독립 HTTP 반례는 Drive action·검수·Host/Origin/CSRF·로컬 조회를 포함한 21개 조건에서 원격 접근·토큰 저장소·작업 이력 생성 없이 예상 응답을 확인했다. 이 자동 테스트들은 실제 GUI 실행의 증거가 아니다. 아래 별도 사용자 직접 시작의 화면 표본을 구분한다.

## 0.16.4 새 패키지 결과

패키지 제품 소스는 c342dfd9d5b3810e9d265c110d568ffaaec2c212에 고정했다. ZIP은 113,190,388 bytes·SHA256 503a352a2a53485602ad3f16aa24f6a19c93a994f7e045d9b4e92275767b66d4이며 EXE SHA256은 44b7b40e01c13210880152eb115b6dd21d1bc5806cd385774243df16e4f3ebaa다. 새 frozen 자체 검사는 version 0.16.4·같은 소스 commit·code SHA256 d6741c88cfd94c8281975eb98a59ec91ee056b70e5c184b8cb52fdad527021a6을 검증했다.

독립 검토에서 manifest 8,313개 파일과 ZIP member의 전량 SHA256·CRC·중복/누락/추가 경로를 확인했고 78개 source의 출처에 새 local_mode.py가 포함됨을 확인했다. 라이선스와 텍스트 개인정보 패턴 검사도 수행했다. 이 검사는 코드서명 또는 모든 비밀값 탐지의 보증이 아니다.

0.16.4에서는 portable build를 직접 검증했다. installer 구현은 이전 중간 버전과 버전 식별 문자열 두 곳만 다르며 관련 단위 회귀를 통과했으나 0.16.4의 새 설치 복사를 다시 실행하지 않았다. 이전 0.16.3 설치 성공을 0.16.4 설치 성공으로 대체하지 않는다. 후속 문서 commit은 고정된 패키지 제품 소스를 변경하지 않는다.

## 사용자가 직접 시작한 로컬 화면 표본

사용자가 고정된 0.16.4 portable EXE와 이번 새 E 작업실을 명시해 창을 열었다. 지원 UI에서 **Drive 없이 로컬 작업실 시작**을 선택하여 정상 대시보드로 전환했다. 저장된 설정은 version 2·mode local·빈 accounts/allowlist/sources였고 credentials 디렉터리는 생성되지 않았다. WebView 초기화와 탐색 guard가 준비됐음을 새 상태 기록으로 확인했다. Google 로그인·런타임 다운로드·모델 준비·추론은 수행하지 않았다.

이번 1266×893 네이티브 캡처와 접근성 트리에서 모델 관리 제목, KPI, 검색 아이콘과 placeholder, 필터·버튼, Drive 미설정 설명과 비활성 안내를 확인했다. 독립 검토에서 보이는 영역의 글자 겹침·잘림은 발견하지 못했다. 빈 등록 목록 표본이며 실제 모델 목록 전체나 모든 화면 상태의 통과를 의미하지 않는다. 로컬 모드의 계정 화면 상단에 기존 두 계정 연결 설명이 남아 있는 문구 혼동 가능성도 후속 개선 후보로 보존한다.

첫 대시보드 전환에 **Failed to fetch** 배너가 나타났고 지원되는 **다시 불러오기**를 한 번 선택한 뒤 사라졌다. 시작 단계 로그와 host 상태에는 요청별 네트워크 실패 원인이 없어서 원인을 확정하지 못했다. 초기 전환 시점의 일시적 조회 문제 가능성은 추정일 뿐이며 해결 완료나 전체 시작 흐름 PASS로 확대하지 않는다. 현재 열린 창의 정상 조회·탐색만 확인했으며 종료/재시작은 검증하지 않았다.
