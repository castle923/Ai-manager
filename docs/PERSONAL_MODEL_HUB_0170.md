# Ai Manager · 개인 모델 관리 개선 · 0.17.0

상태: 소스 구현·새 합성 작업실의 설정 전환·UI·최종 전체 회귀 검증 완료. 새 패키지·실제 native 설정 전환·Google 로그인·실제 외장 장치·모델 추론·RunPod 연동은 아직 완료했다고 주장하지 않는다.

Ai Manager는 개인 PC의 내장·외장 드라이브와 Google Drive에 보관한 개인 AI 모델을 관리한다. 발견한 파일·폴더, 등록한 보관 위치, 모델 구성·해시 확인, 실행 환경 준비, 실제 출력 검증을 각각 구분한다. 실행 프로필이 없는 모델도 설명과 위치를 등록해 관리할 수 있다.

## 요청과 변경 연결

| 요청 | 이번 변경 | 검증 범위와 남은 항목 |
| --- | --- | --- |
| 개인 모델 관리 목적 | 모델 관리 첫 화면에 내장·외장·Google Drive와 보관/실행 구분 명시 | 새 합성 빈 목록 화면, 실물 외장 장치는 별도 |
| 정확한 이름 | 사용자 표시를 `Ai Manager`로 통일 | 내부 API·CSRF·패키지 식별자는 호환 유지 |
| Google Drive 사용 불가 | 현재 로컬 모드와 로그인 필요/만료를 구분하고 같은 작업실에 Drive 설정을 추가하는 지원 흐름 제공 | 합성 설정 전환·복구 검증, 실제 로그인·계정 수집은 사용자 참여 필요 |
| 폴더와 모델 선택 혼동 | 모델 관리에 범용 보관 폴더 선택·직접 경로, 준비 화면에 두 TTS 프로필 범위 표시 | 실제 파일 다이얼로그·외장 장치 확인은 별도 |
| 작업실과 비교 | 준비 순서 사이드바와 작업별 하위 메뉴, `TTS A/B 비교` 범위 표시 | 기존 섹션·원본 기록 URL 유지, 새 실행은 별도 |
| RunPod 가능성 | 현재 로컬 실행과 원격 통합 미구현을 구분하고 아래 조사 범위 기록 | 이번 Pod 생성·전송·실행·과금 없음 |
| 준비 순서 | 저장소 연결 → 모델 관리 → 실행 준비 → 작업실, 검수/기록 구분 | 준비 카드는 실행 준비 화면에 집중, 상태 polling은 유지 |

`유형별 작업실 전체`는 기존 통합 화면·기록 링크 호환을 위한 항목이며, 작업별 하위 메뉴는 같은 지원 프로필을 필터링한다. 음성 합성(TTS)은 문장을 음성으로 만들고, 음성 인식(STT)은 음성을 텍스트로 변환한다. TAPIR는 짧은 영상의 지정 점을 추적하며 영상 생성 기능이 아니다.

`4. 작업실`을 클릭하거나 키보드로 선택하면 하위 목록이 접히고 다시 펼쳐진다. 기본은 펼침이며 목록을 접어도 선택한 작업 화면·입력·실행은 바뀌지 않는다. 이 펼침 상태는 현재 화면 세션에서 유지한다.

## 로컬 작업실과 Google Drive 연결

새 로컬 작업실은 처음부터 계정과 자격 증명이 없는 별도 공간이다. 이 상태만으로 이전 작업실의 OAuth가 풀렸거나 토큰이 삭제·만료됐다고 판단하지 않는다. 기존 다른 작업실의 인증을 자동 검색·복사하지 않는다.

현재 로컬 작업실에서 연결하려면 저장소 연결 화면에서 사용자가 이번 프로젝트에 지정한 OAuth client JSON과 두 계정·허용 폴더 목록 JSON 원본을 선택하거나 전체 절대경로를 입력한다. 원본을 선택하기 전에 경로를 자동 검색하거나 비밀 내용을 UI에 표시하지 않는다. 원본 검증 뒤 현재 설정을 새 파일로 백업하고, 모델 DB는 유지하며 연결 설정을 원자적으로 적용한다.

대기·실행 중인 모델 작업, 자동 검수, 런타임·모델 준비 중에는 전환을 거절한다. 서버의 변경 요청과 전환은 같은 admission gate를 사용한다. 성공 시 설정·인증 객체를 포함한 서버 전체를 새 세대로 재구성하고 CSRF와 허용 origin을 바꾼다. 전환 전에 대기하던 native 변경 호출은 진입 세대와 현재 세대가 다르면 거절한다. 검증한 OAuth 설정 구조가 최초 원본 바이트의 구조와 같은지도 대조한다. 실패 시 현재 설치한 설정이 그대로인지 확인한 뒤 로컬 설정을 복구한다. 복구 자체가 실패하면 변경 기능을 차단하고 재시작 필요 상태를 표시한다. 손상된 설정이나 기존 Drive 설정을 로컬 모드로 조용히 바꾸지 않는다.

이 설정 절차는 실제 Google 로그인이 아니다. 계정 A/B의 `Google 로그인`과 동의는 사용자가 직접 진행하며, 읽기 전용 권한·기대 계정·PKCE·state·토큰 보호 검증을 유지한다. 저장된 자격 증명 여부와 실제 갱신·수집 성공은 별도 상태다.

## 보관 위치와 실행 프로필

현재 고정 실행 프로필은 Qwen3-TTS CustomVoice 0.6B/1.7B, Whisper large-v3-turbo, Qwen Image 2.1, Llama 3.1 8B Instruct, BootsTAPIR v2의 여섯 개다. 이는 소유 모델 목록이나 여섯 모델 모두의 실행 성공 목록이 아니다. 새 모델을 자동 실행하는 범용 로더도 아니다.

내장·외장 드라이브의 폴더는 같은 로컬 보관 참조로 다루며 존재·경로 안전성을 확인한다. reparse 경로는 거절한다. 장치가 분리돼 경로를 읽지 못하는 상태는 모델 삭제를 뜻하지 않는다. 폴더 선택을 취소하면 입력한 경로를 유지하고 등록 저장 전에는 모델 DB를 바꾸지 않는다.

두 TTS 프로필의 native 준비는 지정 구성요소를 새 준비 폴더로 복사하고 전량 해시를 확인한다. 다른 네 유형의 작업은 등록한 로컬 원본의 manifest·해시를 검증한 뒤 해당 원본 경로를 작업자에게 전달한다. 모든 로컬·외장 모델이 내부 복사나 인터넷 재다운로드를 필요로 한다고 일반화하지 않는다.

Drive 후보 참조는 제한된 읽기 전용 메타데이터 관찰이다. 원격 저장소의 모델을 실행하려면 실행할 PC나 원격 런타임에 완전하고 검증된 구성요소의 실제 파일이 지원되는 경로로 제공되어야 한다. 현재 TTS A/B는 같은 새 문장과 공통 조건으로 두 지정 TTS 프로필의 WAV를 비교하는 기능이다. 서로 다른 작업 종류의 비교에는 별도 입력·평가 규약이 필요하다.

## RunPod 조사와 미구현 범위

현재 앱 실행 대상은 로컬 PC다. RunPod Linux 작업자를 통합하려면 원격 dispatcher·작업자 프로토콜, Linux 의존성 준비, 보호된 모델·입력 전송, 취소·소유권·예산 제한, 결과 해시 재조회가 별도로 필요하다. 독립 원격 실험의 성공을 이 앱 연동 완료로 표시하지 않는다. Windows 드라이브 문자는 원격 Pod에서 같은 파일 경로로 사용할 수 없다.

RunPod의 계산 자원과 저장 공간은 별도 과금이며 선택할 구성의 가격·가용성을 실제 생성 전에 확인해야 한다. 중지는 계산 자원을 해제하더라도 저장 공간 과금이 남을 수 있고, 종료는 Pod 로컬 자료를 제거하지만 별도 저장 공간은 유지될 수 있다. 이번에는 자원을 생성하거나 삭제하지 않았다. [가격](https://docs.runpod.io/pods/pricing), [저장소 유형](https://docs.runpod.io/pods/storage/types), [Pod 수명주기](https://docs.runpod.io/pods/manage-pods)를 참조한다.

RunPod native Cloud Sync의 Google Cloud Storage는 Google Drive와 다르며 Google Drive 동기화를 지원하지 않는다. Drive 모델에는 별도로 승인된 전송 경로가 필요하다. [파일 전송](https://docs.runpod.io/pods/storage/transfer-files), [Cloud Sync](https://docs.runpod.io/pods/storage/cloud-sync)를 참조한다.

## 검증 상태

새 합성 작업실에서 설정 백업·원자적 교체·실패 복구, 대기 작업·변경 요청 경합, 이전 CSRF·origin 차단, 기존 DB와 설정 보존, 공식 OAuth endpoint 거절, 폴더 선택·취소의 비변경을 검증한다. 실제 모델이나 자격 증명을 합성 fixture로 대체해 실행 성공이라고 판정하지 않는다.

최종 동결 소스에서 전체 438개 테스트를 실행해 431개 통과, 7개 건너뜀으로 오류 없이 종료했다(240.937초). 건너뛴 항목은 별도 추적 CPU/영상 decode 의존성이 필요한 6개와 현재 OS에서 허용되지 않는 비관리자 symlink 1개다. 신규 설정 전환 반례 16개는 독립 검토자가 별도로 실행해 모두 통과했다. 앞선 전체 실행에서는 기존 `__new__` fixture에 새 전환 상태 필드가 없어 7개 subcase 오류가 났으며, fixture를 명시적으로 보완한 뒤 최종 전체 실행으로 다시 확인했다. 제품 guard를 완화하지 않았다.

TypeScript/Vite 빌드와 합성 UI의 폴더 선택·취소 입력 보존, 모의 Drive 설정 실패 안내, STT 필터, TTS 비교 한계, inherited key를 포함한 잘못된 workshop URL, 1266/768px 표본을 확인했다. 작업실 목록 접기·펼치기는 click·Enter·Space로 검사했고 선택 URL과 전송하지 않은 입력이 유지됐다. 새 문서·소스·UI·설정 전환에 독립 검토를 수행했다. 이전 테스트 결과를 이번 성공 근거로 대체하지 않는다.

0.17.0 제품 소스는 `3fab95deb040fca42c29f9ee85e784d57d858b9e`에 고정했고 215개 tracked 원본 바이트를 해당 Git blob과 대조했다. 새 Windows portable 패키지의 manifest 8,317개 파일 해시, 79개 제품 소스와 고정 커밋의 바이트 일치, ZIP 8,318개 항목의 바이트·CRC, 묶인 안내 문서를 전량 확인했다. 독립 검토자도 같은 범위를 다시 확인했다. ZIP은 113,211,587 bytes, SHA-256 `f233198a37458ef638aa0b3f712b2319edea9c775707caad5133b3040ea4aab4`다. 정식 무창 package self-check는 frozen·version·source 일치 상태로 통과했다.

이 문서의 패키지 결과 갱신은 제품 소스 커밋 뒤의 문서 변경이다. 패키지 안의 안내 문서는 빌드 시점의 스냅샷이며 패키지 해시나 제품 소스를 바꾸지 않았다. 실제 native 창의 새 버전 사용 흐름, 사용자가 선택한 실제 OAuth 원본으로의 전환, Google 로그인·토큰 갱신·Drive 목록 수집은 아직 미검증이다. 합성 전환·UI·패키지 검사만으로 실제 Google 로그인 복구가 완료됐다고 판정하지 않는다.
