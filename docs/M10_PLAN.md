# M10 다종 모델 실행 계획

> C6 후속 결과: 동일 새 조건의 TTS A/B 양쪽 생성·재생과 새 8개 기록의 정상 재시작 후 유지까지 확인했다. 상세 선택은 재선택 검증이며 자동 복원 판정이 아니다. 기존 22개 이력 전체 UI ID·모든 필터 검증은 하지 않았다. 최종 전체 완료나 이미지 로컬 성공으로 확대하지 않는다.

> 현재 candidate6 실제 사용 갱신: 이번 새 TTS 생성·running 취소·소유 자식 정리, 사용자 수동 native 저장/취소와 저장본 SHA 일치, 새 Whisper 전사 및 16프레임 합성 TAPIR 추적을 확인했다. Whisper는 원문 차이가 있어 정확도 PASS가 아니며, TAPIR는 실물 영상 검증이 아니다. LLM은 RAM/GPU/disk 공통 자원 gate에서 실패해 출력이 없었다. 새 TTS A/B 양쪽 cold 생성·native 재생 완료와 정상 종료·재시작 후 새 8개 기록 유지까지 확인했다. 기존 DB 행 fingerprint·환경 보존과 대표 STT JSON의 사용자 수동 native 저장·해시 일치도 확인했다. 추가 TAPIR PNG·A/B 저장 변형은 미검증으로 남긴다. 아래 남은 검증/초기 상태와 최신 항목별 결과를 [M10 보고서](M10_REPORT.md)에서 구분한다.


### candidate4·5의 시작 실패와 candidate6 수정

candidate4는 새 대상 설치 8,291개 파일 무결성을 통과했으나 앱 창 시작에 실패했다. 진단만 보강한 candidate5에서도 시작 실패를 보존했다. candidate5의 opt-in trace는 `home → SettingsStore → protect_directory → icacls`의 30초 timeout 호출 위치를 확인했다. WebView 초기화 전 단계이며, 채워진 디렉터리에 상속 ACL을 다시 적용하면서 자식으로 전파된 것이 정확한 지연 원인인지는 별도로 측정하지 않았으므로 가설로 남긴다.

candidate6은 Win32 API로 기존 root 디렉터리의 실제 owner·protected DACL·현재 사용자/SYSTEM의 정확한 두 full-control 규칙을 검사하고 일치할 때 재적용을 생략한다. 불명확한 ACL의 populated 디렉터리는 변경하지 않고 실패하며, 새 empty 디렉터리에만 기존 보호 절차를 적용하고 다시 검증한다. root의 계약 확인은 모든 자식 ACL을 전수 인증하는 것이 아니다. 전역 보안 설정을 변경하거나 보호 검사를 끄지 않는다.

명시적 opt-in 시작 진단은 단계·제한된 예외 종류·허용 module/line만 기록한다. 예외 원문·locals·실제 경로·계정·비밀값은 수집하지 않으며 16KiB·32 events로 제한한다. 진단 쓰기 실패가 원래 오류를 바꾸거나 시작 흐름을 가로막지 않도록 한다. 시작 진단과 worker의 별도 이미지 진단을 구분한다.

candidate6 소스 동결·native build·바이트 정합은 확인했고 전체 자동 회귀 280개 중 274개 통과·6개 skip, 관련 독립 CPU 13개 통과를 확인했다. candidate6는 새 설치본 8,292개 파일 검증과 실행 파일 SHA 일치, 같은 작업 영역의 실제 앱 창 진입을 확인했다. 현재 후보의 명시한 새 TTS·Whisper·합성 TAPIR 실행, TTS 취소·저장, 새 A/B·재생, 기록·정상 재시작 및 보존 검증을 확인했다. LLM은 자원 gate 실패·이미지 로컬은 미준비 상태이며 전체 모델 PASS는 아니다. 기존 22개 기록 조회는 보존된 과거 이력이며 새 실행 성공으로 계산하지 않는다. candidate4 설치 성공이나 이전 버전 모델 출력을 candidate6 실제 실행 성공으로 사용하지 않는다.


## 0.10.0 candidate6 통합 수정의 이번 게이트

현재 public 프로그램 Release는 v0.7.0이며 로컬 0.10.0 candidate6와 구분한다. 이번 수정은 이미지 런타임 패키지 계약 일치, 검증된 기존 라이브러리 환경의 원래 위치 재참조, 모델 선택·실행·취소·저장·기록·재시작 정합을 대상으로 한다. 원본 candidate3 Python 기반·기존 네 런타임·인증·DB·출력을 보존하며 TTS 의존성 변경이나 네 환경 재설치를 하지 않는다.

동결 snapshot의 Python 280개(274 통과·6 skip), TypeScript/Vite/native build·manifest 정합을 확인했다. 새 설치본 실제 앱 창 진입과 명시한 새 실행·취소·저장·재시작 및 새 TTS 회귀를 확인했으며 이 계획이나 source 게시만으로 완료 처리하지 않는다. 로컬 이미지 생성과 앱 원격 GPU 통합은 완료 범위가 아니다. 기존 [RunPod 보고](M10_RUNPOD_REPORT.md)는 별도 실행 이력으로 보존한다.

선택 source/test/docs 게시로 재현 경로를 제공하고, 생성 static은 새 npm build로 만든다. [M10 설치 안내](M10_INSTALL.md)가 native 빌더의 필수 문서다. 미검토 subtree·개인 자료·생성 빌드·모델·런타임·raw 로그 일괄 게시는 하지 않는다. 비활성 HQ 내부 worker는 후보 소스 재현에 포함할 수 있으나 앱 지원 기능으로 표시하지 않는다. 새 태그·Release·asset 공개는 이번 source 게시와 구분한다.

## 승인 범위와 보존

사용자 지정 Drive 모델 자산을 기준으로 진행한다. 이번 Llama 구성에서 확인한 누락 7개 파일의 공식 고정 revision 추가 다운로드와 gated 접근은 승인된 보완 범위다. 인증 성공은 다운로드나 모델 실행 성공이 아니다. 다른 외부 모델·원격 GPU·Drive 쓰기·공개 서비스·OS 또는 브라우저 보안 변경은 자동 확대하지 않는다. 같은 승인 범위의 수정·설치·검증·문서·비식별 소스 반영에 반복 승인을 요구하지 않는다.

같은 Ai-manager 소스·문서의 후속 갱신과 지정 모델 가중치·필수 구성요소는 사용할 수 있다. 과거 WAV·출력·로그·스크린샷·측정값·배포물을 이번 새 실행 성공의 근거로 쓰지 않는다. 실행마다 새 ID·출력 경로·입력 출처·모델 해시·의존성 버전·결과 해시를 비공개에 연결한다. 기존 home·인증·DB·릴리스와 실패한 환경을 보존한다. Windows 경로 길이 오류에는 새 짧은 전용 경로를 사용하며 보안 설정을 바꾸지 않는다.

공개 문서에는 계정 A/B와 경로 별칭을 쓴다. 개인 계정·Drive ID·실제 경로·자격 증명·입력 본문·원시 로그·모델·개인 결과물은 게시하지 않는다. 공개 반영과 프로그램 Release를 구분하고 최종 게이트 전 새 태그·Release를 만들지 않는다.

같은 실행 안의 새 TTS → 16 kHz 변환 → STT 전달은 출처 기록과 해시를 연결한 경우 허용한다. 이전 단계에서 만든 과거 WAV를 새 STT 입력으로 자동 가져오지 않는다. 합성 fixture는 오류·상태 경계 검증용이며 실제 모델 결과와 구분한다.

Qwen 이미지 모델의 연구용 라이선스 범위를 확인하고 연구·평가·개인 실험 범위로 제한한다. 상업 사용 가능으로 표현하지 않는다. 일반 offload API의 존재는 현재 PC의 메모리에서 해당 모델이 실제 생성된다는 증거가 아니다. 지정 자원 조건을 충족하지 못하면 이유와 실제 관측을 기록하고 차단/미확인으로 남긴다. 모델 변경·축소본으로 대체해 원래 대상의 성공으로 기록하지 않는다.

## 공통 구현과 오류 경계

등록 모델의 adapter·manifest·artifact generation/fingerprint와 새 실행을 연결한다. 입력 유형과 출력 파일 유형을 고정하고 다른 유형의 결과를 열거나 저장하는 요청을 거부한다. registry·통합 기록·작업 상세·자원 감시가 같은 run 상태를 표시해야 한다. GPU 작업 슬롯은 유형 간에 공유하며 중복 실행·잘못된 대기/취소를 검증한다.

빈 입력·손상 입력·잘못된 경로/형식·누락/변경된 모델·환경 실패·자원 부족·worker 예외·timeout·대기/실행 취소·앱 종료를 성공과 구분한다. 취소 후 해당 작업자와 자원이 정리되는지 확인한다. 실패/취소 중간 파일을 정상 결과로 승격하지 않는다. 정상 native 저장에서 취소·기존 대상·경로 경계를 확인하고 저장본 크기·SHA-256을 원본과 대조한다. 보안/정책 설정 변경이나 다른 저장 도구로의 우회는 하지 않는다.

## 최종 게이트

1. 네 지정 모델의 출처·고정 버전·필수 구성·해시와 공식 의존성/라이선스를 기록한다. 발견·접근 허가·부분 다운로드·완전 다운로드·해시·환경·실행을 구분한다.
2. 현재 소스의 공통 상태·입력/출력 경계·registry·history·취소·자원 슬롯을 자동·독립 반례로 검증한다.
3. 각 어댑터의 새 실제 실행을 새 run과 연결한다. 자원 gate나 다운로드로 막힌 어댑터는 미완료로 남긴다.
4. 수정이 끝난 소스를 동결하고 새 Windows 패키지·전용 설치본을 만든다. 소스·패키지·설치본 해시를 연결하고 그 설치본에서 실제 입력·결과 표시·오류·취소·정상 저장을 확인한다. 초기 소스 실행을 최종 패키지 E2E로 대체하지 않는다.
5. 현재 패키지의 재시작·기록/결과 보존과 기존 두 TTS 모델의 **새 A/B 실행**을 확인한다. 과거 M9 성공을 회귀 성공으로 쓰지 않는다. 한국어 가독성·키보드/포커스·대표 화면 폭·오류/빈 상태도 확인 범위를 명시한다.
6. 독립 검토에서 반례를 해소하고 확인 범위·제한·미완료 항목을 정리한다. 허용 파일 목록과 개인정보 검토 후 소스/문서를 반영한다. 게시나 문서 작성 자체를 실행 검증 완료로 표시하지 않는다.

어댑터별 최종 실행·오류/취소·저장과 공통 패키지 게이트가 모두 충족되기 전 M10 전체 PASS를 선언하지 않는다. 특정 유형의 제한을 사용자와 정리하더라도 나머지 완료 결과와 구분해 보고한다.
