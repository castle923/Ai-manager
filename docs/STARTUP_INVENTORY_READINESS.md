# 새 작업실 첫 요청의 인벤토리 준비 순서 · Windows 0.16.6

상태: 소스 수정·새 합성 작업실의 HTTP 회귀·새 portable 패키지 무결성 검증 완료. 실제 네이티브 첫 전환은 아직 검증하지 않았다. 새 GitHub Release나 태그를 뜻하지 않는다.

새 로컬 작업실에서는 상태 요청이 처음 인벤토리 DB를 만들었다. 라이브러리 요청은 DB 파일이 이미 있으면 읽기 전용으로 테이블을 조회한다. 파일 생성과 테이블 생성 사이에 두 요청이 겹치면 `no such table: scans`가 발생하고 HTTP 응답 없이 연결이 닫힐 수 있었다.

이번에는 파일 생성 직후 상태 요청을 잠시 대기시키는 새 합성 테스트로 이 순서를 재현했다. 그 사이 라이브러리 요청은 `RemoteDisconnected`로 끝났고, 스키마 생성 후에는 같은 요청이 200과 빈 목록을 반환했다. 이 결과는 앞서 관찰한 네이티브 `Failed to fetch`와 부합하는 서버 경합을 입증한다. 당시 네이티브 요청의 원인이 이것이었다고 확정하는 증거는 아니다.

앱은 이제 HTTP 서버를 만들기 전에 인벤토리 초기화를 완료한다. 준비가 실패하면 서버를 노출하지 않는다. 요청 재시도나 오류 무시를 추가하지 않았으며 손상된 DB를 빈 목록으로 바꾸지 않는다. 기존 인벤토리 초기화의 중단 작업 판정은 그대로 적용된다.

## 이번 새 검증

- 스키마 생성 전 대기 중에는 서버 생성이 호출되지 않고, 대기 해제 뒤 생성된다.
- 새 로컬 작업실에서 상태·라이브러리·세션·설정의 동시 GET 20개가 모두 200과 JSON 응답을 반환했다.
- 새로 만든 완료 상태 인벤토리와 설정은 앱 구성 전후 파일 전체 SHA-256이 같았다.
- 새로 만든 손상 DB는 서버 생성 전 실패하고 원본 바이트를 보존했다.
- 같은 신규 테스트를 수정 전 서버에 적용하면 준비 순서와 손상 DB 관련 두 테스트가 실패했다. 다른 두 테스트는 통과했다.
- 최종 0.16.6 소스에서 startup·local mode·native guard·desktop·dashboard·server·package integrity·view contract 관련 54개 테스트가 통과했다. 독립 검토자가 신규 4개를 별도로 실행해 통과했다.

기존 인증·개인 DB·모델·보안 설정은 이 검증의 입력이 아니다. 모델 준비·추론·다운로드·OAuth와 실제 네이티브 첫 전환은 이번 HTTP 검증에서 수행하지 않았다. 공용 오류 배너가 상태 요청 성공만으로 갱신되지 않는 동작은 별도 후속 조사 대상이며 이번 변경에 포함하지 않는다. 기존 가독성 검증의 폭·zoom·재시작·스크린리더 제한도 그대로 남는다.

## 새 portable 패키지와 소스 연결

제품 소스 커밋은 `6cef96c4676bba5d0c37fb2a1a99cc72d0695368`이다. 패키지는 이 커밋으로 빌드했으며, 이 문서의 후속 검증 결과 갱신은 패키지 코드 변경이 아니다. 패키지 안 문서는 빌드 전 검증 상태의 스냅샷으로 보존한다.

첫 빌드는 Windows checkout의 줄 끝 변환 때문에 일부 소스의 실제 바이트가 커밋 원본과 다른 점을 발견하여 중단했다. 중단 빌드는 검증 결과로 사용하지 않는다. 새 격리 checkout의 212개 추적 파일을 커밋 원본 바이트와 대조한 뒤 새 출력 경로에서 다시 빌드했다. 고정된 공개 CPython 배포 압축 파일은 전체 해시를 재확인했다. 복원한 최종 소스에서도 54개 테스트가 다시 통과했다.

최종 패키지의 8,315개 manifest 파일 전량 SHA-256, 78개 포함 소스와 제품 커밋의 원본 바이트, ZIP 8,316개 항목의 CRC·실제 바이트·중복·위험 경로와 동봉 문서를 대조해 통과했다. 독립 검토자가 패키지 전체를 별도로 대조했다. 정식 무창 자체 검사는 0.16.6 / 해당 소스 커밋 / frozen 상태에서 `verified`를 반환했다. 이 검사는 실제 창 표시·첫 전환·모델 실행 검증과 구분한다.

ZIP은 113,194,182 bytes이며 SHA-256은 `3eb5e1ef117ef16b5afdd7afa786ebafc3cd5b0c3941b7f64e7de39e0fff213d`다. 실행 파일 SHA-256은 `659560622832e48884edbbd2ff928c6eed9c0abc2a42b5fae7b66540b28aa334`다. 기존 작업실·인증·DB·모델 원본과 기존 패키지는 보존했다.
