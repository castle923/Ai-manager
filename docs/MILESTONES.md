# 마일스톤과 검증 기준

M0–M7은 승인된 TTS 중심 1차 범위·독립 앱의 완료 이력이다. **전체 원구상은 미완료**이며 이번 사용자 승인으로 M8 모델 등록·통합 상태부터 확장한다. M8은 후보 3의 편집 수리·보관/해제·새 실행/재생/저장을 확인했고 성공 후 편집 유지·정상 재시작까지 검증했다. 미검증 경로/화면 범위와 게시 상태는 M8 보고서를 따르며 M9/M10은 후속 계획이다. [모델 관리 로드맵·상태/KPI·완료 게이트](M8_PLAN.md)

## 진행 규칙

M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 순서로 진행한다. 각 단계는 범위 승인, 구현, 별도 검토, 완료 보고를 거친다. 실패 시 근거와 수정 범위를 기록하고 같은 단계에서 해결한다. 다음 단계나 다른 모델 계열로 자동 확장하지 않는다. 모든 실무는 서브에이전트가 수행하며 이후 생성 서브에이전트는 GPT-6.1 sol / medium을 사용한다. [품질 게이트](QUALITY_GATES.md)를 단계 완료 기준에 함께 적용한다. M2/M4/M6는 목업이나 단순 스모크 성공만으로 완료하지 않는다.

## 단계별 사용자 확인 장면

M7 후속 사용자 요청: 0.7.1 후보의 새 1.7B 준비와 동일 새 한국어 A/B 실행·재생·두 native 저장본 해시 검증을 완료했다. 기존 v0.7.0 검증 범위·공개 배포와 구분하며 [후속 보고서](M7_AB_REPORT.md)에 소스 변경·실측·제한을 기록한다.

### M0 — 만들 범위가 명확하다

사용자가 “어느 계정의 어느 폴더를 읽고, 어떤 모델을 어디서 실행할지”를 확인한다. PC 자원과 로컬 파일 상태는 새로 조회한다. 이전 대화의 보유 목록은 현재 인벤토리로 가져오지 않는다.

### M1 — 내 모델 목록이 들어온다

계정별 연결과 허용 폴더를 설정하고 새로고침한다. 스캔 수와 오류를 볼 수 있다. 읽기 전용 계정 권한을 유지하고 Drive 변경 호출이 없는지 검토한다.

### M2 — 찾고 판단할 수 있다

“음성 합성” 필터로 후보를 찾고 상세 화면에서 구성 충족·무결성·런타임·실행 이력을 각각 확인한다. 여기까지가 **조회용 MVP**다. 실행 버튼은 아직 사용 가능하다고 표시하지 않는다.

### M3 — 실행할 자산이 준비된다

선택한 모델의 준비 화면에 필요한 파일과 예상 디스크 사용량, 다운로드 진행률, 검증 결과가 표시된다. 실패하면 부족한 항목이 남으며 원본 파일은 보존된다.

### M4 — 첫 목소리가 실제로 나온다

새 한국어 문장을 입력하고 실행한다. 완료 후 오디오를 듣고 저장한다. 실행 ID, 입력·모델 해시, 출력 검증, 실제 시간과 오류 기록이 연결된다. 여기까지가 **실행용 MVP**다.

### M5 — 직접 비교할 수 있다

비교할 두 모델과 새 입력을 선택한다. 두 실행이 끝나면 A/B 음성을 듣고 발음·속도·메모리를 비교한다. 한쪽 실패 시 부분 완료이며 승자를 표시하지 않는다. 과거 WAV나 측정값으로 새 실행을 대체하지 않는다.

### M6 — 다시 켜도 믿을 수 있다

앱 재시작, 작업 중단, 인증 만료를 재현해 상태가 일관적인지 확인한다. 새 사용자 실행 안내와 알려진 제한을 제공한다. 개인용 로컬 출시이며 공개 서비스 배포를 뜻하지 않는다.

## 일정과 우선순위

확정 날짜 대신 완료 기준으로 관리한다. M0에서 인증 경로, 첫 모델 의존성, PC 메모리·GPU 여유를 검증한 뒤 단계별 작업량을 산정한다.

우선순위는 **정확한 상태 표시 → 조회 기능 → 준비 검증 → 실제 실행 → 비교 → 복구**다. 범용 모델 실행이나 화면 장식 때문에 이 순서를 뒤집지 않는다.
