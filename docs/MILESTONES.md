# 마일스톤과 검증 기준

작성일: 2026-10-16 · 모든 구현 단계 미착수

## 진행 규칙

M0 → M1 → M2 → M3 → M4 → M5 → M6 순서로 진행한다. 각 단계는 범위 승인, 구현, 별도 검토, 완료 보고를 거친다. 실패 시 근거와 수정 범위를 기록하고 같은 단계에서 해결한다. 다음 단계나 다른 모델 계열로 자동 확장하지 않는다.

| 단계 | 산출물 | 완료 기준 | 핵심 반례·검증 | 의존성 |
|---|---|---|---|---|
| **M0 범위·환경 확정** | 요구사항, 허용 자산 목록, 인증·하드웨어 기록, 기술 결정 | 두 계정의 읽기 범위, 첫 모델, 저장 위치, 실행 환경, 재사용 금지 기준 확정 | 토큰 없이 공개 문서를 재현 가능한지, 이전 결과물 유입 여부, 인증 경로 가능 여부 | 사용자 범위 승인 |
| **M1 인벤토리 수집** | 읽기 전용 연결·스캔·로컬 목록 | 계정 A/B의 지정 범위를 페이지 끝까지 스캔하고 부분 실패를 표시 | 두 페이지 이상, 권한 거부, 인증 만료, 중복 파일명, 공유 파일, 바로가기 순환 | M0 |
| **M2 조회 대시보드** | 개요·목록·상세·필터·갱신 화면 | 실제 스캔 목록을 표시하며 파일 발견과 실행 성공을 구분 | 빈 폴더, 미수집 값, 부분 스캔, 긴 파일명, 분할 가중치 누락, 예시/실제 혼합 방지 | M1 |
| **M3 실행 준비** | 자산 다운로드·검증·환경 점검 | 선택한 모델만 준비하고 준비 상태·차단 이유를 명시 | 디스크 부족, 전송 중단, 해시 불일치, 기반 모델 누락, 지원하지 않는 런타임 | M2 |
| **M4 첫 실제 실행** | TTS 어댑터·큐·취소·출력 재생·실행 기록 | 새 문장으로 WAV를 만들고 검증·재생까지 성공 | 빈 입력, 메모리 부족, 시간 초과, 취소, 프로세스 비정상 종료, 손상 출력 | M3 |
| **M5 새 A/B 비교** | 비교 세션·조건·지표·사용자 평가 | 같은 계열 두 모델의 새 실행을 연결하고 측정 조건을 공개 | 지원 옵션 차이, 두 번째 모델 실패, 미수집 지표, 결과 캐시 유입, 콜드/웜 혼합 | M4 및 두 번째 모델 준비 |
| **M6 개인용 출시** | 설치·시작·복구 안내, 회귀 검증, 버전 태그 | 재시작 후 상태 일관성, 비밀정보 비노출, 대표 사용 흐름 통과 | 실행 중 앱 종료, 인증 해제, DB 복구, 로그 민감정보, 신규 환경 설치 | M5 |

## 단계별 사용자 확인 장면

### M0 — 만들 범위가 명확하다

사용자가 “어느 계정의 어느 폴더를 읽고, 어떤 모델을 어디서 실행할지”를 확인한다. PC 자원과 로컬 파일 상태는 새로 조회한다. 이전 대화의 보유 목록은 현재 인벤토리로 가져오지 않는다.

### M1 — 내 모델 목록이 들어온다

계정별 연결과 허용 폴더를 설정하고 새로고침한다. 스캔 수와 오류를 볼 수 있다. 읽기 전용 계정 권한을 유지하고 Drive 변경 호출이 없는지 검토한다.

### M2 — 찾고 판단할 수 있다

“음성 합성” 필터로 후보를 찾고 상세 화면에서 구성 충족·무결성·런타임·실행 이력을 각각 확인한다. 여기까지가 **조회용 MVP**다. 실행 버튼은 아직 사용 가능하다고 표시하지 않는다.

### M3 — 실행할 자산이 준비된다

선택한 모델의 준비 화면에 필요한 파일과 예상 디스크 사용량, 다운로드 진행률, 검증 결과가 표시된다. 실패하면 부족한 항목이 남으며 원본 파일은 보존된다.

### M4 — 첫 목소리가 실제로 나온다

새 한국어 문장을 입력하고 실행한다. 완료 후 오디오를 듣고 저장한다. 실행 ID, 입력·모델 해시, 출력 검증, 실제 시간과 오류 기록이 연결된다. 여기까지가 **실행용 MVP**다.

### M5 — 직접 비교할 수 있다

비교할 두 모델과 새 입력을 선택한다. 두 실행이 끝나면 A/B 음성을 듣고 발음·속도·메모리를 비교한다. 한쪽 실패 시 부분 완료이며 승자를 표시하지 않는다. 과거 WAV나 측정값으로 새 실행을 대체하지 않는다.

### M6 — 다시 켜도 믿을 수 있다

앱 재시작, 작업 중단, 인증 만료를 재현해 상태가 일관적인지 확인한다. 새 사용자 실행 안내와 알려진 제한을 제공한다. 개인용 로컬 출시이며 공개 서비스 배포를 뜻하지 않는다.

## 출시 판정 체크리스트

- [ ] 두 계정의 허용 범위에서 새 스캔을 완료하거나 부분 실패를 명시했다.
- [ ] 실제 메타데이터와 예시 데이터가 섞이지 않는다.
- [ ] 구성 누락·무결성 실패 모델이 실행되지 않는다.
- [ ] 첫 모델의 실제 출력과 UI 재생이 검증됐다.
- [ ] 비교 모델 두 개를 같은 새 입력으로 각각 실행했다.
- [ ] 실패·취소·중단이 성공으로 표시되지 않는다.
- [ ] 과거 산출물이나 결과 캐시를 새 실행에 쓰지 않았다.
- [ ] 개인 계정·자격 증명·파일 목록·모델·결과가 Git에 들어가지 않는다.
- [ ] 단계별 검토 기록과 미확인 사항을 남겼다.

## 일정과 우선순위

확정 날짜 대신 완료 기준으로 관리한다. M0에서 인증 경로, 첫 모델 의존성, PC 메모리·GPU 여유를 검증한 뒤 단계별 작업량을 산정한다.

우선순위는 **정확한 상태 표시 → 조회 기능 → 준비 검증 → 실제 실행 → 비교 → 복구**다. 범용 모델 실행이나 화면 장식 때문에 이 순서를 뒤집지 않는다.
